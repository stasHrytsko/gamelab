# Tight Shelf — прототип

Спека — `specs/06-tight-shelf.md`, экраны — `UI Design/prototypes/tight-shelf/`.
Веб-игра под телефон: TypeScript + Vite, без фреймворка, экран на HTML/CSS,
стиль — токены и шрифт из `UI Design/` (подключаются напрямую, не копией).

## Ссылки

| Ссылка | Что открывает |
|---|---|
| `https://<домен>/tight-shelf/` | главный экран — эту ссылку и рассылать |
| `https://<домен>/tight-shelf/#/levels` | экран уровней |
| `https://<домен>/tight-shelf/#/level/3` | сразу уровень 3, если он уже открыт у игрока; иначе экран уровней |
| `https://<домен>/tight-shelf/?unlock=all#/level/5` | любой уровень без прохождения предыдущих — для проверки, прогресс не трогает |

Маршруты в `#`, превью ссылки — `public/og.png`, иконка «На экран Домой» —
`manifest.webmanifest`; всё как у соседних игр.

## Витрина

Игра публикуется на общем сайте по адресу `https://<домен>/tight-shelf/` —
это `path` из `game.json`, там же название, жанр и питч для карточки.
Отдельного Vercel-проекта у игры нет: каждый пуш в `main` пересобирает сайт
целиком (`npm run build` в корне репо, см. `site/README.md`).

## Команды

```sh
npm install          # в корне репо, один раз на все игры (workspaces)
npm run dev          # http://<ip-компьютера>:5173 — открыть с телефона в той же Wi-Fi
npm test             # движок = солвер, уровни: решаемы, жадный не проходит 3–5 (§6)
npm run e2e          # пять уровней решением солвера, ход мимо, линия, проигрыш, очередь, «без прокрутки»
npx tsx tools/make-images.ts    # иконки и og.png из tools/brand.html
npx tsx tools/make-screens.ts   # экраны для UI Design/prototypes/tight-shelf (после npm run build)
npx tsx tools/build-artifact.ts # один HTML-файл для превью на claude.ai
```

Солвер и подбор уровней — общий `tools/tight-shelf-solver.mjs` в корне репо:

```sh
node tools/tight-shelf-solver.mjs > tools/tight-shelf-levels.json   # подобрать 5 уровней
node tools/tight-shelf-solver.mjs --report                           # метрики уровней §6
node tools/tight-shelf-solver.mjs --log log.json                     # kill-метрика §8 по логу игроков
```

После пересборки уровней скопировать `tools/tight-shelf-levels.json` в
`src/levels/levels.json` — тест сверяет копию с оригиналом.

## Устройство

- `src/engine/shelfEngine.ts` — правила §3–5: правило клетки, 24 линии,
  исчезновение линий через поставленную фигуру, `tapCell` → `{ state, move }`
  или `null`. `fits`, `legal` и `place` — порт солвера; тест сверяет их на
  3000 случайных позиций. Проигрыш `no_moves` — только когда текущей фигуре
  действительно некуда встать; наперёд игра ничего не предсказывает.
- `src/levels/levels.json` — пять уровней: поле (цвет `B/Y/C`, форма `o/s/t`,
  `.` — любая фигура) и очередь.
- `src/ui/pieces.ts` — фигура (inline SVG: силуэт — форма, заливка — цвет,
  узор — второй канал цвета) и клетка-правило.
- `src/ui/game.ts` — игровой экран: очередь «Сейчас + 3 дальше» сверху,
  поле 4×4, подсказка; перелёт фигуры, полоса по линии, двойная очистка,
  сдвиг очереди.
- Главный экран — композиция из фигур игры (`src/ui/screens.ts`), арта
  автора пока нет.
- Лог §8 пишется только на устройство: `localStorage['tight-shelf:log']` — на
  каждом ходе номер фигуры, фигура, клетка, число подходящих клеток, число
  линий. Скопировать из консоли браузера и прогнать через `--log`.
