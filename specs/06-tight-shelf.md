# 1. Граница прототипа

**Что проверяем.** Смотрит ли игрок в очередь перед ходом: оставляет ли
свободной клетку, которая скоро понадобится шару из превью, даже когда
текущий шар туда тоже подходит.

**Минимальный цикл.** Поле 4×4 с правилами клеток, очередь «текущий + 3
следующих», тап по клетке, исчезновение линий, проверка «шару некуда встать».
Вокруг цикла пять экранов и попапы (§7.1, `apps/CLAUDE.md` §2).

**Не делаем.** Таймер, отмену хода, перемещение поставленных шаров, бустеры,
очки, звёзды, подсказку лучшего хода, предупреждение «уровень уже не пройти»,
третий признак шара (размер), вставку шаров со сдвигом, гравитацию, звук,
настройки и бесконечный режим.

**Уровней пять.** Открываются по очереди.

**Откуда эта версия.** Первая версия идеи — товары и полки с таблицей
совместимости. Автор отказался от неё 2026-09-28. Текущие правила выбраны
прогоном ботов по девяти вариантам геометрии и A/B со вставкой со сдвигом.
Таблица и выводы — в `ideas/backlog/06-tight-shelf.md`, «Как выбрали
правила».

**Почему kill-критерий такой.** Вся глубина игры — в превью: бот, который
видит три шара вперёд, выигрывает уровень 5 в 80% попыток, бот без очереди —
в 20%, случайный — в 0% (§6). Если игроки не обходят ловушки, которые видно
в очереди, чаще случайного выбора, они играют в «поставь, куда подходит». Это
не лечится подбором уровней: решение просто не происходит в голове игрока.

# 2. Цель и основной цикл

Цель игрока — поставить на поле все шары очереди уровня.

Первое доступное действие — тапнуть неприглушённую пустую клетку поля.

```text
Посмотреть на текущий шар и три следующих
→ тапнуть пустую клетку, чьё правило подходит текущему шару
→ шар встаёт в клетку; линии через него с общим цветом или формой исчезают
→ очередь сдвигается на один шар
→ проверка победы и поражения по §5
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Шар | в очереди; текущий; на поле; исчез | становится текущим при сдвиге очереди; встаёт на поле тапом; исчезает в линии | цвет — один из `B` синий, `Y` жёлтый, `C` коралловый; форма — одна из `o` круг, `s` квадрат, `t` треугольник; 9 типов |
| Клетка | пустая; занята шаром | занимается постановкой; освобождается, когда её шар исчезает | правило задано уровнем и не меняется: цвет (`B`, `Y`, `C`), форма (`o`, `s`, `t`) или `.` — любой шар; в клетке не больше одного шара |
| Очередь | — | сдвигается на один шар после каждой постановки | порядок и состав заданы уровнем; видно текущий шар и не больше трёх следующих |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Шар подходит клетке**, если правило клетки `.`, или совпадает с цветом
шара, или совпадает с его формой.

**Пространство.** Поле — сетка 4×4. Клетка адресуется индексом
`i = row * 4 + col`, `row` сверху вниз, `col` слева направо, 0..3. Линия —
три подряд идущие клетки по горизонтали, вертикали или диагонали. Таких линий
24: 8 горизонтальных, 8 вертикальных, 8 диагональных. Очередь — список,
индекс 0 — первый шар уровня.

```ts
type Color = 'B' | 'Y' | 'C';
type Shape = 'o' | 's' | 't';
type Ball = `${Color}${Shape}`;          // 'Bt' — синий треугольник
type Rule = Color | Shape | '.';

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  rules: Rule[];                          // 16, из уровня
  board: (Ball | null)[];                 // 16
  queue: Ball[];                          // из уровня
  turn: number;                           // индекс текущего шара в queue
  status: 'playing' | 'won' | 'failed';
  failReason: 'no_moves' | null;
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

# 4. Ввод и правила

```ts
type Action =
  | { type: 'tap-cell'; cell: number }    // 0..15
  | { type: 'open-help' }
  | { type: 'restart' }
  | { type: 'exit-to-levels' };
```

Только тап. Перетаскивания, долгого нажатия, свайпа, отмены хода и тапа по
шарам очереди нет.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Тап по клетке | пустая, правило подходит текущему шару | шар ставится в клетку, дальше по «Исчезновение линий» и §5 | шар перелетает из «Сейчас» в клетку | да |
| Тап по клетке | пустая, правило не подходит текущему шару | ничего | клетка покачивается 160 мс, короткая вибрация | нет |
| Тап по клетке | занята шаром | ничего | клетка покачивается 160 мс, короткая вибрация | нет |
| Тап мимо поля | всегда | ничего | ничего | нет |
| Тап по шару в очереди | всегда | ничего | ничего | нет |
| «?» | попапа нет | ввод заблокирован | попап «Как играть» | нет |
| «Понятно!» | попап «Как играть» открыт | `howToPlaySeen = true` | игра с того же места | нет |
| «Заново» | всегда | уровень в начальное состояние | пустое поле, очередь с начала | — |
| «К уровням» | всегда | попытка брошена | экран уровней | — |
| Любое действие по полю | идёт анимация хода, открыт попап или `status !== 'playing'` | ничего | ничего | нет |

**Исчезновение линий.** После постановки шара в клетку `i`:

1. Проверяются только линии, проходящие через `i`.
2. Линия собрана, если все три её клетки заняты и у трёх шаров один цвет или
   одна форма.
3. Все собранные линии исчезают одновременно: освобождается объединение их
   клеток.
4. Шар, который ставят в пересечение двух собранных линий, закрывает обе
   (двойная очистка).
5. Клетки вне собранных линий не меняются, даже если стоят в том же ряду.
   Пример: в ряду `Yo Bs Bt _` ставим `Bo` в последнюю клетку. Линия `Bs Bt Bo`
   синяя и исчезает, `Yo` остаётся.
6. Каскадов нет: после исчезновения шары не двигаются, и новые линии не
   проверяются.

Линии, не проходящие через поставленный шар, не проверяются. По построению
среди них нет собранных: каждая линия проверяется в момент, когда
заполняется её последняя клетка.

# 5. Победа, поражение и переходы

```text
Дано: текущий шар — последний в очереди.
Когда: он поставлен и линии обработаны.
Тогда: попытка заканчивается победой; шары, оставшиеся на поле, не мешают.
       Уровень добавляется в passed, открывается следующий, попап победы —
       на уровнях 1–4 обычный, на уровне 5 финальный.
```

```text
Дано: в очереди остались шары.
Когда: после сдвига очереди у нового текущего шара нет ни одной пустой
       клетки с подходящим правилом.
Тогда: попытка заканчивается поражением с причиной no_moves; текущий шар
       покачивается, через 900 мс попап «Шару некуда встать».
```

```text
Дано: после хода уровень уже нельзя пройти, но текущему шару есть куда встать.
Когда: завершена обработка хода.
Тогда: игра продолжается молча. Никаких предупреждений и подсветок.
```

Игра не предсказывает проигрыш (`apps/CLAUDE.md` §3): поражение наступает
только тогда, когда текущему шару действительно некуда встать.

Порядок проверок после тапа по подходящей клетке: поставить шар → найти
собранные линии через него → убрать их шары → сдвинуть очередь → проверить
победу → проверить `no_moves` → вернуть ввод.

Код причины поражения один и стабильный: `no_moves`.

**Случайности нет.** Правила клеток и вся очередь заданы уровнем. Попытки
одного уровня всегда начинаются с одного и того же состояния.

**Переходы между экранами** — как в `apps/CLAUDE.md` §2: главный → уровни →
игровой экран; попап победы: «Следующий уровень», «Переиграть», «К уровням»;
попап поражения: «Переиграть», «К уровням»; финальный попап после уровня 5:
«Переиграть», «К уровням».

# 6. Контент и кривая сложности

Пример данных одного уровня (`tools/tight-shelf-levels.json`):

```json
{
  "id": 3,
  "seed": 18,
  "rules": ["BBB.", "Bs.o", ".tsB", "C.YB"],
  "queue": ["Yo", "Ct", "Ct", "Bt", "Ct", "Co", "Yt", "Yt", "Cs", "Ct", "Yo", "Bo",
            "Cs", "Yt", "Bs", "Yt", "Ct", "Yt", "Bs", "Ct", "Bt", "Co", "Ct", "Yo"]
}
```

`rules` — четыре строки поля сверху вниз, по символу на клетку.

**Правило генерации** (`generate` и `CURVE` в `tools/tight-shelf-solver.mjs`).
Уровень N задаётся числом джокеров и длиной очереди. Джокеры ставятся в
случайные клетки, остальные клетки получают одно из шести правил равновероятно,
очередь — равновероятные шары из 9 типов. Перебираются seed от 1. Берётся
первый уровень, который проходит проверки из таблицы ниже.

| Уровень | Джокеров | Очередь | Отбор |
|---:|---:|---:|---|
| 1 | 8 из 16 (50%) | 18 | решаем; жадный проходит; случайный ≥ 60%; ловушек ≤ 1 |
| 2 | 6 (38%) | 22 | решаем; все 6 правил на поле; жадный проходит; случайный 30–60%; ловушек ≥ 1 |
| 3 | 4 (25%) | 24 | решаем; все 6 правил; жадный не проходит; случайный ≤ 30%; превью 3 ≥ 80%; ловушек ≥ 3 |
| 4 | 3 (19%) | 30 | то же; случайный ≤ 15%; без превью ≤ 50%; превью 3 ≥ 70%; ловушек ≥ 5 |
| 5 | 1 (6%) | 36 | то же; случайный ≤ 5%; без превью ≤ 30%; превью 3 ≥ 60%; ловушек ≥ 7 |

Термины отбора:

- **решаем** — точный солвер находит расстановку всей очереди;
- **жадный** — детерминированный бот: клетка, где исчезает больше всего
  шаров, при равенстве первая по индексу;
- **случайный** — любая подходящая клетка;
- **без превью** — лучшая оценка поля после хода без знания очереди;
- **превью 3** — перебор текущего и трёх следующих шаров;
- **ловушка** — ход вдоль найденного солвером решения, где хотя бы одна
  подходящая клетка делает уровень нерешаемым, а другая нет.

Доли побед случайного бота — по 2000 попыток, без превью — по 400,
превью 1 — по 200, превью 3 — по 100.

**Уровни** (seed и полные очереди — `tools/tight-shelf-levels.json`, метрики
— `node tools/tight-shelf-solver.mjs --report`, 2026-09-28):

| Уровень | Поле | Случайный | Без превью | Превью 1 | Превью 3 | Ловушек | Первая ловушка |
|---:|---|---:|---:|---:|---:|---:|---:|
| 1 | `.t..` `ss..` `.Yt.` `tBo.` | 75% | 98% | 100% | 100% | 1 | шар 11 |
| 2 | `C.sB` `tY..` `Cst.` `.Bo.` | 46% | 82% | 100% | 100% | 3 | шар 9 |
| 3 | `BBB.` `Bs.o` `.tsB` `C.YB` | 23% | 72% | 85% | 98% | 3 | шар 6 |
| 4 | `B.oo` `.ooY` `osYC` `ot.s` | 5% | 32% | 46% | 90% | 5 | шар 5 |
| 5 | `tCBs` `otBB` `YsBY` `toB.` | 0% | 20% | 39% | 80% | 13 | шар 9 |

| Уровень | Новый навык | Главное давление | Сложный момент |
|---:|---|---|---|
| 1 | поставить шар в подходящую клетку; увидеть, как исчезает линия | почти нет: половина поля — джокеры | 18 шаров на 16 клеток — без хотя бы одной линии не пройти |
| 2 | правила формы и цвета вперемешку; линия по форме, а не только по цвету | 6 джокеров, клетки начинают кончаться | первые ловушки, но жадная игра их ещё проходит |
| 3 | сберечь клетку под шар из превью | жадный ход «собери линию сейчас» проигрывает | первая ловушка уже на 6-м шаре |
| 4 | держать две клетки под разные шары очереди | 3 джокера, 30 шаров | без превью бот выигрывает только в 32% |
| 5 | всё вместе на почти полностью «правильном» поле | 1 джокер, 36 шаров, 13 ловушек | превью решает: 80% против 20% без него |

Разница между соседними уровнями:

- `1→2` — появляются все шесть правил и линии по форме; джокеров меньше.
- `2→3` — жадная игра перестаёт работать: впервые нужно не собирать линию
  сейчас, а сберечь клетку.
- `3→4` — ловушек больше и раньше, одной сбережённой клетки уже мало.
- `4→5` — почти нет джокеров, 13 ловушек: прямая проверка гипотезы.

**Проверки уровней** (`tests/levels.test.ts` в прототипе):

- каждый уровень решаем точным солвером, а его решение проходится движком игры;
- все шары очереди подходят хотя бы одной клетке поля;
- уровни 1–2 жадный бот проходит;
- уровни 3–5 жадный бот не проходит — kill-критерий дизайна в форме теста;
- уровень N+1 не легче уровня N для случайного бота.

# 7. Обратная связь и обучение

- **Правило клетки.** Цвет — клетка подкрашена этим цветом, с рамкой и
  узором цвета (§7.1). Форма — на серой клетке выдавленный контур
  круга, квадрата или треугольника. Джокер — серая клетка с точкой, как
  «Пустая» клетка кита.
- **Шар.** Тело — цвет с узором цвета, на теле белый знак формы.
- **Доступное действие.** Пустые клетки, куда текущий шар не встаёт,
  приглушены (непрозрачность 0,38). Подходящие клетки — обычные.
- **Запрещённое действие.** Клетка покачивается 160 мс, короткая вибрация.
  Ход не тратится.
- **Постановка.** Шар перелетает из «Сейчас» в клетку, 180 мс, ease-out.
  После этого очередь сдвигается влево, 200 мс. Пока идёт анимация, ввод
  заблокирован.
- **Payoff.** Шары собранной линии вспыхивают и сжимаются в ноль, 260 мс,
  линия коротко подсвечена полосой поверх шаров. Двойная очистка — две
  полосы одновременно, шары подпрыгивают перед исчезновением (+120 мс).
- **Цена хода.** Поставленный шар не двигается и не снимается.
- **Победа.** Все клетки поля подпрыгивают волной, через 500 мс попап победы.
- **Поражение.** Текущий шар покачивается, все пустые клетки приглушены, через
  `900 мс` попап «Шару некуда встать» — «Для этого шара не осталось подходящей
  клетки».
- **Без текста игрок должен понять:** шар встаёт только туда, где совпадает
  цвет или форма; три в ряд с общим признаком исчезают; очередь показывает,
  какие шары придут.

**Обучение — попап «Как играть».** Открывается сам при первом входе в
уровень 1, дальше — по «?». Картинка-пример: линия из трёх синих шаров
разной формы исчезает. Четыре правила:

1. Ставь шар в клетку, где совпадает цвет или форма. Клетка с точкой примет
   любой шар.
2. Три в ряд — по горизонтали, вертикали или диагонали — с одним цветом или
   одной формой исчезают.
3. Вверху видно текущий шар и три следующих. Береги клетки для них.
4. Поставь все шары. Если шару некуда встать — попытка проиграна.

Строка подсказки под полем постоянна: «Три в ряд с общим цветом или общей
формой исчезают».

## 7.1. Экран — как выглядит поле

![Игровой экран](../UI%20Design/prototypes/tight-shelf/game-screen.png)

Скетч — `UI Design/prototypes/tight-shelf/game-screen.html` (390×664,
уровень 3, середина партии). Рядом тот же экран в оттенках серого,
`game-screen-gray.png`: проверка второго канала цвета.

Сверху вниз:

1. **Шапка, 48 px:** слева иконка «к уровням», по центру «Уровень N», справа
   иконки «?» и «заново».
2. **Очередь, карточка:** слева текущий шар 64 px с подписью «Сейчас»,
   разделитель, справа три следующих шара по 44 px, слева направо в порядке
   прихода, с подписью «Дальше».
3. **Поле — главный объект, занимает оставшееся место.** Размер клетки
   считается от свободного места, 56–88 px. Шар в клетке — 78% клетки.
4. **Строка подсказки** под полем.

Почему так: очередь — информация для решения, поэтому она над полем. Палец
тапает поле снизу и не закрывает очередь.

**Экран помещается без прокрутки** от 360×560 до 430×932.

За секунду читаются: текущий шар, куда ему можно (неприглушённые клетки), и
какие шары идут следом. Payoff — на поле, в линии, которая исчезает.

**Второй канал к цвету — узор.** Скетч в сером показал: синий и коралловый
шары без узора сливаются. Поэтому синий — гладкий, коралловый — в косую
полоску, жёлтый — в точку. Тот же узор на подкрашенных клетках-правилах.
Узор — белый полупрозрачный поверх цвета из токенов, новых цветов нет. Форма
всегда передаётся знаком, не цветом.

Новые объекты — шар, клетка-правило, выдавленный контур — собраны из токенов
кита (`--ui-blue`, `--ui-yellow`, `--ui-coral`, `--ui-surface-muted`,
`--ui-disabled`, `--ui-shadow-tile`, `--ui-radius-large`, `--ui-radius-pill`).
Это одноразовые объекты прототипа, они живут в
`UI Design/prototypes/tight-shelf/`.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=70%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - уровни 3–5 жадный бот не проходит (tests/levels.test.ts)
    - на уровнях 3–5 доля ходов игроков в видимую ловушку заметно ниже, чем у случайного выбора (42–51%, --report)
    - минимум один игрок словами объясняет, что держал клетку под шар из очереди
  kill:
    - выполняется заранее записанный kill_criterion
```

Первое валидное действие — первый поставленный шар. По нему считается
`first_action_without_help`.

**Ловушка, видимая в превью** — клетка для текущего шара, после которой
один из трёх следующих шаров гарантированно некуда поставить, хотя другая
подходящая клетка этого избегает (`visibleTraps` в солвере). Базовая линия
случайного выбора подходящей клетки, по 300 партий на уровень:

| Уровень | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| Случайный выбор попадает в видимую ловушку | 44% | 43% | 39% | 51% | 42% |

В лог уровня на каждом ходе пишутся: номер шара, шар, клетка, число
подходящих клеток, число исчезнувших линий. Солвера в игре нет. Доля ходов в
видимую ловушку считается после теста: лог прогоняется через
`visibleTraps` в `tools/tight-shelf-solver.mjs`.

- `preview_trap_rate` — доля ходов в видимую ловушку среди ходов, где она
  была; по уровням 3–5. Это kill-метрика.
- `double_clears` — число двойных очисток за уровень: проверка payoff.

Метрики, кроме kill, диагностические. Решение Gate 2 — по наблюдаемому
поведению и kill-критерию.

`tools/tight-shelf-solver.mjs` без изменений. `tests/levels.test.ts`
прогоняет решение точного солвера через движок игры. Солвер, боты и
`visibleTraps` нужны для подбора уровней, тестов и разбора логов, в игре их
нет.
