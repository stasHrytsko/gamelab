# 1. Граница прототипа

**Что проверяем.** Смотрит ли игрок в очередь перед ходом: оставляет ли
свободной клетку, которая скоро понадобится фигуре из превью, даже когда
текущая фигура туда тоже подходит.

**Минимальный цикл.** Поле 4×4 с правилами клеток, очередь «текущая + 3
следующих», тап по клетке, исчезновение линий, проверка «фигуре некуда
встать». Вокруг цикла пять экранов и попапы (§7.1, `apps/CLAUDE.md` §2).

**Не делаем.** Таймер, отмену хода, перемещение поставленных фигур, бустеры,
очки, звёзды, подсказку лучшего хода, предупреждение «уровень уже не пройти»,
третий признак фигуры (размер), вставку фигур со сдвигом, гравитацию, звук,
настройки и бесконечный режим.

**Уровней пять.** Открываются по очереди.

**Откуда эта версия.** Первая версия идеи — товары и полки с таблицей
совместимости. Автор отказался от неё 2026-09-28. Текущие правила выбраны
прогоном ботов по девяти вариантам геометрии и A/B со вставкой со сдвигом.
Таблица и выводы — в `ideas/approved/06-tight-shelf.md`, «Как выбрали
правила». Сначала фишки были шарами с белым знаком формы. Решение автора
2026-09-28: фишка сама имеет форму — квадрат, круг или треугольник нужного
цвета. Правила от этого не изменились.

**Почему kill-критерий такой.** Вся глубина игры — в превью: бот, который
видит три фигуры вперёд, выигрывает уровень 5 в 80% попыток, бот без очереди
— в 20%, случайный — в 0% (§6). Если игроки не обходят ловушки, которые видно
в очереди, чаще случайного выбора, они играют в «поставь, куда подходит». Это
не лечится подбором уровней: решение просто не происходит в голове игрока.

# 2. Цель и основной цикл

Цель игрока — поставить на поле все фигуры очереди уровня.

Первое доступное действие — тапнуть пустую клетку поля, чьё правило подходит текущей фигуре.

```text
Посмотреть на текущую фигуру и три следующих
→ тапнуть пустую клетку, чьё правило подходит текущей фигуре
→ фигура встаёт в клетку; линии через неё с общим цветом или формой исчезают
→ очередь сдвигается на одну фигуру
→ проверка победы и поражения по §5
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Фигура | в очереди; текущая; на поле; исчезла | становится текущей при сдвиге очереди; встаёт на поле тапом; исчезает в линии | цвет — один из `B` синий, `Y` жёлтый, `C` коралловый; форма — одна из `o` круг, `s` квадрат, `t` треугольник; 9 типов |
| Клетка | пустая; занята фигурой | занимается постановкой; освобождается, когда её фигура исчезает | правило задано уровнем и не меняется: цвет (`B`, `Y`, `C`), форма (`o`, `s`, `t`) или `.` — любая фигура; в клетке не больше одной фигуры |
| Очередь | — | сдвигается на одну фигуру после каждой постановки | порядок и состав заданы уровнем; видно текущую фигуру и не больше трёх следующих |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Фигура подходит клетке**, если правило клетки `.`, или совпадает с цветом
фигуры, или совпадает с её формой.

**Пространство.** Поле — сетка 4×4. Клетка адресуется индексом
`i = row * 4 + col`, `row` сверху вниз, `col` слева направо, 0..3. Линия —
три подряд идущие клетки по горизонтали, вертикали или диагонали. Таких линий
24: 8 горизонтальных, 8 вертикальных, 8 диагональных. Очередь — список,
индекс 0 — первая фигура уровня.

```ts
type Color = 'B' | 'Y' | 'C';
type Shape = 'o' | 's' | 't';
type Piece = `${Color}${Shape}`;        // 'Bt' — синий треугольник
type Rule = Color | Shape | '.';

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  rules: Rule[];                          // 16, из уровня
  board: (Piece | null)[];                // 16
  queue: Piece[];                         // из уровня
  turn: number;                           // индекс текущей фигуры в queue
  status: 'playing' | 'won' | 'failed';
  failReason: 'no_moves' | null;
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

# 4. Ввод и правила

```ts
type Action =
  | { type: 'tap-cell'; cell: number }    // 0..15
  | { type: 'open-help' }
  | { type: 'restart' }
  | { type: 'exit-to-levels' };
```

Только тап. Перетаскивания, долгого нажатия, свайпа, отмены хода и тапа по
фигурам очереди нет.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Тап по клетке | пустая, правило подходит текущей фигуре | фигура ставится в клетку, дальше по «Исчезновение линий» и §5 | фигура перелетает из «Сейчас» в клетку | да |
| Тап по клетке | пустая, правило не подходит текущей фигуре | ничего | клетка покачивается 160 мс, короткая вибрация | нет |
| Тап по клетке | занята фигурой | ничего | клетка покачивается 160 мс, короткая вибрация | нет |
| Тап мимо поля | всегда | ничего | ничего | нет |
| Тап по фигуре в очереди | всегда | ничего | ничего | нет |
| «?» | попапа нет | ввод заблокирован | попап «Как играть» | нет |
| «Понятно!» | попап «Как играть» открыт | `howToPlaySeen = true` | игра с того же места | нет |
| «Заново» | всегда | уровень в начальное состояние | пустое поле, очередь с начала | — |
| «К уровням» | всегда | попытка брошена | экран уровней | — |
| Любое действие по полю | идёт анимация хода, открыт попап или `status !== 'playing'` | ничего | ничего | нет |

**Исчезновение линий.** После постановки фигуры в клетку `i`:

1. Проверяются только линии, проходящие через `i`.
2. Линия собрана, если все три её клетки заняты и у трёх фигур один цвет или
   одна форма.
3. Все собранные линии исчезают одновременно: освобождается объединение их
   клеток.
4. Фигура, поставленная в пересечение двух собранных линий, закрывает обе
   (двойная очистка).
5. Клетки вне собранных линий не меняются, даже если стоят в том же ряду.
   Пример: в ряду `Yo Bs Bt _` ставим `Bo` в последнюю клетку. Линия
   `Bs Bt Bo` синяя и исчезает, `Yo` остаётся.
6. Каскадов нет: после исчезновения фигуры не двигаются, и новые линии не
   проверяются.

Линии, не проходящие через поставленную фигуру, не проверяются. По построению
среди них нет собранных: каждая линия проверяется в момент, когда
заполняется её последняя клетка.

# 5. Победа, поражение и переходы

```text
Дано: текущая фигура — последняя в очереди.
Когда: она поставлена и линии обработаны.
Тогда: попытка заканчивается победой; фигуры, оставшиеся на поле, не мешают.
       Уровень добавляется в passed, открывается следующий, попап победы —
       на уровнях 1–4 обычный, на уровне 5 финальный.
```

```text
Дано: в очереди остались фигуры.
Когда: после сдвига очереди у новой текущей фигуры нет ни одной пустой
       клетки с подходящим правилом.
Тогда: попытка заканчивается поражением с причиной no_moves; текущая фигура
       покачивается, через 900 мс попап «Фигуре некуда встать».
```

```text
Дано: после хода уровень уже нельзя пройти, но текущей фигуре есть куда встать.
Когда: завершена обработка хода.
Тогда: игра продолжается молча. Никаких предупреждений и подсветок.
```

Игра не предсказывает проигрыш (`apps/CLAUDE.md` §3): поражение наступает
только тогда, когда текущей фигуре действительно некуда встать.

Порядок проверок после тапа по подходящей клетке: поставить фигуру → найти
собранные линии через неё → убрать их фигуры → сдвинуть очередь → проверить
победу → проверить `no_moves` → вернуть ввод.

Код причины поражения один и стабильный: `no_moves`.

**Случайности нет.** Правила клеток и вся очередь заданы уровнем. Попытки
одного уровня всегда начинаются с одного и того же состояния.

**Переходы между экранами** — как в `apps/CLAUDE.md` §2: главный → уровни →
игровой экран; попап победы: «Следующий уровень», «Переиграть», «К уровням»;
попап поражения: «Переиграть», «К уровням»; финальный попап после уровня 5:
«Переиграть», «К уровням».

# 6. Контент и кривая сложности

Пример данных одного уровня (`tools/tight-shelf-levels.json`):

```json
{
  "id": 3,
  "seed": 18,
  "rules": ["BBB.", "Bs.o", ".tsB", "C.YB"],
  "queue": ["Yo", "Ct", "Ct", "Bt", "Ct", "Co", "Yt", "Yt", "Cs", "Ct", "Yo", "Bo",
            "Cs", "Yt", "Bs", "Yt", "Ct", "Yt", "Bs", "Ct", "Bt", "Co", "Ct", "Yo"]
}
```

`rules` — четыре строки поля сверху вниз, по символу на клетку.

**Правило генерации** (`generate` и `CURVE` в `tools/tight-shelf-solver.mjs`).
Уровень N задаётся числом джокеров и длиной очереди. Джокеры ставятся в
случайные клетки, остальные клетки получают одно из шести правил
равновероятно, очередь — равновероятные фигуры из 9 типов. Перебираются seed
от 1. Берётся первый уровень, который проходит проверки из таблицы ниже.

| Уровень | Джокеров | Очередь | Отбор |
|---:|---:|---:|---|
| 1 | 8 из 16 (50%) | 18 | решаем; жадный проходит; случайный ≥ 60%; ловушек ≤ 1 |
| 2 | 6 (38%) | 22 | решаем; все 6 правил на поле; жадный проходит; случайный 30–60%; ловушек ≥ 1 |
| 3 | 4 (25%) | 24 | решаем; все 6 правил; жадный не проходит; случайный ≤ 30%; превью 3 ≥ 80%; ловушек ≥ 3 |
| 4 | 3 (19%) | 30 | то же; случайный ≤ 15%; без превью ≤ 50%; превью 3 ≥ 70%; ловушек ≥ 5 |
| 5 | 1 (6%) | 36 | то же; случайный ≤ 5%; без превью ≤ 30%; превью 3 ≥ 60%; ловушек ≥ 7 |

Термины отбора:

- **решаем** — точный солвер находит расстановку всей очереди;
- **жадный** — детерминированный бот: клетка, где исчезает больше всего
  фигур, при равенстве первая по индексу;
- **случайный** — любая подходящая клетка;
- **без превью** — лучшая оценка поля после хода без знания очереди;
- **превью 3** — перебор текущей и трёх следующих фигур;
- **ловушка** — ход вдоль найденного солвером решения, где хотя бы одна
  подходящая клетка делает уровень нерешаемым, а другая нет.

Доли побед случайного бота — по 2000 попыток, без превью — по 400,
превью 1 — по 200, превью 3 — по 100.

**Уровни** (seed и полные очереди — `tools/tight-shelf-levels.json`, метрики
— `node tools/tight-shelf-solver.mjs --report`, 2026-09-28):

| Уровень | Поле | Случайный | Без превью | Превью 1 | Превью 3 | Ловушек | Первая ловушка |
|---:|---|---:|---:|---:|---:|---:|---:|
| 1 | `.t..` `ss..` `.Yt.` `tBo.` | 75% | 98% | 100% | 100% | 1 | фигура 11 |
| 2 | `C.sB` `tY..` `Cst.` `.Bo.` | 46% | 82% | 100% | 100% | 3 | фигура 9 |
| 3 | `BBB.` `Bs.o` `.tsB` `C.YB` | 23% | 72% | 85% | 98% | 3 | фигура 6 |
| 4 | `B.oo` `.ooY` `osYC` `ot.s` | 5% | 32% | 46% | 90% | 5 | фигура 5 |
| 5 | `tCBs` `otBB` `YsBY` `toB.` | 0% | 20% | 39% | 80% | 13 | фигура 9 |

| Уровень | Новый навык | Главное давление | Сложный момент |
|---:|---|---|---|
| 1 | поставить фигуру в подходящую клетку; увидеть, как исчезает линия | почти нет: половина поля — джокеры | 18 фигур на 16 клеток — без хотя бы одной линии не пройти |
| 2 | правила формы и цвета вперемешку; линия по форме, а не только по цвету | 6 джокеров, клетки начинают кончаться | первые ловушки, но жадная игра их ещё проходит |
| 3 | сберечь клетку под фигуру из превью | жадный ход «собери линию сейчас» проигрывает | первая ловушка уже на 6-й фигуре |
| 4 | держать две клетки под разные фигуры очереди | 3 джокера, 30 фигур | без превью бот выигрывает только в 32% |
| 5 | всё вместе на почти полностью «правильном» поле | 1 джокер, 36 фигур, 13 ловушек | превью решает: 80% против 20% без него |

Разница между соседними уровнями:

- `1→2` — появляются все шесть правил и линии по форме; джокеров меньше.
- `2→3` — жадная игра перестаёт работать: впервые нужно не собирать линию
  сейчас, а сберечь клетку.
- `3→4` — ловушек больше и раньше, одной сбережённой клетки уже мало.
- `4→5` — почти нет джокеров, 13 ловушек: прямая проверка гипотезы.

**Проверки уровней** (`tests/levels.test.ts` в прототипе):

- каждый уровень решаем точным солвером, а его решение проходится движком
  игры;
- все фигуры очереди подходят хотя бы одной клетке поля;
- уровни 1–2 жадный бот проходит;
- уровни 3–5 жадный бот не проходит — kill-критерий дизайна в форме теста;
- уровень N+1 не легче уровня N для случайного бота.

# 7. Обратная связь и обучение

- **Фигура.** Силуэт — форма: скруглённый квадрат, круг или треугольник со
  скруглёнными углами. Заливка — чистый цвет (§7.1), блик сверху, тёмная
  кромка снизу. Знаков и узоров на фигуре нет.
- **Правило клетки.** Цвет — клетка подкрашена этим цветом, с рамкой того
  же цвета. Форма — на серой клетке выдавленный контур круга, квадрата
  или треугольника: фигура этой формы в него «вкладывается». Джокер — серая
  клетка с точкой, как «Пустая» клетка кита. Вид клетки зависит только от её
  правила и не меняется от того, какая фигура сейчас текущая.
- **Доступное действие.** Игра не подсвечивает и не приглушает клетки под
  текущую фигуру: игрок сам сверяет фигуру с правилом клетки. Решение автора
  2026-09-28 после первой игры: «клетки с цветом подсвечиваются — ощущение,
  что игра заставляет меня именно туда ставить фигуру». Ошибку объясняет
  отказ: клетка покачивается, ход не тратится.
- **Запрещённое действие.** Клетка покачивается 160 мс, короткая вибрация.
  Ход не тратится.
- **Постановка.** Фигура перелетает из «Сейчас» в клетку, 180 мс, ease-out.
  После этого очередь сдвигается влево, 200 мс. Пока идёт анимация, ввод
  заблокирован.
- **Payoff.** Фигуры собранной линии вспыхивают и сжимаются в ноль, 260 мс,
  линия коротко подсвечена полосой поверх фигур. Двойная очистка — две
  полосы одновременно, фигуры подпрыгивают перед исчезновением (+120 мс).
- **Цена хода.** Поставленная фигура не двигается и не снимается.
- **Победа.** Все клетки поля подпрыгивают волной, через 500 мс попап победы.
- **Поражение.** Текущая фигура покачивается, все пустые клетки приглушены,
  через `900 мс` попап «Фигуре некуда встать» — «Для этой фигуры не осталось
  подходящей клетки».
- **Без текста игрок должен понять:** фигура встаёт только туда, где
  совпадает цвет или форма; три в ряд с общим признаком исчезают; очередь
  показывает, какие фигуры придут.

**Обучение — попап «Как играть».** Открывается сам при первом входе в
уровень 1, дальше — по «?». Картинка-пример: линия из трёх синих фигур
разной формы исчезает. Четыре правила:

1. Ставь фигуру в клетку, где совпадает цвет или форма. Клетка с точкой
   примет любую фигуру.
2. Три в ряд — по горизонтали, вертикали или диагонали — с одним цветом или
   одной формой исчезают.
3. Вверху видно текущую фигуру и три следующих. Береги клетки для них.
4. Поставь все фигуры. Если фигуре некуда встать — попытка проиграна.

Строка подсказки под полем постоянна: «Три в ряд с общим цветом или общей
формой исчезают».

## 7.1. Экран — как выглядит поле

![Игровой экран](../UI%20Design/prototypes/tight-shelf/game-screen.png)

Скетч — `UI Design/prototypes/tight-shelf/game-screen.html` (390×664,
уровень 3, середина партии).

Сверху вниз:

1. **Шапка, 48 px:** слева иконка «к уровням», по центру «Уровень N», справа
   иконки «?» и «заново».
2. **Очередь, карточка:** слева текущая фигура 64 px с подписью «Сейчас»,
   разделитель, справа три следующих фигуры по 44 px, слева направо в
   порядке прихода, с подписью «Дальше · ещё N фигур» — сколько фигур,
   включая текущую, осталось поставить до победы. На экранах ниже 620 px
   фигуры 48 и 34 px.
3. **Поле — главный объект, занимает оставшееся место.** Размер клетки
   считается от свободного места, 56–88 px. Фигура в клетке — 74% клетки.
4. **Строка подсказки** под полем.

Почему так: очередь — информация для решения, поэтому она над полем. Палец
тапает поле снизу и не закрывает очередь.

**Экран помещается без прокрутки** от 360×560 до 430×932.

За секунду читаются: текущая фигура, правила клеток (цвет — подкраска,
форма — контур) и какие фигуры идут следом. Payoff — на поле, в линии, которая исчезает.

**Размер фигур подобран на глаз под одинаковый визуальный вес,** а не по
одной формуле: в квадрате 100×100 квадрат 82×82 со скруглением 18, круг
радиусом 45, треугольник с вершинами (50, 9), (93, 86), (7, 86) и
скруглением углов 14. Треугольник крупнее, иначе он выглядит меньше
соседей.

**Цвета чистые, без второго канала (решение автора 2026-09-28).** Сначала у
цвета был узор: коралловый в полоску, жёлтый в точку, потому что в оттенках
серого синий и коралловый сливаются. Автор убрал узоры: «оставь только
чистые цвета». Цвета — `--ui-blue`, `--ui-yellow`, `--ui-coral` (красный в
ките — коралловый, `--ui-danger` оставлен за поражением). Это осознанный
риск: игроку, который плохо различает синий и красный по светлоте, цвет
придётся угадывать. На красно-зелёный дальтонизм тройка синий / жёлтый /
красный реагирует слабо, так что риск умеренный. Если на тесте кто-то
спутает цвета, узор возвращается одной правкой в `src/ui/pieces.ts`. Форма
передаётся силуэтом, цвет форму не кодирует.

**Главный экран — арт автора** (2026-09-29):
`UI Design/prototypes/tight-shelf/assets/home-screen.png` — название,
поле 4×4 с фигурами, летящие фигуры. В игре — `home-art.webp`: арт обрезан
сверху (нарисованные шестерёнка и звук) и снизу (нарисованная кнопка),
края растворяются в размытой копии арта на фоне. Под артом — настоящая
кнопка «Играть» по `apps/CLAUDE.md` §2. Арт и кнопка — одной группой по
центру, помещаются без прокрутки от 360×560.

**Снимки собранного прототипа** — `UI Design/prototypes/tight-shelf/`:
главный, уровни, игровой экран (`app-game.png`), момент очистки
(`app-clear.png`), 360×560 (`app-small.png`), «Как играть», проигрыш, победа.
Пересобираются из `apps/tight-shelf` (`tools/make-screens.ts`).

Новые объекты — фигура, клетка-правило, выдавленный контур — собраны из
токенов кита (`--ui-blue`, `--ui-yellow`, `--ui-coral`,
`--ui-surface-muted`, `--ui-disabled`, `--ui-radius-large`). Это одноразовые
объекты прототипа, они живут в `UI Design/prototypes/tight-shelf/`.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=70%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - уровни 3–5 жадный бот не проходит (tests/levels.test.ts)
    - на уровнях 3–5 доля ходов игроков в видимую ловушку заметно ниже, чем у случайного выбора (39–51%, --report)
    - минимум один игрок словами объясняет, что держал клетку под фигуру из очереди
  kill:
    - выполняется заранее записанный kill_criterion
```

Первое валидное действие — первая поставленная фигура. По нему считается
`first_action_without_help`.

**Ловушка, видимая в превью** — клетка для текущей фигуры, после которой
одну из трёх следующих фигур гарантированно некуда поставить, хотя другая
подходящая клетка этого избегает (`visibleTraps` в солвере). Базовая линия
случайного выбора подходящей клетки, по 300 партий на уровень:

| Уровень | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|
| Случайный выбор попадает в видимую ловушку | 44% | 43% | 39% | 51% | 42% |

В лог уровня на каждом ходе пишутся: номер фигуры, фигура, клетка, число
подходящих клеток, число исчезнувших линий. Солвера в игре нет. Доля ходов в
видимую ловушку считается после теста: лог прогоняется через
`visibleTraps` в `tools/tight-shelf-solver.mjs`.

- `preview_trap_rate` — доля ходов в видимую ловушку среди ходов, где она
  была; по уровням 3–5. Это kill-метрика.
- `double_clears` — число двойных очисток за уровень: проверка payoff.

Метрики, кроме kill, диагностические. Решение Gate 2 — по наблюдаемому
поведению и kill-критерию.

# Приложение A. Профиль реализации

**Фабрика.** `apps/tight-shelf/` (папка названа по slug), по `apps/CLAUDE.md`:
веб-игра под браузер телефона, TypeScript + Vite, без фреймворка, экран на
HTML/CSS. Токены и шрифт — из `UI Design/`. Фигуры — inline SVG, как в
скетче.

**Уровни** копируются из `tools/tight-shelf-levels.json` в
`apps/tight-shelf/src/levels/levels.json`. Пересобрать их:
`node tools/tight-shelf-solver.mjs > tools/tight-shelf-levels.json`.

**Движок** портирует `fits`, `legal` и `place` из
`tools/tight-shelf-solver.mjs` без изменений. `tests/levels.test.ts`
прогоняет решение точного солвера через движок игры. Солвер, боты и
`visibleTraps` нужны для подбора уровней, тестов и разбора логов, в игре их
нет.
