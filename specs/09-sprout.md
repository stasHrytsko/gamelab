# 1. Граница прототипа

**Что проверяем.** Берёт ли игрок на уровнях 3–5 первым не ближайший
источник, а тот, после которого остальные ещё достижимы, и понимает ли после
проигрыша, что его порядок отрезал воду.

**Минимальный цикл.** Поле 6×6 с камнями, водой, точками А и Б. Тап по
соседней с кончиком клетке, рост корня на одну клетку, счётчик оставшихся
ходов, пополнение на воде. Вокруг цикла — главный экран, экран уровней и
попапы (§5, §7.1).

**Не делаем.** Отмену хода, подсказку маршрута, предупреждение «уже не
дойти», подсветку «собери всю воду», звёзды и очки за остаток ходов, таймер,
звук, настройки, другие типы клеток (удобрение, корни-ветки, движущиеся
камни), поля другого размера и бесконечный режим.

**Уровней пять.** Два обучающих и три с ловушкой. Уровни собирает генератор
по зерну, отбирает солвер, и в игре они заморожены (§6). Открываются по
очереди.

**Почему kill-критерий такой.** Игру делает интересной только порядок обхода
воды. Если к победе почти всегда ведёт «иди к ближайшей воде», то порядок
очевиден, и остаётся лабиринт с ресурсом. Подбором пяти уровней это не
вылечить, поэтому критерий меряется на всём пуле валидных уровней
генератора, а не на выбранных. На 2026-09-26 жадная стратегия проходит 43%
пула (§6), то есть структурно критерий не выполнен. Проверять надо игроков:
поле маленькое, и уровень можно пройти перебором через «заново». §8 отделяет
осознанный выбор первого источника от найденного перебором.

# 2. Цель и основной цикл

Цель игрока — довести кончик корня до клетки Б.

Первое доступное действие — тапнуть клетку рядом с А.

```text
Тапнуть свободную клетку рядом с кончиком корня
→ корень вырастает в неё, запас ходов −1
→ если это Б — победа
→ если это вода — запас +X
→ проверка поражения по §5
→ ввод возвращается игроку
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Клетка «земля» | свободна; занята корнем | тап, когда клетка соседняя с кончиком: занимается корнем | занятая корнем не освобождается до «заново» |
| Камень | стоит | не меняется | корень в него не растёт |
| Вода `+X` | полная; выпита (занята корнем) | корень вырос в неё: запас `+X`, клетка становится корнем | `X` от 2 до 6, виден с начала; одноразовая, потому что в клетку корня вход закрыт |
| А | старт, первая клетка корня | — | одна на уровень |
| Б | цель | корень вырос в неё: победа | одна на уровень; вход в Б заканчивает попытку |
| Кончик корня | клетка, куда корень вырос последним | переходит на новую клетку каждым ходом | стартует на А |
| Запас ходов | 0…∞ | −1 за шаг, `+X` за воду | стартовое значение задано уровнем |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Пространство.** Поле — сетка 6×6. Клетка адресуется `row` (0–5, сверху
вниз) и `col` (0–5, слева направо). В тексте спеки клетки названы как на
шахматной доске: столбцы `a`–`f` слева направо, ряды `1`–`6` снизу вверх
(`a1` — левый нижний угол, `row 5, col 0`). Соседи — только по стороне.

```ts
type Cell = { row: number; col: number };

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  path: Cell[];             // корень от А до кончика включительно, path[0] = А
  moves: number;            // оставшийся запас
  status: 'playing' | 'won' | 'failed';
  failReason: 'moves_exhausted' | 'no_moves' | null;
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

Выпитая вода и занятая земля не хранятся отдельно, это клетки из `path`.

# 4. Ввод и правила

```ts
type Action =
  | { type: 'tap-cell'; row: number; col: number }
  | { type: 'restart' }
  | { type: 'open-help' }
  | { type: 'close-help' }
  | { type: 'exit-to-levels' };
```

Ввод только тапом. Свайпа, протягивания пальцем по клеткам, долгого
нажатия, отмены хода и диагоналей нет.

**Правила шага** — дословно как `step` в `tools/sprout-solver.mjs`:

1. Шаг — рост из кончика в соседнюю по стороне клетку.
2. Клетка шага не камень и не клетка корня.
3. Шаг возможен, только пока запас не меньше 1.
4. Шаг стоит ровно 1 ход: запас `−1`.
5. Если клетка шага — Б, попытка выиграна, даже если запас стал 0.
6. Если клетка шага — вода `+X`, сразу после `−1` запас `+X`. Войти в воду
   последним ходом можно: `1 − 1 + X = X`.
7. Случайности нет. Все бонусы видны с начала.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Тап по клетке | соседняя с кончиком, свободная земля | клетка в `path`, `moves − 1` | корень вытягивается в клетку | да |
| Тап по клетке | соседняя с кончиком, вода `+X` | клетка в `path`, `moves − 1 + X` | корень вытягивается, капля впитывается, `+X` летит к счётчику | да |
| Тап по клетке | соседняя с кончиком, Б | клетка в `path`, `moves − 1`, `status: 'won'` | корень доходит до Б, росток пробивается | да |
| Тап по клетке | соседняя с кончиком, камень | ничего | камень покачивается `160 мс`, короткая вибрация | нет |
| Тап по клетке | соседняя с кончиком, клетка корня | ничего | кончик покачивается `160 мс`, короткая вибрация | нет |
| Тап по клетке | не соседняя с кончиком (любая, включая сам кончик) | ничего | кончик пульсирует `300 мс`: «расти отсюда» | нет |
| Тап во время анимации шага | ввод заблокирован | ничего | ничего | нет |
| «Заново» | всегда | уровень в стартовое состояние | поле как в начале | — |
| «?» | попапа нет | ввод заблокирован | попап «Как играть» | нет |
| «Понятно!» | попап открыт | `howToPlaySeen = true` | игра с того же места | нет |
| «К уровням» | всегда | попытка брошена | экран уровней | — |
| Любое действие на поле | `status !== 'playing'` или открыт попап | ничего | ничего | нет |

Недопустимый тап никогда не тратит ход.

# 5. Победа, поражение и переходы

```text
Дано: кончик рядом с Б, запас не меньше 1.
Когда: игрок тапает Б.
Тогда: победа, даже если запас стал 0. Уровень добавляется в passed,
       открывается следующий, попап победы — на уровнях 1–4 обычный, на
       уровне 5 финальный.
```

```text
Дано: после шага запас равен 0, кончик не на Б.
Когда: завершена обработка шага (вода этого шага уже прибавлена).
Тогда: поражение с причиной moves_exhausted; счётчик вспыхивает коралловым,
       через 900 мс попап «Ходы закончились».
```

```text
Дано: после шага запас больше 0, кончик не на Б, у кончика нет ни одной
      соседней клетки, кроме камней и корня.
Когда: завершена обработка шага.
Тогда: поражение с причиной no_moves; кончик получает коралловое кольцо,
       через 900 мс попап «Корню некуда расти».
```

```text
Дано: до Б уже не дойти (Б отрезана корнем или запаса не хватит даже со
      всей доступной водой), но соседняя свободная клетка есть и запас > 0.
Когда: завершена обработка шага.
Тогда: игра продолжается молча. Никаких предупреждений и подсветок.
```

Игра не предсказывает проигрыш. Игрок сам упирается в ноль или в тупик,
«Заново» доступно всегда.

**Порядок после шага:** рост в клетку → `moves − 1` → проверить Б (победа)
→ прибавить воду `+X` → проверить `moves = 0` (`moves_exhausted`) →
проверить тупик (`no_moves`) → вернуть ввод. Если запас 0 и кончик в тупике
одновременно, причина — `moves_exhausted`.

Коды причин поражения стабильны: `moves_exhausted`, `no_moves`.

**Случайности нет.** Поле, бонусы и стартовый запас заданы уровнем и видны с
начала. Скрытой информации нет.

**Переходы между экранами** такие же, как в `specs/36-arrow-flip.md`:
главный → уровни → игровой экран. Попап победы: «Следующий уровень»,
«Переиграть», «К уровням». Попап поражения: «Переиграть», «К уровням».
Финальный попап после уровня 5: «Переиграть», «К уровням». Закрытый уровень
на экране уровней коротко покачивается.

# 6. Контент и кривая сложности

Пример данных одного уровня — формат солвера. Строки идут сверху вниз:
`.` земля, `#` камень, `A` старт, `B` цель, цифра `2`–`6` — вода с этим `+X`.

```json
{
  "name": "SP-4-1992", "start": 4,
  "rows": ["...6B.", ".#..#.", "..####", "..#.4.", "6..#3.", ".....A"]
}
```

**Генератор** (`randomLevel(seed, cfg)` в `tools/sprout-solver.mjs`): А — в
нижнем ряду, Б — в верхнем, камни и вода разбросаны по остальным клеткам по
зерну. Настройки уровней с ловушкой:

| Уровень | Воды | Камней | `+X` |
|---:|---:|---:|---|
| 3 | 4 | 8 | 3–6 |
| 4 | 5 | 8 | 2–5 |
| 5 | 6 | 8 | 2–4 |

**Валидный уровень с ловушкой** (`validate`):

- стартовый запас равен минимальному, при котором солвер находит победу
  (`minStart`), без запаса;
- каждый источник необходим: если обнулить бонус любого одного источника,
  оставив клетку проходимой, победы нет (`everySourceNeeded`). Отсюда же:
  без воды до Б не дойти, и любая победа выпивает всю воду;
- с А на стартовом запасе, не заходя в другую воду, достижимы минимум два
  источника (`firstChoices` ≥ 2) — два правдоподобных первых выбора.

**Отбор в игру** (`isTrapPick`, кандидатов печатает
`node tools/sprout-solver.mjs pick <воды> <камни> <min X> <max X>`): уровень
валиден; жадная стратегия не проходит; ближайший к А источник единственный
(без ничьей по расстоянию); ни одна победа не начинается с него, то есть он
приманка; стартовый запас не меньше 3. Из первых кандидатов по возрастанию
зерна уровни выбраны вручную так, чтобы рисунок поля был разный. Зерно 1396
пропущено: его расклад камней проходит отбор на всех трёх настройках, и три
уровня выглядели бы одинаково. На уровне 4 зерно 21657 взято вместо 9057:
у 9057 первыми достижимы четыре источника из пяти, и приманка среди них не читается.

**Жадная стратегия** (`greedy`, она же kill-критерий): кратчайшим путём по
свободным клеткам к ближайшему невыпитому источнику (при равенстве — к
большему `+X`, затем по порядку чтения), после всей воды — кратчайшим путём к
Б. Соседей перебирает в порядке вверх, вправо, вниз, влево.

**Обучающие уровни** (1–2, `tutorialPick`, команда `pick … tutorial`, взят
первый кандидат): стартовый запас — наибольший, при котором каждый источник
ещё необходим; запас сверх оптимума не меньше 2; жадная стратегия проходит;
каждый источник достижим первым; на уровне 2 побеждают оба порядка воды.
Уровень 1 — `randomLevel(1, { water: 1, stones: 4, X: 5–6 })`, уровень 2 —
`randomLevel(1392, { water: 2, stones: 5, X: 3–5 })`.

Уровни ниже — `GAME_LEVELS` в `tools/sprout-solver.mjs`. Игра берёт их оттуда
без правки руками.

### Уровень 1 — SP-T1, обучающий

Запас 7, одна вода.

```text
6  B  ·  ·  ·  ·  ·
5  ·  ·  ·  #  ·  ·
4  ·  ·  ·  ·  ·  ·
3  #  6  ·  ·  ·  ·
2  ·  ·  ·  ·  ·  ·
1  ·  #  ·  A  #  ·
   a  b  c  d  e  f
```

До Б кратчайшим путём 8 шагов, запас 7: без воды не дойти. Вода `b3 +6`
лежит почти на пути: `d1 d2 d3 c3 b3 b4 b5 b6 a6`, в Б остаётся 5 ходов.
Минимальный запас — 4, так что свободы хватает. Навык: шаг стоит ход, вода
даёт ходы.

### Уровень 2 — SP-T2, обучающий

Запас 4, две воды.

```text
6  B  ·  ·  ·  ·  ·
5  #  ·  ·  ·  ·  ·
4  #  ·  ·  ·  #  ·
3  ·  #  ·  ·  ·  ·
2  ·  ·  ·  5  ·  ·
1  ·  A  ·  5  ·  #
   a  b  c  d  e  f
```

Обе воды нужны и обе достижимы первыми. Побеждают оба порядка: `d2 → d1` и
`d1 → d2`. Минимальный запас — 2. Навык: воды несколько, нужна вся, порядок
выбираешь сам.

### Уровень 3 — SP-4-1992, первая ловушка

Запас 4, четыре воды.

```text
6  ·  ·  ·  6  B  ·
5  ·  #  ·  ·  #  ·
4  ·  ·  #  #  #  #
3  ·  ·  #  ·  4  ·
2  6  ·  ·  #  3  ·
1  ·  ·  ·  ·  ·  A
   a  b  c  d  e  f
```

Ближайшая вода `e2 +3` — в двух шагах, это приманка: взять её первой значит
отрезать `e3`. Верно начать с `e3` через `f2 f3`, затем `e2`, дальше по
нижнему ряду к `a2` и вверх к `d6`. Единственный победный порядок
`e3 → e2 → a2 → d6`, путь
`f1 f2 f3 e3 e2 e1 d1 c1 c2 b2 a2 a3 a4 a5 a6 b6 c6 d6 e6`.

### Уровень 4 — SP-5-21657

Запас 4, пять вод.

```text
6  B  ·  #  #  #  #
5  #  ·  ·  ·  2  ·
4  ·  #  #  ·  ·  ·
3  ·  ·  ·  ·  2  ·
2  5  2  2  ·  ·  #
1  ·  ·  ·  ·  A  ·
   a  b  c  d  e  f
```

Ближайшая вода `e3 +2` в двух шагах вверх, дорога к Б тоже вверху, и это
приманка. Верно сначала уйти влево к ряду `c2 b2 a2`, подняться и только
потом взять `e3` и `e5`. Победный порядок `c2 → b2 → a2 → e3 → e5`, путь
`e1 e2 d2 c2 b2 a2 a3 b3 c3 d3 e3 e4 e5 d5 c5 b5 b6 a6`.

### Уровень 5 — SP-6-1630, проверка гипотезы

Запас 4, шесть вод.

```text
6  ·  ·  #  ·  ·  B
5  4  ·  ·  #  3  #
4  3  ·  2  #  ·  ·
3  ·  #  3  ·  #  ·
2  4  #  ·  ·  ·  ·
1  ·  ·  ·  A  #  ·
   a  b  c  d  e  f
```

Ближайшая вода `c3 +3` в трёх шагах, и её надо брать почти последней. Верно
начать с дальней `a2`, пройти левый край, вернуться через `c4 c3` вниз и
выйти к Б справа. Победный порядок `a2 → a4 → a5 → c4 → c3 → e5`, путь
`d1 c1 b1 a1 a2 a3 a4 a5 b5 c5 c4 c3 d3 d2 e2 f2 f3 f4 e4 e5 e6 f6` — 21
шаг по 28 свободным клеткам.

Разница между соседними уровнями:

- `1→2` — источников два, и оба обязательны; порядок выбирает игрок, оба
  верны. Запас сверх оптимума 2 вместо 3.
- `2→3` — появляется ловушка: ближайшая вода проигрывает уровень. Запас без
  свободы, источников четыре.
- `3→4` — пять источников, приманка стоит по дороге к Б, верный маршрут
  сначала уходит от Б в сторону.
- `4→5` — шесть источников, ближайшую воду надо оставить почти на конец,
  маршрут занимает 21 из 28 свободных клеток. Уровень проверяет гипотезу
  напрямую.

**Как проверяется решаемость.** Солвер перебирает пути корня полностью
(DFS), отсекая ветку, когда Б отрезана или запаса вместе со всей ещё
достижимой водой не хватает на расстояние до Б, и запоминая лучший запас для
пары «кончик + занятые клетки». Тест прототипа прогоняет пути солвера через
движок игры и проверяет каждое свойство отбора.

# 7. Обратная связь и обучение

- **Доступное действие:** свободные соседние клетки кончика (земля, вода,
  Б) обведены зелёным кольцом. Кольцо переезжает с каждым шагом.
- **Запрещённое действие:** по §4. Камень или корень покачиваются `160 мс`
  на 4 px, короткая вибрация. Тап вдали пульсирует кончиком.
- **Цена хода:** крупный счётчик «Ходы `N`» под шапкой — оставшийся запас.
  Каждый шаг уменьшает его на 1 в момент роста. Когда осталось `≤ 2`, у
  счётчика коралловая обводка.
- **Вода:** тайл с каплей и крупным `+X`. После шага в воду число `+X`
  летит к счётчику, и счётчик подпрыгивает на прибавке. На клетке корня
  остаётся маленькая капля — след «здесь выпита вода».
- **Корень:** клетки корня светло-зелёные, через их центры идёт тёмно-зелёный
  стебель, на кончике — листок. На А — семечко, Б — жёлтый тайл с ростком и
  лучами. Букв «А» и «Б» на поле нет (решение автора 2026-09-27): точки
  различаются значком и цветом, а буквы остаются только названиями в спеке.
- **Победа — payoff:** корень входит в Б, из Б пробивается росток и
  распускается, по всему корню от А до Б пробегает волна свечения, попап.
- **Поражение:** `moves_exhausted` — счётчик вспыхивает коралловым;
  `no_moves` — вокруг кончика коралловое кольцо. Через `900 мс` попап
  «Ходы закончились» или «Корню некуда расти».
- **Без текста игрок должен понять:** растёшь на соседнюю клетку; каждый шаг
  минус ход; вода плюс ход; назад не растёшь. Что воду нужно собрать всю, он
  открывает сам. Текстом это не пишется нигде.

**Обучение — попап «Как играть».** Открывается сам при первом входе в
уровень 1, дальше по кнопке «?». Картинка-пример и четыре правила:

1. Тапни клетку рядом с кончиком корня — корень вырастет туда.
2. Каждый шаг стоит 1 ход. Капля воды даёт столько ходов, сколько на ней
   написано.
3. В камень и туда, где корень уже вырос, расти нельзя.
4. Доведи корень до жёлтой клетки с ростком, пока не кончились ходы.

Больше подсказка не говорит ничего, в том числе про «всю воду».

На уровне 1 до первого шага внизу стоит подсказка со значком пальца:
«Нажми на соседнюю клетку, чтобы вырастить корень». После первого шага она
пропадает. На уровнях 2–5 подсказки нет.

## 7.2. Анимация

Числа — решение автора 2026-09-26 («записать сразу, без демо, поправить на
показе»).

- **Рост:** `180 мс`, `ease-out`. Стебель вытягивается из центра прежнего
  кончика в центр новой клетки (`transform: scaleX/scaleY` от края), клетка
  светлеет до зелёного, листок переезжает на новый кончик.
- **Вода:** после роста капля на клетке сжимается до маленькой (`200 мс`), а
  `+X` летит от клетки к счётчику `400 мс`, `cubic-bezier(.3, 0, .2, 1)`.
  Число на счётчике меняется в момент прилёта, счётчик подпрыгивает
  (`scale 1 → 1.15 → 1`, `200 мс`).
- **Ввод** возвращается после роста (`180 мс`), а на воде — после прилёта
  `+X` (`180 + 400 = 580 мс`).
- **Недопустимый тап:** покачивание `160 мс` на 4 px; пульс кончика
  `scale 1 → 1.12 → 1`, `300 мс`.
- **Победа:** рост в Б, затем росток на Б вырастает из земли
  (`scale 0 → 1.2 → 1`, `600 мс`), одновременно по клеткам корня от А к Б
  бежит волна `filter: brightness(1.3)` с шагом `40 мс` на клетку. Попап
  через `500 мс` после конца.
- **Поражение:** подсветка по §5, попап через `900 мс`.
- Анимируются только `transform`, `opacity` и `filter`.
- **`prefers-reduced-motion`:** клетка становится корнем сразу, `+X` не
  летит, число меняется сразу, волна победы заменена одной вспышкой. Кольца,
  листок и отметки остаются.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=75%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - на пуле генератора жадная стратегия проходит меньше 80% валидных уровней (проверка солвером, сейчас 43%)
    - на уровнях 3–5 жадная стратегия не проходит, а ближайший к А источник не начинает ни одной победы
    - на уровне 5 минимум половина победивших начинает победную попытку с верного первого источника не позже третьей попытки
    - минимум один игрок словами объясняет порядок («сначала туда, иначе потом не добраться»)
  kill:
    - выполняется заранее записанный kill_criterion
    - уровни 3–5 проходятся в основном перебором первого источника через «заново», а не планом (см. ниже)
```

Первое валидное действие — первый шаг корня на уровне 1. По нему считаются
`first_action_without_help` и `onFirstAction()`.

В лог на каждый шаг пишутся: уровень, номер попытки, номер шага, клетка,
была ли это вода и её `+X`, запас после шага, расстояние до ближайшего
невыпитого источника до шага, время от предыдущего шага. Осталась ли
победа достижимой после шага, игра не считает: солвер восстанавливает это по
выгруженному логу (`node tools/sprout-solver.mjs log <файл>`).

- `first_water` — какой источник выпит первым в попытке; `bait_first` —
  доля попыток на уровнях 3–5, где первой выпита ближайшая к А вода.
- `attempts_to_win` — попыток до победы на уровне.
- `switch_after_loss` — после проигрыша следующая попытка начата с другого
  первого источника.
- `step_lost` — номер шага, после которого победа стала недостижимой, против
  шага фактического поражения: как долго игрок идёт, не зная, что уже
  проиграл.
- `think_before_first` — пауза перед первым шагом попытки против медианы пауз
  игрока.
- `fail_reason` — доли `moves_exhausted` и `no_moves`.

**Как отделить план от перебора.** Перебор: на уровнях 3–4 первых выборов
два, и игрок, меняющий первый источник после каждого проигрыша, находит
верный за 2 попытки, не думая. Признаки плана: верный первый источник на
уровне 5 в первой или второй попытке; пауза перед первым шагом длиннее
обычной; объяснение словами. Если на уровне 5 игроки побеждают только после
многих попыток и объяснить порядок не могут — это kill.

Метрики диагностические. Решение Gate 2 — по наблюдаемому поведению и
kill-критерию.

# Приложение A. Профиль реализации

**Фабрика.** `apps/sprout/`: веб-игра под браузер телефона, TypeScript +
Vite, без фреймворка, экран на HTML/CSS. Токены и шрифт — из `UI Design/`.
Устройство как у `apps/arrow-flip` (`apps/CLAUDE.md`).

Правила шага — порт `step` из `tools/sprout-solver.mjs` без изменений.
Уровни — копия `GAME_LEVELS`; тест сверяет копию с солвером, прогоняет
победные пути солвера через движок игры (каждый побеждает), путь жадной
стратегии на уровнях 3–5 (проигрывает) и проверяет свойства отбора из §6. В
игре — только проверки §5 после шага. Солвера в игре нет, решаемость наперёд
она не считает. `step_lost` из §8 солвер считает по логу после сессии.
