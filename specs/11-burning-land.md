# 1. Граница прототипа

**Что проверяем.** Ставит ли игрок на уровнях 3–5 стены у домов, отдавая
огню кусок поля, а не на клетках, куда огонь пойдёт следующим шагом. И
понимает ли после проигрыша, какой кусок надо было отдать.

**Минимальный цикл.** Поле 8×8 с очагами, домами и травой. Три фигуры хода
в трее и три следующие под ними. Перетаскивание фигуры на поле, поворот
тапом, шаг огня после каждой постановки, точки превью следующего шага огня.
Вокруг цикла — главный экран, экран уровней и попапы (§5, §7.1).

**Не делаем.** Отмену хода, подсказку хода, предупреждение «уже не спасти»,
звёзды, рекорды и цель по спасённым клеткам (число спасённых только
показывается в конце), встречный пал, камни и другие
типы клеток, дома разной ценности, «спасти большинство домов», таймер,
звук, настройки, поля другого размера, бесконечный режим, новую очередь
фигур на каждую попытку.

**Уровней пять.** Два обучающих и три с ловушкой. Уровни собирает
генератор по зерну, отбирает солвер, в игре они заморожены (§6).
Открываются по очереди.

**Почему kill-критерий такой.** Игра держится на решении «что отдать огню».
Самая естественная стратегия новичка — каждым ходом ставить стену так, чтобы
огонь оказался как можно дальше от ближайшего дома. Если она почти всегда
выигрывает, решать ничего не нужно: остаётся реакция на ближайшую угрозу.
Подбором пяти уровней это не вылечить, поэтому критерий меряется на всём
пуле валидных уровней генератора, а не на выбранных. На 2026-09-27 эта
стратегия проходит 66% пула (§6), порог 80% не достигнут. Вторая наивная
стратегия, «закрывай клетки, куда огонь пойдёт дальше», проходит 34%. Она
напрямую противоположна гипотезе, и её доля — главная цифра для
уверенности, что жертва поля нужна. Порог 80% такой же, как у
`specs/09-sprout.md`. Выбран после первых цифр солвера, потому что в идее до
2026-09-27 критерий был неизмеримым: это записанное отступление.

# 2. Цель и основной цикл

Цель игрока — отрезать огонь от всех домов так, чтобы не сгорел ни один
дом. Уровень кончается, как только ни до одного дома огонь больше не
доберётся (решение автора 2026-09-27); число спасённых клеток показывается в
конце.

Первое доступное действие — перетащить фигуру из трея на поле.

```text
Перетащить одну из трёх фигур хода на свободную траву (тап по фигуре — поворот)
→ клетки фигуры становятся стеной, две другие фигуры хода пропадают
→ если огню уже некуда расти — победа (§5)
→ огонь шагает: соседи фронта загораются, старый фронт выгорает
→ проверка поражения и победы (§5)
→ три фигуры следующего хода встают в трей, ниже показываются три после них
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Трава | целая | фигура поставлена → стена; шаг огня рядом с фронтом → огонь | — |
| Стена | стоит | не меняется | не горит, до «заново» не убирается |
| Огонь (фронт) | горит | шаг огня → пепел | горит ровно один шаг |
| Пепел | выгорело | не меняется | не горит, на него ставить нельзя |
| Дом | цел; горит | шаг огня рядом с фронтом → горит → поражение | на дом ставить нельзя; 2–5 на уровень |
| Фигура хода | в трее; поднята; поставлена | тап → поворот на 90° по часовой; перетаскивание → поставлена или вернулась | ровно 3 на ход; неиспользованные пропадают с концом хода |
| Фигура «дальше» | видна | с концом хода переезжает в трей | 3 штуки; не трогается |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Фигуры** (буква — имя в данных уровня, клетки в базовом повороте,
`строка,столбец`):

| Буква | Фигура | Клетки | Поворотов |
|---|---|---|---:|
| `M` | моно | `0,0` | 1 |
| `D` | домино | `0,0 0,1` | 2 |
| `I` | палка 3 | `0,0 0,1 0,2` | 2 |
| `V` | уголок 3 | `0,0 0,1 1,0` | 4 |
| `O` | квадрат | `0,0 0,1 1,0 1,1` | 1 |
| `L` | Г-4 | `0,0 0,1 0,2 1,0` | 4 |
| `S` | зигзаг | `0,0 0,1 1,1 1,2` | 2 |
| `T` | Т-4 | `0,0 0,1 0,2 1,1` | 4 |

Зеркального отражения нет: у `L` и `S` зеркальные формы недоступны.

**Пространство.** Поле — сетка 8×8. Клетка адресуется `row` (0–7, сверху
вниз) и `col` (0–7, слева направо). В тексте спеки клетки названы как на
шахматной доске: столбцы `a`–`h` слева направо, ряды `1`–`8` снизу вверх
(`a1` — левый нижний угол, `row 7, col 0`). Соседи — только по стороне.

```ts
type CellKind = 'grass' | 'wall' | 'fire' | 'ash' | 'house';
type ShapeLetter = 'M' | 'D' | 'I' | 'V' | 'O' | 'L' | 'S' | 'T';

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  cells: CellKind[];          // 64, индекс row * 8 + col
  turn: number;               // 0, 1, 2… — номер хода, тройка фигур = queue[turn*3 .. turn*3+2]
  rotations: [number, number, number]; // поворот каждой фигуры хода, 0–3, сброс в 0 на новом ходу
  rotationsLeft: number;      // поворотов осталось в ходу: 3 на ход на все три фигуры, сброс на новом ходу
  status: 'playing' | 'won' | 'failed';
  failReason: 'house_burned' | null;
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

Горящий дом хранится как `fire`; какой клетка была до этого, знает уровень.

# 4. Ввод и правила

```ts
type Action =
  | { type: 'rotate'; slot: 0 | 1 | 2 }
  | { type: 'place'; slot: 0 | 1 | 2; row: number; col: number } // клетка-якорь = row,col клетки 0,0 повёрнутой фигуры
  | { type: 'restart' }
  | { type: 'open-help' }
  | { type: 'close-help' }
  | { type: 'exit-to-levels' };
```

**Жесты.** Касание фигуры хода и движение пальца больше `8 px` — фигура
поднимается и тащится. Касание и отпускание без движения больше `8 px` —
поворот. Двойного тапа, долгого нажатия, свайпа, кнопки поворота, отмены и
отражения нет. Фигуры «дальше» не реагируют ни на что.

**Перетаскивание.** Поднятая фигура рисуется призраком на поле: центр фигуры
(клетка `centerOffset` = `[floor(maxRow/2), floor(maxCol/2)]`) стоит в
клетке на `1` клетку выше пальца, чтобы палец её не закрывал. Если все клетки
призрака на траве — призрак синий, иначе коралловый. Фигура за пределами
поля — призрака нет.

**Правила хода** — дословно как `playTurn` и `spread` в
`tools/burning-land-solver.mjs`:

1. Фигура ставится только целиком на траву: не на стену, огонь, пепел,
   дом, не за край поля.
2. Клетки фигуры становятся стеной. Две другие фигуры хода пропадают.
3. Если после постановки дома в безопасности — победа, огонь не шагает.
   «Дома в безопасности» — ни до одного дома огонь не доберётся по траве:
   все пути перекрыты стенами, пеплом или краем поля. Сюда входит и случай
   «огню некуда расти» (решение автора 2026-09-27).
4. Шаг огня: каждая трава и каждый дом, соседние по стороне с огнём,
   загораются. Одновременно весь прежний огонь становится пеплом.
5. Если загорелся дом — поражение `house_burned`.
6. Если после шага дома в безопасности — победа.
7. Иначе ход `+1`, в трей встают три следующие фигуры в базовом повороте.
8. Если ни одна из трёх фигур хода ни одним поворотом никуда не помещается,
   ход пропускается сам: огонь делает шаг (4–7). Игрок ничего не нажимает.
9. Поворотов — 3 на ход, общий лимит на три фигуры; неистраченные не
   копятся (решение автора 2026-09-27). Любой поворот одной фигуры
   достижим за ≤ 3 тапа, поэтому лимит не отнимает ни одной постановки, а
   только мешает крутить все три фигуры в поисках; солвер его не учитывает.
10. Случайности во время игры нет. Очередь фигур — поле `shapes` уровня,
   одинаковое в каждой попытке.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Тап по фигуре хода | игра идёт, `rotationsLeft > 0` | `rotations[slot] + 1` по модулю числа поворотов, `rotationsLeft − 1` | фигура поворачивается `150 мс`, счётчик поворотов −1 | нет |
| Тап по фигуре хода | `rotationsLeft = 0` | ничего | фигура покачивается `160 мс`, счётчик поворотов вспыхивает, короткая вибрация | нет |
| Отпустить фигуру | все клетки призрака на траве | правила 2–7 | фигура встаёт стеной, затем шаг огня | да |
| Отпустить фигуру | хоть одна клетка призрака не на траве или за краем | ничего | фигура улетает обратно в трей `200 мс`, короткая вибрация | нет |
| Отпустить фигуру | палец вне поля | ничего | фигура улетает обратно в трей `200 мс` | нет |
| Тап / перетаскивание фигуры «дальше» | всегда | ничего | ничего | нет |
| Тап по полю | всегда | ничего | ничего | нет |
| Ни одна фигура не помещается | после смены хода | правило 8 | надпись «Некуда поставить» `900 мс`, затем шаг огня | да |
| Любое действие во время анимации хода | ввод заблокирован | ничего | ничего | нет |
| «Заново» | всегда | уровень в стартовое состояние, `turn = 0` | поле и очередь как в начале | — |
| «?» | попапа нет | ввод заблокирован | попап «Как играть» | нет |
| «Понятно!» | попап открыт | `howToPlaySeen = true` | игра с того же места | нет |
| «К уровням» | всегда | попытка брошена | экран уровней | — |
| Любое действие на поле или в трее | `status !== 'playing'` или открыт попап | ничего | ничего | нет |

Второй палец во время перетаскивания игнорируется.

# 5. Победа, поражение и переходы

```text
Дано: огонь может добраться хотя бы до одного дома.
Когда: игрок ставит фигуру, после которой ни до одного дома огонь по траве
       не доберётся (огню ещё может быть куда расти).
Тогда: победа сразу, огонь не шагает. Всё, до чего огонь ещё дотянется,
       догорает на экране волной — это отданная часть. Уровень добавляется
       в passed, открывается следующий, попап победы — на уровнях 1–4
       обычный, на уровне 5 финальный.
```

```text
Дано: после постановки огонь может добраться до дома.
Когда: огонь сделал шаг, ни один дом не загорелся, и дома в безопасности.
Тогда: победа (как выше). На практике так не бывает: шаг огня не
       перекрывает путей к домам, — правило остаётся для полноты.
```

```text
Дано: победа.
Тогда: спасено = трава и дома, до которых огонь не доберётся никогда.
       Стены не считаются. Число показывается в попапе, целью не является.
```

```text
Дано: дом соседствует с огнём по стороне.
Когда: огонь сделал шаг.
Тогда: поражение с причиной house_burned. Дом вспыхивает, через 900 мс попап
       «Дом сгорел».
```

```text
Дано: дом соседствует с огнём, спасти его уже нельзя (на дом ставить нельзя).
Когда: ход игрока.
Тогда: игра продолжается молча. Никаких предупреждений и подсветок; дом
       сгорит на ближайшем шаге огня.
```

```text
Дано: ни одна из трёх фигур хода никуда не помещается.
Когда: фигуры хода встали в трей.
Тогда: надпись «Некуда поставить» 900 мс, огонь шагает, дальше как после
       постановки. Это не поражение.
```

Игра не предсказывает проигрыш. Игрок сам видит, что дом сгорел.
«Заново» доступно всегда.

**Порядок после постановки:** клетки → стена → проверить «дома в
безопасности» (победа) → шаг огня → проверить загоревшийся дом
(`house_burned`) → проверить «дома в безопасности» (победа) → следующий ход → проверить «ни одна
фигура не помещается» (правило 8). Если в один шаг загорелся дом и огню
стало некуда расти, причина — `house_burned`.

Коды причин поражения стабильны: `house_burned`.

**Случайности нет.** Поле и очередь фигур заданы уровнем. Для игрока фигуры
выглядят случайными, но после «заново» идут в том же порядке. Скрытой
информации нет, кроме фигур дальше следующего хода: они заданы уровнем
заранее.

**Переходы между экранами** такие же, как в `specs/36-arrow-flip.md`:
главный → уровни → игровой экран. Попап победы: «Следующий уровень»,
«Переиграть», «К уровням». Попап поражения: «Переиграть», «К уровням».
Финальный попап после уровня 5: «Переиграть», «К уровням». Закрытый уровень
на экране уровней коротко покачивается.

# 6. Контент и кривая сложности

Пример данных одного уровня — формат солвера. Строки идут сверху вниз:
`.` трава, `F` огонь, `H` дом. `shapes` — очередь фигур, по три на ход
(20 ходов).

```json
{
  "name": "BL-3-51",
  "rows": ["....F...", ".F......", "........", "..H..H..", "........", "..H.....", "........", "........"],
  "shapes": "ODTVMSISIDSOSLLLLOMTSSLVTTDVSMVSTISSDMSMSVVLODTTSSVVDIVLMVLV"
}
```

**Генератор** (`randomLevel(seed, cfg)` в `tools/burning-land-solver.mjs`):
очаги ставятся на случайную траву где угодно; дома — на случайную траву не
ближе `minDist` по Манхэттену от каждого очага и, при `inner: 1`, не на
крайних рядах и столбцах; очередь фигур — `shapeQueue(seed)`: на каждую
позицию `10%` моно, иначе одна из семи остальных равновероятно. Настройки:

| Уровень | Очагов | Домов | `minDist` | `inner` |
|---:|---:|---:|---:|---:|
| 1 | 1 | 2 | 4 | 1 |
| 2 | 2 | 3 | 4 | 1 |
| 3 | 2 | 3 | 3 | 1 |
| 4 | 3 | 4 | 3 | 1 |
| 5 | 3 | 5 | 3 | 0 |

**Валидный уровень** (`validate`): у огня на старте есть куда расти; ни
один дом не соседствует с огнём; без единой стены хоть один дом горит
(`winsWithoutWalls` — нет); солвер находит победу.

**Уровень с ловушкой** (`isTrapPick`): уровень валиден; обе наивные
стратегии проигрывают; победных первых постановок не меньше 2 и не больше
трети всех (солвер проверяет каждую). Кандидаты печатает
`node tools/burning-land-solver.mjs pick <очагов> <домов> 0 <minDist> <inner> [сколько]`.
Из первых кандидатов по возрастанию зерна уровни выбраны вручную так,
чтобы дома стояли по-разному: у 3 — треугольник, у 4 — столбец, у 5 —
разбросаны по трём сторонам.

**Обучающий уровень** (`tutorialPick`, `pick … tutorial`, взят первый
кандидат): обе наивные стратегии выигрывают, и выигрывает не меньше
половины первых постановок.

**Наивные стратегии** (сравнивают все постановки хода: три фигуры, все
повороты, все позиции; при равенстве берут первую в порядке «слот, поворот,
строка, столбец»):

- `greedyHouse` — **kill-критерий**: максимум расстояния огня до
  ближайшего дома после постановки (расстояние — по траве, в шагах огня),
  затем максимум суммы расстояний до всех домов;
- `greedyFront` — максимум клеток фигуры на клетках, куда огонь пойдёт
  следующим шагом, затем как `greedyHouse`.

Уровни ниже — `GAME_LEVELS` в `tools/burning-land-solver.mjs`. Игра берёт
их оттуда без правки руками. На схемах `▣` — стена, `x` — пепел, `F` —
огонь в конце.

### Уровень 1 — BL-T1, обучающий

Один очаг, два дома. Первые ходы: `S O O`, `M T D`, `S V I`.

```text
8  ·  ·  ·  ·  ·  ·  ·  ·
7  ·  ·  ·  ·  ·  ·  ·  ·
6  ·  H  ·  ·  ·  ·  ·  ·
5  ·  ·  ·  ·  ·  ·  ·  ·
4  ·  ·  ·  ·  ·  ·  ·  ·
3  F  ·  ·  ·  ·  ·  H  ·
2  ·  ·  ·  ·  ·  ·  ·  ·
1  ·  ·  ·  ·  ·  ·  ·  ·
   a  b  c  d  e  f  g  h
```

Схемы конца партии выше нарисованы до правила «дома в безопасности —
победа» (решение автора 2026-09-27): теперь партия кончается раньше, когда
последний дом отрезан, а огонь догорает на экране. Исходы и победные
первые постановки от этого не меняются: если огонь не доберётся ни до
одного дома, раньше он всё равно выгорал бы без поражения. «Спасено у
солвера» — трава и дома вне досягаемости огня в победе, которую нашёл
солвер; это не максимум.

«Случайная игра» — доля побед случайных постановок на 100 прогонах.
Проигрыш почти всегда: исход решают постановки, а не стартовая раскладка.

**Kill-критерий на пуле** (`node tools/burning-land-solver.mjs kill`: первые
100 валидных уровней на каждую настройку уровней 3–5, зёрна с 1):

| Настройка | Валидных | `greedyHouse` | `greedyFront` | Случайная игра |
|---|---:|---:|---:|---:|
| 2 очага, 3 дома | 100 | 80 (80%) | 53 (53%) | 0.6% |
| 3 очага, 4 дома | 100 | 61 (61%) | 22 (22%) | 0.1% |
| 3 очага, 5 домов | 100 | 56 (56%) | 26 (26%) | 0.1% |
| всего | 300 | 197 (66%) | 101 (34%) | 0.2% |

Порог — 80%. Структурно идея его не проходит, но с двумя очагами стоит
ровно на пороге: вся нагрузка гипотезы — на трёх очагах.

Разница между соседними уровнями:

- `1→2` — очагов два, огонь идёт с двух сторон, побеждать приходится,
  отдавая больше половины поля. Ловушки ещё нет.
- `2→3` — появляется ловушка: стена у очагов проигрывает, нужно стоять у
  домов. Выигрывает 7% первых постановок вместо всех.
- `3→4` — три очага, дома одной группой; верная стена стоит в двух
  клетках от домов, а поле отдаётся почти целиком. Выигрывает 2.5% первых
  постановок.
- `4→5` — дома в трёх разных сторонах: за ход закрывается только одна
  группа, нужно выбрать, какую первой. Уровень проверяет гипотезу напрямую.

**Как проверяется решаемость.** Солвер перебирает постановки в глубину
(DFS): все фигуры хода, все повороты, все позиции, одинаковые наборы клеток
один раз. Отсекает постановки, которые не касаются ни одной клетки,
досягаемой огнём (они равны пропуску хода, а пропуск не лучше любой
постановки: лишняя стена огню не помогает), и позиции, где дом уже
соседствует с огнём. Проигранные позиции запоминает. Порядок перебора — по
расстоянию огня до ближайшего дома. Тест прототипа прогоняет победные
линии солвера через движок игры и проверяет каждое свойство отбора.

# 7. Обратная связь и обучение

- **Доступное действие:** три фигуры хода — белые карточки в трее, в углу
  значок поворота. Фигуры «дальше» — мелкие серые, без карточек.
- **Призрак:** при перетаскивании клетки фигуры на поле — синие
  полупрозрачные с пунктиром (можно поставить) или коралловые (нельзя).
- **Запрещённое действие:** по §4. Фигура улетает обратно в трей, короткая
  вибрация.
- **Цена хода:** точки превью — маленькие коралловые точки на каждой
  клетке, куда огонь шагнёт после следующей постановки. Они пересчитываются
  сразу, пока фигура висит призраком над полем: клетки под призраком теряют
  точку, а если призрак запирает огонь, точки гаснут все. Под шапкой — «Ход
  `N`», «Дома `K/K`» и счётчик поворотов «↻ `R`» (3 → 0, на нуле серый,
  значки поворота на фигурах бледнеют).
- **Огонь:** фронт — коралловый тайл с пламенем, пепел — плоская клетка
  без объёма, чуть темнее пустой, с угольками. Стена — синий тайл с кладкой. Дом — жёлтый тайл с
  домиком.
- **Победа — payoff:** стена, отрезавшая последний дом, встаёт; всё, до
  чего огонь ещё дотянулся бы, догорает в пепел волной от фронта (`40 мс`
  на шаг огня), затем волна подсветки бежит по спасённой траве от домов
  наружу, дома подпрыгивают. Попап победы «Дома спасены!», крупно число
  «`X` клеток спасено от огня», ниже «Дома в безопасности на ходу `N`».
- **Поражение:** загоревшийся дом вспыхивает и становится огнём, счётчик
  «Дома» краснеет. Через `900 мс` попап «Дом сгорел».
- **Без текста игрок должен понять:** фигура из трея становится стеной;
  огонь шагает после каждого хода туда, где точки; огонь не проходит сквозь
  стены и пепел; отрезал огонь от всех домов — победа. Что поле можно и
  нужно отдавать, он открывает сам. Текстом это не пишется нигде.

**Обучение — попап «Как играть».** Открывается сам при первом входе в
уровень 1, дальше по кнопке «?». Картинка-пример и четыре правила:

1. Перетащи фигуру на поле — она станет стеной. Тапни фигуру, чтобы
   повернуть.
2. После каждого хода огонь шагает на соседние клетки — туда, где точки.
3. Огонь не проходит через стены и выгоревшие клетки.
4. Отрежь огонь от всех домов. Поворотов — 3 за ход.

Больше подсказка не говорит ничего, в том числе про «отдай часть поля».

На уровне 1 до первой постановки над треем стоит подсказка со значком
пальца: «Перетащи фигуру на поле». После первой постановки она пропадает.
На уровнях 2–5 подсказки нет.

## 7.2. Анимация

Числа — черновые, поправить на показе.

- **Постановка:** фигура из-под пальца «защёлкивается» в клетки `120 мс`,
  `ease-out`, стена чуть проседает (`scale 1.08 → 1`).
- **Шаг огня:** через `150 мс` после постановки. Новые клетки огня
  разгораются из точки превью (`scale 0.3 → 1`, `250 мс`), старый фронт
  одновременно гаснет в пепел (`opacity`/`filter`, `250 мс`).
- **Смена хода:** фигуры «дальше» въезжают в трей (`200 мс`), новый ряд
  «дальше» проявляется (`150 мс`). Точки превью появляются вместе с ним.
- **Ввод** возвращается после смены хода: `120 + 150 + 250 + 200 = 720 мс`
  после отпускания.
- **Поворот:** `150 мс`, `ease-out`.
- **Недопустимое отпускание:** фигура летит в трей `200 мс`.
- **Победа:** оставшийся огонь гаснет (`300 мс`), затем волна
  `filter: brightness(1.2)` с оттенком `--ui-green` по отрезанной траве с
  шагом `40 мс` на клетку по расстоянию от ближайшего дома, дома
  подпрыгивают (`scale 1 → 1.15 → 1`, `250 мс`). Попап через `500 мс` после
  конца.
- **Поражение:** по §5, попап через `900 мс`.
- Анимируются только `transform`, `opacity` и `filter`.
- **`prefers-reduced-motion`:** постановка и шаг огня мгновенные, волна
  победы заменена одной вспышкой. Точки, призрак и пунктир остаются.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=75%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - на пуле генератора greedyHouse проходит меньше 80% валидных уровней (проверка солвером, сейчас 66%)
    - на уровнях 3–5 обе наивные стратегии проигрывают
    - на уровнях 3–5 у победивших доля постановок «на фронт» ниже, чем у проигравших (см. ниже)
    - минимум половина игроков проходит уровень 5 не больше чем за 5 попыток
    - минимум один игрок словами объясняет жертву («это отдам, зато тут закрою»)
  kill:
    - выполняется заранее записанный kill_criterion
    - уровни 3–5 проходятся в основном перебором через «заново», а не планом (см. ниже)
```

Первое валидное действие — первая постановка фигуры на уровне 1. По нему
считаются `first_action_without_help` и `onFirstAction()`.

В лог на каждую постановку пишутся: уровень, номер попытки, номер хода,
слот, буква фигуры, поворот, клетки, сколько клеток фигуры попало на точки
превью, число поворотов перед постановкой, время от смены хода до
постановки, число неудачных отпусканий в этом ходу. Остаётся ли победа
достижимой, игра не считает: солвер восстанавливает это по выгруженному
логу.

- `front_share` — доля клеток фигуры, попавших на точки превью. Высокая
  доля — игрок затыкает фронт, низкая — строит у домов. Сравнивается у
  победных и проигранных попыток на уровнях 3–5.
- `attempts_to_win` — попыток до победы на уровне.
- `turn_lost` — ход, после которого победа стала недостижимой, против хода
  фактического поражения: как долго игрок играет, не зная, что уже
  проиграл.
- `think_time` — пауза перед постановкой против медианы пауз игрока.
- `rotate_count` — поворотов перед постановкой: подбирает ли игрок форму
  под место.
- `saved_on_win` — сколько клеток спасено в победной попытке (растёт ли от
  попытки к попытке: ищет ли игрок меньшую жертву после победы).
- `rotations_out` — доля ходов, где повороты кончились до постановки.

**Как отделить план от перебора.** Перебор: игрок меняет первую
постановку после каждого проигрыша, не думая, и побеждает после многих
попыток; `think_time` не растёт. Признаки плана: на уровне 5 победа за 1–3
попытки; `front_share` в победной попытке заметно ниже, чем в первых;
объяснение словами, какую сторону отдали. Если на уровне 5 игроки побеждают
только после многих попыток и объяснить жертву не могут — это kill.

Метрики диагностические. Решение Gate 2 — по наблюдаемому поведению и
kill-критерию.

# Приложение A. Профиль реализации

**Фабрика.** `apps/burning-land/`: веб-игра под браузер телефона,
TypeScript + Vite, без фреймворка, экран на HTML/CSS, перетаскивание на
Pointer Events. Токены и шрифт — из `UI Design/`. Устройство как у
`apps/arrow-flip` (`apps/CLAUDE.md`).

Старый прототип `stasHrytsko/burning-land` (Phaser + Capacitor) не
фабрика этой спеки. Из него переносятся только поведение перетаскивания и
идея точек превью. Правила берутся из солвера, не из старого `engine/`: там
иная очередь фигур (6 в трее, одна замена за ход) и очаги только у краёв.

Правила хода — порт `playTurn`, `spread`, `nextBurn` и `placementsOf` из
`tools/burning-land-solver.mjs` без изменений. Уровни — копия `GAME_LEVELS`
(поля `rows` и `shapes`); тест сверяет копию с солвером, прогоняет
победные линии солвера через движок игры (каждая побеждает), линии обеих
наивных стратегий на уровнях 3–5 (проигрывают) и проверяет свойства отбора
из §6. В игре — только проверки §5 после хода. Солвера в игре нет,
решаемость наперёд она не считает. `turn_lost` из §8 солвер считает по
логу после сессии.
