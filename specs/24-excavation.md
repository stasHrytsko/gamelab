# 1. Граница прототипа

**Что проверяем.** Останавливается ли игрок, когда логика кончилась, а выход
открыт, и взвешивает ли он риск именно этой плиты: иногда забирает, иногда
копает — в зависимости от того, сколько звёзд уже есть и насколько опасна
лучшая из оставшихся плит.

**Минимальный цикл.** Одна комната-поле 5×5 или 6×6, скрытые ловушки,
число на открытой плите (оно же золото), скрытый выход у края, шкала из трёх
звёзд, кнопка «Забрать». Вокруг цикла — главный экран, экран уровней и попапы (§5, §7.1).

**Не делаем.** Несколько комнат в уровне, ключи и закрытые комнаты,
постоянные и временные артефакты, кошелёк между уровнями, трату золота,
кампанию больше пяти уровней, особые текстовые подсказки, флажки и ручные
метки, автораскрытие пустых областей, отмену хода, подсказку «здесь
безопасно», предупреждение «безопасных плит больше нет», таймер, звук,
настройки и бесконечный режим. Всё это есть в полном дизайне
(`stasHrytsko/raskop`, `concept.txt`) и ждёт ответа на вопрос прототипа.

**Уровней пять.** Открываются по очереди. У каждого — 20 заранее собранных
раскладок; попытка номер `k` на уровне идёт на раскладке `k mod 20` (§6).

**Откуда эта версия.** Backlog-версия идеи проверяла «логик обгоняет
случайного игрока на 20%». Солвер ответил сразу: по подсказкам уровни 2–5
проходятся в 100% попыток, случайным тапом — в 1–8%. Это свойство «Сапёра»,
а не риск идеи, поэтому гипотеза и kill-критерий переписаны на то, что
действительно не проверено: решение «забрать или рискнуть». Полный разбор —
в `ideas/approved/24-excavation.md`, раздел «Финализация».

**Почему kill-критерий такой.** Вся игра держится на моменте выбора: числа
больше не ведут, выход найден и открыт. Если игроки в этом моменте ведут себя
одинаково, выбора нет — есть «Сапёр» с кнопкой выхода, которую либо жмут
всегда, либо не жмут никогда. Уровни при этом не виноваты: баланс заранее
выставлен ботами так, что «уходи на второй звезде» и «копай до третьей» дают
почти одно и то же число звёзд за попытку (§6). Значит, одинаковое поведение
говорит о том, что ставка не ощущается, а не о перекосе цифр.

# 2. Цель и основной цикл

Цель игрока — найти выход и выйти через него с золотом не меньше порога
первой звезды; чем больше золота, тем больше звёзд (до трёх).

Первое доступное действие — тапнуть закрытую плиту рядом со входом.

```text
Тапнуть закрытую плиту
→ безопасная: открывается, показывает число N (ловушек среди 8 соседей),
  золото попытки += N
→ шкала звёзд обновляется; если это выход — он найден
→ когда выход найден и есть первая звезда, активна «Забрать»
→ игрок решает: копать дальше или «Забрать»
→ проверки по §5
```

Попытка заканчивается по §5: «Забрать», открыты все безопасные плиты или
открыта ловушка.

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Плита | закрыта; открыта; вход; раскрыта после конца | закрытая открывается тапом; в конце попытки все закрытые раскрываются | открытую нельзя закрыть; вход открыт с начала |
| Безопасная плита | — | открытием даёт золото = своё число | число 0–5; число выше 5 генератор не создаёт |
| Ловушка | закрыта; сработала; раскрыта после конца | тап по закрытой — срабатывает | число ловушек в комнате задано уровнем и показано игроку |
| Вход | открыт | не меняется | ровно один на комнату, его число 0, золота не даёт |
| Выход | скрыт (выглядит как любая закрытая плита); найден | найден, когда игрок открывает его плиту | ровно один на комнату; безопасная плита у края; даёт золото = своё число, как любая; не ловушка и не вход |
| Золото попытки | 0…сумма чисел комнаты | растёт при открытии; сгорает до 0 при ловушке | не тратится; между попытками не переносится |
| Звезда | не получена; получена | получена, когда золото ≥ её порога | три порога на уровень, по возрастанию |
| Уровень | закрыт; открыт; пройден | открывается проходом предыдущего; первый открыт всегда | пройден = хотя бы раз вышел через выход с ≥1★ |

**Пространство.** Комната — прямоугольная сетка `rows×cols` (5×5 или 6×6).
Плита адресуется `row` (сверху вниз, с 0) и `col` (слева направо, с 0).
Соседи плиты — до восьми плит по сторонам и диагоналям. В данных уровня
раскладка хранится строками: `*` — ловушка, `.` — безопасная плита, `E` —
вход, `X` — выход. Числа не хранятся — они выводятся из раскладки. Край
комнаты — плиты первой и последней строки и первого и последнего столбца.

```ts
type Tile = { trap: boolean; clue: number; open: boolean };   // clue = ловушек среди соседей; у ловушки -1

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  layout: number;                     // 0..19, индекс раскладки уровня
  tiles: Tile[][];
  gold: number;
  exitFound: boolean;                 // плита выхода открыта
  stars: 0 | 1 | 2 | 3;               // выводится из gold и порогов уровня
  status: 'playing' | 'won' | 'failed';
  failReason: 'trap' | null;
  lostGold: number;                   // сколько сгорело на ловушке, для попапа
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  best: Record<number, 0 | 1 | 2 | 3>;   // лучшие звёзды на уровне
  attempts: Record<number, number>;      // сколько попыток начато на уровне
  howToPlaySeen: boolean;
  clueTipSeen: boolean;                  // обучающая подсветка соседей уже показана (§7)
};
```

# 4. Ввод и правила

```ts
type Action =
  | { type: 'tap-tile'; row: number; col: number }
  | { type: 'hold-tile'; row: number; col: number }     // удержание открытой плиты с числом
  | { type: 'take' }                    // кнопка «Забрать»
  | { type: 'restart' }
  | { type: 'open-help' }
  | { type: 'close-help' }
  | { type: 'exit-to-levels' };
```

Тап и удержание. Флажков и меток, перетаскивания, свайпа и отмены хода нет.

**Удержание открытой плиты с числом** (решение автора 2026-09-27, после
показа): держишь палец 350 мс — закрытые соседи этой плиты подсвечиваются
коралловым, и **насыщенность — точная вероятность ловушки** под каждой: чем
ярче, тем вероятнее. Сосед с вероятностью 0 не подсвечивается. Вероятность
считается по всем открытым числам сразу и по общему числу ловушек — тем же
перебором, что у солвера (`trapProbabilities`). Процентов на экране нет,
только насыщенность: игра подсказывает, а не называет. Флажков нет (решение
автора: «скучно»).

**Число — одно на плите.** Под плитой бывает только три вещи: ловушка,
пусто (0) или число `N` от 1 до 5. Открытая плита с числом `N` показывает
только `N`: столько ловушек среди её соседей и столько золота она принесла.
Отдельных плит «с монетой» или «с числом без золота» нет. Открытая плита с
`0` пустая и золота не даёт. Выход — это одна из безопасных плит: у него
тоже есть число, и оно тоже приносит золото.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Тап по плите | закрыта, безопасна, число `N ≥ 1` | `open = true`, `gold += N`, звёзды пересчитаны, дальше по §5 | плита переворачивается, `+N` летит к счётчику, шкала растёт | да |
| Тап по плите | закрыта, это выход | `open = true`, `exitFound = true`, `gold += N`, дальше по §5 | плита переворачивается дверью, коротко светится зелёным `600 мс`, `+N` летит к счётчику | да |
| Тап по плите | закрыта, безопасна, число 0 | `open = true`, золото не меняется, дальше по §5 | плита переворачивается пустой | да |
| Тап по плите | закрыта, ловушка | `status = 'failed'`, `failReason = 'trap'`, `lostGold = gold`, `gold = 0` | ловушка срабатывает, золото сгорает до нуля, комната раскрывается, попап поражения (§5) | да |
| Тап по плите | открыта, вход или найденный выход | ничего | ничего | нет |
| Удержание 350 мс | плита открыта, число `N ≥ 1` (в т. ч. найденный выход; у входа число всегда 0) | ничего | закрытые соседи с вероятностью ловушки > 0 заливаются коралловым, насыщенность = вероятность; плашка «N ловушек · чем ярче плита, тем вероятнее» | нет |
| Отпустить после удержания | было удержание | ничего | подсветка и плашка гаснут | нет |
| «Забрать» | `exitFound` и `gold ≥` порога 1★ | `status = 'won'`, дальше по §5 | счётчик золота уходит в звёзды, комната раскрывается, попап победы | — |
| «Забрать» | выход не найден | ничего | кнопка неактивна: серая, подпись «Найди выход», при тапе коротко покачивается | нет |
| «Забрать» | выход найден, `gold <` порога 1★ | ничего | кнопка неактивна: серая, подпись «Выход с 18», при тапе коротко покачивается | нет |
| «Заново» | `status === 'playing'` | попытка брошена без подтверждения, новая попытка на следующей раскладке | новое поле, золото 0 | — |
| «?» | попапа нет | ввод поля заблокирован | попап «Как играть» | нет |
| «Понятно!» | попап открыт | `howToPlaySeen = true` | игра с того же места | нет |
| «К уровням» | всегда | попытка брошена | экран уровней | — |
| Любое действие с полем или «Забрать» | `status !== 'playing'` или открыт попап | ничего | ничего | нет |

**Что игра говорит, а что нет.** Без удержания — ничего сверх чисел: не
сообщает, остались ли безопасные плиты, не подсвечивает их. С удержанием —
показывает вероятность ловушки у соседей удерживаемого числа. Это сознательно
меняет исходное правило (решение автора 2026-09-27): раньше «логика
кончилась» игрок решал сам, теперь это видно — у всех чисел на границе
соседи подсвечены. Что меняется для проверки — в §8.

# 5. Победа, поражение и переходы

```text
Дано: exitFound, gold ≥ порога 1★, status = 'playing'.
Когда: игрок нажимает «Забрать».
Тогда: попытка заканчивается победой с числом звёзд по золоту; уровень
       добавляется в passed; best = max(best, звёзды); открывается следующий
       уровень.
```

```text
Дано: закрытыми остались только ловушки.
Когда: завершена обработка тапа, открывшего последнюю безопасную плиту.
Тогда: попытка заканчивается победой так же, как по «Забрать». Выход к
       этому моменту найден (он безопасная плита), а все валидные раскладки
       дают на полной расчистке не меньше порога 3★ (§6), так что это всегда
       три звезды.
```

```text
Дано: status = 'playing'.
Когда: игрок тапает закрытую ловушку.
Тогда: попытка заканчивается поражением с причиной trap; золото попытки
       сгорает; звёзды за эту попытку — 0; best и passed не меняются.
```

**Порядок проверок после тапа по плите:** открыть плиту → если ловушка —
поражение `trap`, стоп → прибавить золото → если это выход — `exitFound` →
пересчитать звёзды и активность «Забрать» → если закрытых безопасных плит не осталось — победа → вернуть ввод.

Код причины поражения один: `trap`. Брошенная попытка («Заново», «К уровням»)
поражением не считается и в лог пишется с исходом `abandon`.

**Смена раскладки.** Каждая новая попытка на уровне (после победы, поражения,
«Заново» или входа с экрана уровней) берёт раскладку `attempts[level] mod 20`
и затем увеличивает `attempts[level]` на 1. Первая попытка — раскладка 0.
Последовательность раскладок одна и та же у всех игроков. Повторить только
что проигранную раскладку нельзя — иначе вторая попытка проверяет память, а
не решение.

**Случайности во время игры нет.** Ловушки, числа, вход, выход и пороги звёзд
заданы раскладкой заранее. «Первый тап всегда безопасен» из полного дизайна
заменён открытым входом с числом 0: все его соседи гарантированно безопасны,
и ничего не переносится под пальцем игрока. Скрытое — только положение
ловушек и выхода; первое сужают видимые числа, второе игрок ищет у края.

**Переходы между экранами** — как в `apps/CLAUDE.md`, §2: главный → уровни →
игровой. Попап победы: «Следующий уровень», «Переиграть», «К уровням».
Попап поражения: «Переиграть», «К уровням». Финальный попап после победы на
уровне 5: «Переиграть», «К уровням». «Переиграть» — новая попытка на
следующей раскладке. Закрытый уровень на экране уровней при тапе
покачивается.

# 6. Контент и кривая сложности

Уровни генерируются по зерну и замораживаются в `levels.json`
(`node tools/excavation-solver.mjs json`). Пример одной раскладки уровня 5:

```json
{
  "id": 5, "rows": 6, "cols": 6, "traps": 9, "stars": [18, 26, 36],
  "layouts": [
    { "seed": 5035, "map": [".*...*", "X...*.", "...*..", "*...**", "....*.", "*.E..."] }
  ]
}
```

**Правило генерации** (`tools/excavation-solver.mjs`, `generateRoom`):

1. Ловушки ставятся равномерно генератором `mulberry32(seed)`.
2. Раскладка отбрасывается, если у какой-то безопасной плиты число больше 5.
3. Вход — нулевая плита в самом нижнем ряду, где она есть; при равенстве —
   ближайшая к центру ряда. Нет нулевой плиты — раскладка отбрасывается.
4. Выход — безопасная плита у края, которую одна логика открывает без
   единой догадки (см. валидность), не вход; из таких — самая дальняя от входа
   по сумме разниц строк и столбцов, при равенстве — с меньшим индексом
   `row·cols + col`. Нет такой или она ближе 3 к входу — раскладка
   отбрасывается.
5. Кандидаты берутся с зерна `id·1000` подряд; в уровень идут первые 20,
   прошедшие проверку валидности.

**Валидность раскладки** (проверяет точный солвер, открывающий только
плиты с вероятностью ловушки 0 при известном числе ловушек):

- уровень 1 — одна логика открывает комнату целиком;
- уровни 2–5 — одна логика останавливается, набрав золото внутри «полосы»:
  не меньше порога 1★ и меньше порога 2★. То есть первая звезда всегда
  достижима без риска, а вторая — никогда;
- сумма чисел комнаты не меньше порога 3★;
- выход достижим одной логикой (правило 4). Без этого условия выход лежал бы
  в зоне, куда логика не доводит, в ~58% случаев, и игрок рисковал бы не ради
  звезды, а просто чтобы уйти — это давление, а не жадность, и оно мешает
  kill-критерию.

**Уровни.** Цифры ботов — на пуле из 200 валидных раскладок каждого уровня
(`node tools/excavation-solver.mjs report pool` и `stops`). «Звёзд за
попытку» — среднее, поражение = 0.

| Ур. | Поле | Ловушек | Пороги ★ | Золото без риска | В комнате всего, ср. | Случайный тап: проходит | «Уходи, как кончилась логика» | «Копай до 2★» | «Копай до 3★» | Риск лучшей плиты в стопе на 1★ / 2★ |
|---:|---|---:|---|---|---:|---:|---:|---:|---:|---|
| 1 | 5×5 | 4 (16%) | 6 / 10 / 14 | вся комната | 20,1 | 11% | 3,00★ | 3,00★ | 3,00★ | стопов нет |
| 2 | 5×5 | 5 (20%) | 8 / 14 / 19 | 8–13 | 24,3 | 8% | 1,00★ | 1,84★ | 1,73★ | 18% / 35% |
| 3 | 6×6 | 7 (19%) | 14 / 22 / 30 | 14–21 | 36,6 | 3% | 1,00★ | 2,31★ | 2,28★ | 12% / 20% |
| 4 | 6×6 | 8 (22%) | 16 / 24 / 33 | 16–23 | 39,9 | 1% | 1,00★ | 2,05★ | 2,01★ | 14% / 24% |
| 5 | 6×6 | 9 (25%) | 18 / 26 / 36 | 18–25 | 42,1 | 1% | 1,00★ | 1,89★ | 1,91★ | 18% / 26% |

«Стоп» — момент, когда безопасных по логике плит нет. Выход к первому стопу
всегда уже найден: логика доводит до него по построению. Боты «копай»
открывают плиту с наименьшей точной вероятностью ловушки — это потолок; живой
игрок угадывает хуже.

| Ур. | Новый навык или решение | Главное давление | Ожидаемый сложный момент |
|---:|---|---|---|
| 1 | число = ловушки рядом = золото; открывать по числам; найти выход | почти нет, вся комната решается логикой | первый вывод «эта плита точно безопасна» |
| 2 | логика кончилась — появляется «Забрать» как решение | первая догадка, риск в стопе на 1★ ~18% | «у меня звезда, зачем рисковать?» |
| 3 | большая комната, после догадки логика снова ведёт | ставка крупнее: в комнате ~37 золота, а без риска — 14–21 | вторая догадка подряд |
| 4 | стоп на 2★ бывает в трети попыток | плотность 22%, риск в стопе на 2★ ~24% | отказаться от третьей звезды |
| 5 | всё вместе, центральная проверка | плотность 25%, риск в стопе на 2★ ~26%, «до 2★» ≈ «до 3★» по звёздам | тот самый выбор из kill-критерия |

Разница между соседними уровнями:

- `1→2` — логика впервые кончается раньше комнаты: игрок впервые видит,
  что безопасных ходов нет, и впервые выбирает между «Забрать» и догадкой.
- `2→3` — поле 6×6 и золота в комнате в полтора раза больше: остаток после
  первой звезды стал заметно дороже, и догадка чаще открывает новую цепочку
  логики.
- `3→4` — ловушек 8 вместо 7: стоп на второй звезде случается вдвое чаще
  (35% попыток против 18%), а риск в нём выше (24% против 20%).
- `4→5` — плотность 25%: риск в стопе на 2★ ~26%, и боты «до 2★» и «до 3★»
  сравниваются (1,89 и 1,91 звезды) — выбор на второй звезде становится
  честным пари.

**Проверки уровней** (в тестах приложения, на замороженных раскладках):

- каждая раскладка валидна по правилам выше; вход — нулевая плита; выход —
  безопасная плита у края не ближе 3 к входу; ловушек ровно столько, сколько
  в уровне;
- на уровне 1 логика открывает комнату целиком, на уровнях 2–5 —
  останавливается внутри полосы;
- случайный бот проходит уровни 2–5 реже, чем в 25% попыток, логический — в
  100% (закрытый вопрос backlog-версии);
- на уровнях 3–5 боты «копай до 2★» и «копай до 3★» расходятся не больше чем
  на 0,3 звезды за попытку на пуле из 200 раскладок — баланс, при котором
  kill-критерий судит идею, а не уровни.

# 7. Обратная связь и обучение

- **Тема «Гробница»** — тёмная (`data-theme="tomb"`, токены в
  `UI Design/design-tokens.css`), одобрена автором 2026-09-27. Все состояния
  плиты — `UI Design/prototypes/excavation/tiles.png`.
- **Доступное действие:** закрытая плита — объёмный тайл `--ui-stone` с
  трещинами («камень»); открытая — плоская ячейка `--ui-surface-muted`.
  Отличаются формой (объём или плоскость), не только цветом.
- **Число и золото на плите** (решение автора 2026-09-27): крупная цифра
  своего цвета — ловушки рядом; чем больше, тем «горячее», как в «Сапёре»:
  1 — синий `--ui-clue-1`, 2 — зелёный, 3 — коралловый, 4 — фиолетовый, 5 —
  розовый (`--ui-clue-2..5`). Под цифрой — ряд из стольких же монеток
  `--ui-yellow` (7 px, зазор 2 px; при плите меньше 44 px — 5 px): «2» и две
  монетки, «5» и пять. Одинаковое количество говорит «это одно и то же
  число». Пустая плита (0) — без цифры и монеток.
- **Вход и выход — одна квадратная дверь, зеркальная стрелка** (решение
  автора, переделано после показа): вход — квадратная рамка со стрелкой,
  входящей в неё справа; выход — та же рамка зеркально, стрелка выходит из
  неё влево. Общая форма роднит пару как «одна и та же дверь», направление
  стрелки отличает их без чтения текста. Оба `--ui-text` (не `--ui-clue-2` /
  `--ui-green`: этот зелёный уже занят числом 2, совпадение цвета с плитой
  путало). Вход виден с начала на плоской ячейке. Выход до находки
  неотличим от закрытой плиты. Найденный выход — плоская ячейка с рамкой
  `--ui-text` и значком двери; его цифра — в левом верхнем углу (14 px)
  своего цвета, монетки — внизу, как у обычной плиты.
- **Удержание** (решение автора 2026-09-27): держишь открытую плиту с
  числом 350 мс — закрытые соседи заливаются `--ui-coral` с насыщенностью по
  вероятности ловушки (заливка 15–85 %, обводка 35–100 %; значок трещин
  прячется, чтобы цвет читался), сама плита получает лёгкое внутреннее
  кольцо, над полем плашка «N ловушек · чем ярче плита, тем вероятнее».
  Соседи с вероятностью 0 остаются обычными камнями. Отпустил — всё гаснет,
  ход не тратится. Скриншот — `UI Design/prototypes/excavation/hold-peek.png`.
- **Обучающая подсветка соседей** (решение автора 2026-09-27). На уровне 1,
  пока `clueTipSeen = false`: когда открывается первая плита с числом `N ≥ 1`,
  её закрытые соседи на `1500 мс` обводятся рамкой `--ui-coral`, а над полем —
  плашка «N ловушки среди этих плит · +N золота». Ввод не блокируется; после
  показа `clueTipSeen = true`, больше не повторяется.
- **Цена хода:** счётчик золота попытки и шкала звёзд. Шкала — дорожка 8 px,
  заливка `--ui-yellow`, на порогах — три круглых значка 28 px поверх
  дорожки, со своим фоном и рамкой, чтобы не сливаться с полосой; под значком
  — число порога. Полученная звезда — жёлтый круг с тёмной звездой; следующая
  — жёлтая рамка; дальняя — серая рамка. Число ловушек в комнате — отдельная
  карточка со значком шипов.
- **Запрещённое действие:** «Забрать», пока выход не найден, — серая,
  подпись «Найди выход»; выход найден, но нет первой звезды — серая, подпись
  «Выход с N». При тапе покачивается `300 мс`. Тап по открытой плите — ничего.
- **Строка подсказки над кнопкой** (одна фраза, по состоянию, по порядку
  проверки): выход не найден — «Найди выход — он где-то у края»; нет 1★ —
  «Набери N золота, чтобы выйти»; от 1★ до 3★ — «Выйти сейчас — или копать
  ради следующей звезды»; на 3★ — «Все звёзды! Забирай». Строка не зависит от
  того, остались ли безопасные плиты.
- **Открытие плиты:** переворот `150 мс`, `+N` летит к счётчику `400 мс`.
  Ввод не блокируется.
- **Победа:** «Забрать» → счётчик золота перетекает в шкалу, полученные
  звёзды по очереди подпрыгивают (`150 мс` каждая) → комната раскрывается
  волной `300 мс`: ловушки — тайл `--ui-coral` со значком шипов, оставшиеся
  безопасные плиты — бледные числа (38% непрозрачности) → через `900 мс` после
  «Забрать» попап победы: звёзды, «Вынесено 23», «Осталось в комнате 19».
- **Поражение:** сработавшая ловушка — тайл `--ui-coral` с шипами,
  покачивание `300 мс`; счётчик золота сгорает до 0 за `600 мс`; комната
  раскрывается так же, как при победе → через `900 мс` попап: красный ✕,
  «Ловушка!», «Сгорело 23 золота».
- **Payoff:** момент «Забрать» — золото уходит в звёзды, а раскрытая комната
  тут же показывает, что было под оставшимися плитами. Одинаково крупно
  отыгрывается и «спас», и «сгорело».
- **Без текста игрок должен понять:** число на плите растёт у ловушек; число
  прибавляется к золоту; выйти можно только через найденный выход; кнопка
  загорается, когда есть и выход, и первая звезда.

**Максимум в «?»** — четыре правила ниже, без стратегии и без подсказки, где
безопасно.

**Онбординг — попап «Как играть».** Открывается сам при первом входе в
уровень 1, дальше — по «?». Картинка-пример: плита «2» с двумя монетками и
две ловушки среди её соседей.

1. Тапни любую закрытую плиту. Цифра — сколько ловушек среди 8 соседних плит.
2. Монетки под цифрой — золото с плиты, их столько же. Пустая плита — 0.
3. Найди выход — он спрятан у края. С выходом и первой звездой можно
   «Забрать» и пройти уровень. За второй и третьей звездой — копай дальше.
4. Ловушка сжигает всё золото попытки. Следующая попытка — новая комната.

## 7.1. Экран — как выглядит поле

![Игровой экран](../UI%20Design/prototypes/excavation/game-screen.png)

Скетч — `UI Design/prototypes/excavation/game-screen.png` (исходник
`mockup.html`, 390×664): уровень 5, раскладка seed 5035 после всех
гарантированно безопасных плит. Выход найден (левый край, второй ряд), золото
23, первая звезда (18) есть, до второй (26) не хватает трёх, «Забрать 23»
активна — момент главного решения. Все состояния плиты — `tiles.png`.

**Игровой экран обязан помещаться целиком без прокрутки** на экранах от
360×560 до 430×932. Сверху вниз:

1. **Шапка, 44 px:** слева «к уровням», по центру «Уровень N», справа «?» и
   «заново».
2. **HUD, ~100 px:** слева карточка «золото попытки» — монета, число и шкала
   с тремя значками-звёздами на порогах; справа карточка «Ловушек N» со
   значком шипов.
3. **Поле — главный объект, всё оставшееся место.** Размер плиты считается
   от свободного места: 36–60 px, зазор 5 px.
4. **Низ, в зоне большого пальца:** строка подсказки (13 px) и кнопка
   «Забрать N» — пилюля 60 px на всю ширину, зелёная и со звездой, когда
   активна; серая с подписью «Найди выход» или «Выход с N», когда нет.

Почему так: поле — место решения, поэтому крупно и в центре; «Забрать» —
второе главное действие, оно внизу под большим пальцем и всегда видно, чтобы
выбор «копать или уйти» был в одном движении. Шкала звёзд над полем — цена
решения читается до тапа.

За секунду читаются: сколько золота и до какой звезды, сколько ловушек,
какие плиты открыты. Payoff — на поле и в HUD в момент «Забрать» или
ловушки.

**Второй канал к цвету.** Закрытая и открытая плита различаются объёмом;
ловушка — значком шипов; число читается как цифра и как число монеток, цвет
лишь добавляет «температуру»; вход и выход — одна дверь с зеркальной
стрелкой, а не цвет (оба `--ui-text`, отдельно от палитры чисел); звёзды —
формой значка (заливка или рамка) и подписью порога;
активность «Забрать» — подписью («Забрать 23», «Найди выход», «Выход с 18»),
не только цветом.

**Главный экран — арт автора** (добавлен после показа,
`UI Design/prototypes/excavation/assets/home-screen.png`): полноэкранная
иллюстрация — название, поле с монетками и цифрами, лопата, самоцветы;
нарисованную в арте кнопку обрезали (`home-art.webp`), под артом настоящая
«Играть» — жёлтая пилюля 72 px, как у соседних игр. Низ и края арта
растворяются в его размытой копии, паттерн — как у `apps/sprout`.
На игровом экране попапы не размывают поле и прижаты к низу: раскрытая
комната — payoff, её должно быть видно.

Стиль PuzzleKit в теме «Гробница»: новые только нейтральные цвета темы,
`--ui-stone` и `--ui-clue-1..5` (одобрены автором 2026-09-27, занесены в
токены); радиусы и форма теней кита. Главный экран, экран
уровней и попапы — по `apps/CLAUDE.md`, §2; на карточке уровня — лучшие звёзды
и строка «6×6 · 9 ловушек».

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=70%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - логический бот проходит уровни 2–5 в 100% попыток, случайный — реже 25% (тест уровней)
    - на уровнях 3–5 боты «до 2★» и «до 3★» расходятся не больше чем на 0,3 звезды (тест уровней)
    - минимум половина игроков хотя бы раз нажимает «Забрать» в стопе, где можно было копать, и хотя бы раз копает в стопе после 1★
    - минимум трое игроков объясняют выбор в стопе риском конкретной плиты
  kill:
    - выполняется заранее записанный kill_criterion
```

**Первое валидное действие** — первая открытая плита (тап по закрытой
плите). По нему считается `first_action_without_help` и вызывается
`onFirstAction()`.

**Лог попытки:** уровень, seed раскладки, последовательность тапов
(`row`, `col`, время), золото после каждого тапа, исход (`take`, `cleared`,
`trap`, `abandon`) и золото на выходе. Солвера в игре нет — стопы
восстанавливаются после плейтеста повтором лога через
`tools/excavation-solver.mjs`: для каждого тапа считается, была ли в этот
момент плита с вероятностью ловушки 0.

- **Стоп** — момент, когда выход открыт (найден и `gold ≥` 1★), звёзд
  меньше трёх и плит с вероятностью ловушки 0 нет. Исход стопа: «забрал» (следующее
  действие — «Забрать») или «копал» (следующее — тап по плите).
  Kill-критерий считается по стопам уровней 3–5 всех игроков вместе.
- `take_share_1`, `take_share_2` — доля «забрал» в стопах на 1★ и на 2★.
- `risk_taken` — вероятность ловушки у плиты, которую игрок открыл в стопе,
  против лучшей доступной: читает ли игрок числа, когда рискует.
- `careless_taps` — тапы по плите с риском > 0, когда была плита с риском 0:
  логика не понята, а не жадность.
- `peek_rate` — доля стопов, перед которыми было хотя бы одно удержание
  (§4, §7): пользуются ли игроки подсветкой вероятностей в момент решения.
- **Удержание меняет смысл метрик** (решение автора 2026-09-27). С ним
  игрок видит и то, что логика кончилась, и риск лучшей плиты. Решение
  «забрать или копать» становится ставкой на известный риск — ровно то, что
  проверяет kill-критерий, только без шума от ошибок счёта. Баланс звёзд не
  пересчитывается: боты в §6 и так играли с точными вероятностями.
  `careless_taps` при удержании перед тапом почти всегда 0; считать её
  отдельно для попыток с удержанием и без.

Метрики диагностические. Решение Gate 2 — по наблюдаемому поведению и
kill-критерию. Много `careless_taps` при срабатывании kill-критерия — сначала
чинится обучение чтению чисел, потом судится идея.

# Приложение A. Профиль реализации

**Фабрика.** `apps/excavation/` (папка по slug, собрана 2026-09-27): веб-игра
под браузер телефона, TypeScript + Vite, без фреймворка, экран на HTML/CSS — по
`apps/CLAUDE.md`. Тема ставится атрибутом `data-theme="tomb"` на `<html>` и
`<body>` (в однофайловом артефакте корень занят просмотрщиком). Токены и шрифт — из `UI Design/`. Ключ прогресса —
`excavation:progress:v1`.

**Уровни.** `src/levels/levels.json` — вывод
`node tools/excavation-solver.mjs json`, в репозитории лежит замороженная
копия. Движок читает раскладку строками `*` / `.` / `E` / `X` и сам выводит
числа.

**Вероятности в игре.** `src/engine/probability.ts` — порт
`trapProbabilities` солвера для удержания (§4); тест сверяет его с
солвером на каждом шаге логики. Это исключение из правила `apps/CLAUDE.md`
«солвера в игре нет» — решение автора 2026-09-27. Остальной солвер (боты,
генератор, «есть ли безопасная плита») в игру не попадает.

**Солвер** — `tools/excavation-solver.mjs`: генератор по зерну, точный
подсчёт вероятности ловушки при известном их числе (перебор границы с весом
`C(остаток, ловушек − f)`), боты и отчёты (`report`, `report pool`, `stops`,
`layouts N`, `json`). Используется для подбора уровней, тестов уровней и
разбора логов плейтеста. В игру попадает только подсчёт вероятностей
(см. выше); сама игра не проверяет, остались ли безопасные плиты.

**Источник полного дизайна** — репозиторий `stasHrytsko/raskop`
(`concept.txt` и реализация кампании). Прототип из него ничего не
переиспользует в коде: там другие правила золота (номинал 1–5), первый тап с
переносом ловушки и несколько комнат.
