# 1. Граница прототипа

**Что проверяем.** Делает ли игрок на уровнях 3–5 setup-ход, то есть
запускает блок, который за край не уйдёт, но своим проездом повернёт соседей.
И делает ли он это осознанно, а не находит перебором через «заново».

**Минимальный цикл.** Поле 4×4 с блоками-стрелками, тап по блоку, движение
до препятствия или за край, поворот задетых блоков, счётчик ходов с лимитом.
Вокруг цикла главный экран, экран уровней и три попапа (§5, §7.1).

**Не делаем.** Отмену хода, подсказку решения, предупреждение «уровень уже
не пройти», звёзды, очки, таймер, звук, настройки, блоки других типов (стены,
двойные стрелки, неповорачиваемые), поля больше 4×4 и бесконечный режим.

**Уровней пять.** Два обучающих без ловушек и три с ловушкой (решение автора
2026-09-26). Открываются по очереди.

**Почему kill-критерий такой.** Отличие от обычной block-exit головоломки
только одно: ход, сделанный ради поворота соседей. Если уровни проходятся
одними выходами, поворот — декорация, и подбором уровней это не лечится.
Солвер гарантирует, что на уровнях 3–5 жадная стратегия не проходит (§6),
значит структурно критерий не выполнен. Проверять надо игроков. Поля
маленькие (39–469 состояний), и уровень можно пройти перебором: проиграл,
нажал «заново», попробовал другой первый ход. Такой проход kill-критерий не
опровергает, поэтому §8 отделяет осознанный setup-ход от найденного
перебором.

# 2. Цель и основной цикл

Цель игрока — вывести все блоки за край поля, не превысив лимит ходов.

Первое доступное действие — тапнуть блок.

```text
Тапнуть блок
→ блок едет по стрелке до соседнего блока или за край поля
→ все блоки, которых он коснулся гранью, поворачиваются на 90° по часовой
→ счётчик ходов +1
→ проверка победы и поражения по §5
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Блок | на поле с направлением ↑ → ↓ ←; ушёл за край | тап: едет и либо остаётся на новой клетке, либо уходит; задевший его чужой проезд поворачивает стрелку на 90° по часовой | одна клетка — не больше одного блока; ушедший блок не возвращается; от собственного проезда блок не поворачивается |
| Счётчик ходов | 0…лимит | +1 за каждый допустимый ход | лимит задан уровнем и не меняется |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Пространство.** Поле — сетка 4×4. Клетка адресуется `row` (0–3, сверху
вниз) и `col` (0–3, слева направо). Направления: `^` вверх, `>` вправо, `v`
вниз, `<` влево. Поворот по часовой: `^ → > → v → < → ^`. Блок адресуется
`id` — строкой `'0'`…`'6'`, игроку номер не показывается.

```ts
type Dir = '^' | '>' | 'v' | '<';
type Block = { id: string; row: number; col: number; dir: Dir };

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  blocks: Block[];          // только блоки на поле
  moves: number;            // сделано допустимых ходов
  moveLimit: number;        // из уровня
  lastTouched: string[];    // кого повернул последний ход — для жёлтой отметки
  status: 'playing' | 'won' | 'failed';
  failReason: 'moves_exhausted' | 'no_moves' | null;
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

# 4. Ввод и правила

```ts
type Action =
  | { type: 'tap-block'; id: string }
  | { type: 'restart' }
  | { type: 'open-help' }
  | { type: 'close-help' }
  | { type: 'exit-to-levels' };
```

Ввод только тапом. Свайпа, перетаскивания, долгого нажатия, отмены хода и
выбора направления нет: блок всегда едет туда, куда смотрит стрелка.

**Правила хода** — дословно как в `tools/arrow-flip-solver.mjs` (`applyMove`):

1. Блок едет по стрелке клетка за клеткой.
2. Если следующая клетка за краем поля, блок уходит с поля.
3. Если следующая клетка занята, блок останавливается перед ней.
4. Ход допустим, если блок сдвинулся хотя бы на одну клетку или ушёл за край.
   Блок у края, смотрящий наружу, уходит сразу, не проехав ни клетки, и это
   допустимый ход.
5. Путь — все клетки поля, которые блок занимал за ход, включая стартовую и
   конечную. У ушедшего блока путь заканчивается последней клеткой у края.
6. Задетые — все блоки, которые делят грань хотя бы с одной клеткой пути.
   Сюда входит и блок, в который движущийся упёрся спереди. Касание углом не
   считается.
7. Каждый задетый блок поворачивается на 90° по часовой ровно один раз за ход,
   даже если его касались несколько клеток подряд.
8. Движущийся блок не поворачивается.
9. Задетые считаются по расстановке на начало хода, повороты не меняют
   путь движущегося блока, а повёрнутый блок сам никуда не едет. Анимация
   поворотов может идти во время проезда (§7), на результат это не влияет.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Тап по блоку | следующая клетка за краем | блок удалён, задетые повёрнуты, `moves + 1` | блок уезжает за край, задетые поворачиваются и получают жёлтую отметку | да |
| Тап по блоку | впереди свободно хотя бы на клетку, дальше блок | блок на новой клетке, задетые повёрнуты, `moves + 1` | блок доезжает и упирается, задетые поворачиваются (и упёртый тоже) | да |
| Тап по блоку | соседняя клетка по стрелке занята | ничего | блок покачивается на месте `160 мс`, упёршийся сосед коротко подсвечивается | нет |
| Тап по пустой клетке | всегда | ничего | ничего | нет |
| Тап во время анимации хода | ввод заблокирован | ничего | ничего | нет |
| «Заново» | всегда | уровень в стартовое состояние, `moves = 0` | поле как в начале | — |
| «?» | попапа нет | ввод заблокирован | попап «Как играть» | нет |
| «Понятно!» | попап открыт | `howToPlaySeen = true` | игра с того же места | нет |
| «К уровням» | всегда | попытка брошена | экран уровней | — |
| Любое действие на поле | `status !== 'playing'` или открыт попап | ничего | ничего | нет |

Недопустимый тап никогда не тратит ход и не поворачивает соседей.

# 5. Победа, поражение и переходы

```text
Дано: на поле не осталось блоков.
Когда: завершена обработка хода.
Тогда: победа; уровень добавляется в passed, открывается следующий, попап
       победы — на уровнях 1–4 обычный, на уровне 5 финальный.
```

Победа проверяется раньше лимита: если последний блок ушёл последним
разрешённым ходом, это победа.

```text
Дано: moves = moveLimit, на поле остался хотя бы один блок.
Когда: завершена обработка хода.
Тогда: поражение с причиной moves_exhausted; оставшиеся блоки коротко
       подсвечиваются, через 900 мс попап «Ходы закончились».
```

```text
Дано: moves < moveLimit, на поле остались блоки, ни у одного нет допустимого хода.
Когда: завершена обработка хода.
Тогда: поражение с причиной no_moves; оставшиеся блоки коротко
       подсвечиваются, через 900 мс попап «Ходов нет».
```

Тупик реален: солвер находит такие состояния на уровнях 3, 4 и 5 (§6).

```text
Дано: уровень уже нельзя пройти в оставшиеся ходы, но допустимый ход есть.
Когда: завершена обработка хода.
Тогда: игра продолжается молча. Никаких предупреждений и подсветок.
```

Игра не предсказывает проигрыш — как в `specs/38-build-pack.md`: игрок сам
упирается в лимит или в тупик. «Заново» доступно всегда.

**Порядок после хода:** движение → повороты задетых → удаление ушедшего →
`moves + 1` → проверить победу → проверить `moves_exhausted` → проверить
`no_moves` → вернуть ввод.

Коды причин поражения стабильны: `moves_exhausted`, `no_moves`.

**Случайности нет.** Поле, направления и лимит полностью заданы уровнем и
видны с начала. Скрытой информации нет.

**Переходы между экранами** — как в `specs/done/02-two-moves-later.md`:
главный → уровни → игровой экран; попап победы: «Следующий уровень»,
«Переиграть», «К уровням»; попап поражения: «Переиграть», «К уровням»;
финальный попап после уровня 5: «Переиграть», «К уровням». Закрытый уровень
на экране уровней коротко покачивается.

# 6. Контент и кривая сложности

Пример данных одного уровня — формат солвера:

```json
{
  "name": "AF-T2", "size": 4, "moveLimit": 4,
  "blocks": [
    { "id": "0", "row": 0, "col": 1, "dir": ">" },
    { "id": "1", "row": 1, "col": 0, "dir": "<" },
    { "id": "2", "row": 1, "col": 1, "dir": ">" },
    { "id": "3", "row": 1, "col": 2, "dir": "<" }
  ]
}
```

Источник уровней — `GAME_LEVELS` в `tools/arrow-flip-solver.mjs`. Игра берёт
их оттуда без правки руками. На схемах ниже цифра — `id` блока, `·` — пустая
клетка.

**Лимит.** На обучающих уровнях лимит равен числу блоков, и проиграть нельзя
никаким порядком ходов. На уровнях с ловушкой лимит равен оптимуму солвера,
без запаса.

### Уровень 1 — AF-T1, обучающий

3 блока, лимит 3.

```text
 ·   ·   ·   ·
 ·   ·  0←   ·
 ·  2←   ·   ·
 ·  1↓   ·   ·
```

Все три блока могут выйти сразу, и любой из 6 порядков побеждает. Любой
первый ход кого-то поворачивает: `0` задевает `2`, `1` задевает `2`, `2`
задевает `1`. Навык: тап — блок уезжает, соседи поворачиваются.

### Уровень 2 — AF-T2, обучающий

4 блока, лимит 4.

```text
 ·  0→   ·   ·
1←  2→  3←   ·
 ·   ·   ·   ·
 ·   ·   ·   ·
```

`2` и `3` смотрят друг на друга, их тап недопустим. Выйти могут `0` и `1`.
Проезд `0` вдоль ряда разворачивает сразу `2` и `3` — первый маленький
payoff. Все 9 возможных порядков побеждают. Навык: заблокированный блок
открывается чужим проездом.

### Уровень 3 — AF-01, первая ловушка

5 блоков, лимит 6.

```text
2↓   ·  0←  4↓
3→  1←   ·   ·
 ·   ·   ·   ·
 ·   ·   ·   ·
```

Допустимых первых ходов два. `4` уходит сразу, но после этого уровень не
решается. `0` за край не уходит, упирается в `2` и поворачивает соседей —
это setup-ход. Решение: `0 → 2 → 0 → 1 → 3 → 4`.

### Уровень 4 — AF-03

6 блоков, лимит 8.

```text
2↓   ·  4←  3→
 ·   ·   ·  0←
 ·   ·   ·   ·
 ·   ·  5→  1←
```

Сразу могут выйти `0`, `2` и `3`, и любой из них проигрывает уровень.
Единственный верный первый ход — `4`, и `4` запускается дважды. Решение:
`4 → 0 → 2 → 3 → 4 → 3 → 5 → 1`.

### Уровень 5 — AF-04, проверка гипотезы

7 блоков, лимит 9.

```text
 ·  6↑   ·  5↓
 ·   ·  2→  1←
 ·   ·   ·   ·
0→  4↑  3↓   ·
```

Сразу могут выйти `3` и `6`, и оба проигрывают. Верный первый ход — `4`, и
`4` запускается трижды. Решение: `4 → 0 → 3 → 2 → 4 → 1 → 4 → 6 → 5`.

### Сводка

«Случайный игрок» — тапает случайный допустимый блок, 20 000 попыток.
«Жадный» — тапает случайный из тех, что могут выйти прямо сейчас, а если
таких нет, то любой.

| Уровень | Блоков | Лимит | Состояний | Тупиков до лимита | Случайный | Жадный | Главное давление |
|---:|---:|---:|---:|---:|---:|---:|---|
| 1 | 3 | 3 | — | 0 | 100% | 100% | нет |
| 2 | 4 | 4 | — | 0 | 100% | 100% | нет |
| 3 | 5 | 6 | 39 | 1 | 12% | 0% | приманка `4` |
| 4 | 6 | 8 | 45 | 2 | 9% | 0% | три приманки, двойной запуск |
| 5 | 7 | 9 | 469 | 7 | 0,5% | 0% | две приманки, тройной запуск |

Разница между соседними уровнями:

- `1→2` — появляются заблокированные блоки, которых открывает только чужой
  проезд, и один ход разворачивает сразу двоих.
- `2→3` — появляется ловушка: блок, готовый к выходу, проигрывает уровень.
  Лимит без запаса. Нужен первый setup-ход, блок, который не уходит, а
  упирается.
- `3→4` — приманок три вместо одной, и один и тот же блок нужно запустить
  дважды: setup — не разовый трюк, а часть плана.
- `4→5` — 7 блоков, в 10 раз больше состояний, случайный игрок почти не
  выигрывает. Перебором через «заново» пройти трудно, так что уровень
  проверяет гипотезу напрямую.

**Правило отбора уровня** (проверяется запуском солвера,
`node tools/arrow-flip-solver.mjs`, и тестом прототипа):

- обучающие: оптимум = лимит = число блоков, жадная стратегия решает,
  ни один ход не делает уровень непроходимым (`isTrapFree`), хотя бы один
  первый ход кого-то поворачивает;
- с ловушкой: оптимум = лимит, жадная стратегия не решает, на старте есть
  блок, готовый к выходу, и ни один такой блок не является оптимальным
  первым ходом — это kill-критерий в форме теста.

В запасе, если уровень 3 или 4 окажется слишком лёгким или трудным: `AF-02`
(5 блоков, лимит 6, случайный 8%) и `AF-05` (7 блоков, лимит 10, случайный
29%) — схемы в `ideas/approved/36-arrow-flip.md`.

# 7. Обратная связь и обучение

- **Доступное действие:** каждый блок — тайл с белой стрелкой, цвет тайла
  показывает направление (решение автора 2026-09-27): `←` синий, `→` зелёный,
  `↑` коралловый (тёплый красный кита — чистый красный в ките зарезервирован
  за проигрышем), `↓` жёлтый. Стрелка остаётся первым и обязательным
  каналом: цвет дублирует направление, а не заменяет его. Номер блока игроку
  не показывается.
- **Запрещённое действие:** блок, упёршийся вплотную, покачивается на месте
  `160 мс`, сосед, в которого он упёрся, коротко подсвечивается. Ход не
  тратится.
- **Движение и поворот:** по §7.2. Коротко: квадрат задетого блока стоит на
  месте, крутится только стрелка на нём, и ровно в тот момент, когда мимо
  проезжает блок; вместе со стрелкой плавно меняется и цвет тайла — на новое
  направление.
- **Что повернулось:** повёрнутый блок на миг светлеет, затем плавно, за
  `700 мс`, гаснет обратно к обычному цвету (§7.2). Это главная подсказка
  правила без текста, и она не нуждается в отдельной иконке — блок сам
  показывает, что его коснулись.
- **Цена хода:** счётчик «Ходы `k / лимит`» под шапкой. Когда остался один
  ход, у счётчика появляется коралловая обводка.
- **Победа:** последний блок уезжает, пустое поле коротко подпрыгивает
  волной, попап победы.
- **Поражение:** оставшиеся блоки подсвечиваются, через `900 мс` попап
  «Ходы закончились» (`moves_exhausted`) или «Ходов нет — все блоки упёрлись»
  (`no_moves`).
- **Payoff:** один проезд поворачивает сразу несколько блоков, и они
  оказываются смотрящими в свободные коридоры. На экране — несколько жёлтых
  колец разом и стрелки, указывающие наружу.
- **Без текста игрок должен понять:** блок едет по стрелке; кого заденет, тот
  повернётся по часовой; упёртый блок тапать бесполезно.

**Обучение — попап «Как играть».** Открывается сам при первом входе в
уровень 1, дальше — по кнопке «?». Четыре правила:

1. Тапни блок — он поедет туда, куда смотрит стрелка.
2. Блок едет до другого блока или уходит за край поля.
3. Каждый блок, которого он коснётся по пути, повернётся на 90° по часовой.
4. Выведи все блоки за край, пока не кончились ходы.

Уровни 1–2 работают как обучение: проиграть на них нельзя, и каждый первый
ход показывает поворот.

## 7.1. Экран — как выглядит поле

![Игровой экран](../UI%20Design/prototypes/arrow-flip/game-screen.png)

Скетч — `UI Design/prototypes/arrow-flip/game-screen.png` (исходник
`mockup.html` там же): уровень 2 сразу после первого хода. `0` уезжает
вправо; `2` и `3` повернулись, оба чуть светлее обычного (свечение на
середине угасания) и уже сменили цвет на новое направление.

Игровой экран обязан помещаться целиком без прокрутки от 360×560 до 430×932.

Сверху вниз:

1. **Шапка, 44 px:** слева иконка «к уровням», по центру «Уровень N»,
   справа иконки «?» и «заново».
2. **Счётчик ходов** — пилюля «Ходы `k / лимит`» по центру.
3. **Поле 4×4 — главный объект, всё оставшееся место.** Клетка считается от
   свободного места, 56–88 px, тапом попадается легко.
4. **Строка подсказки внизу:** короткая фраза правила и отметка «повернулся
   этим ходом». Только на уровнях 1–2, на уровнях 3–5 её нет.

За секунду читаются: куда смотрит каждая стрелка, кто повернулся последним
ходом, сколько ходов осталось. Payoff — на поле, в момент поворотов.

**Второй канал к цвету.** Решение принимается по направлению стрелки, а не
по цвету: у каждого направления свой цвет тайла, но это подсказка, не
единственный носитель информации, и она не выключает игрока с дальтонизмом
— форма стрелки читается независимо от цвета. Отметка «повернулся» тоже не
только в цвете: видно по стрелке, которая на глазах меняет направление (и
теперь ещё меняет цвет тайла), а свечение лишь подчёркивает момент.

Главный экран, экран уровней и попапы — как у `apps/build-pack`. Стиль
PuzzleKit, новых цветов, радиусов и теней нет.

## 7.2. Анимация хода

Это главный момент игры, и он обязан быть приятным глазу: игрок видит, как
проезжающий блок «задевает» соседей, а их стрелки проворачиваются следом
(решение автора 2026-09-26). Живое демо на настоящих правилах и уровнях —
`UI Design/prototypes/arrow-flip/animation-demo.html`. Кнопка «Замедлить ×4»
позволяет разглядеть синхрон. Числа ниже взяты из демо.

**Что крутится.**

1. У задетого блока квадрат не двигается, не масштабируется и не
   поворачивается. Крутится только стрелка — отдельный слой вокруг центра
   квадрата.
2. Поворот — 90° по часовой, `320 мс`, easing `cubic-bezier(.34, 1.5, .52, 1)`:
   стрелка чуть перелетает (около 6°) и мягко встаёт на место.
3. Угол стрелки накапливается: после `←` идёт 360°, а не 0°. Иначе переход
   `← → ↑` прокрутится на 270° назад.
4. Одновременно со стартом поворота квадрат блока мгновенно светлеет —
   `filter: brightness(1.35)` — и затем плавно, за `700 мс`, easing
   `ease-out`, гаснет обратно к обычной яркости. Дольше самого поворота: пока
   стрелка уже неподвижна, свечение ещё видно, и след «меня задели» не
   обрывается вместе с поворотом.
5. Вместе с поворотом цвет тайла плавно, за те же `320 мс`, переходит к
   цвету нового направления (решение автора 2026-09-27): браузер сам ведёт
   градиент между двумя цветами кита, скачка нет.

**Когда крутится — привязка к проезду.** Старт поворота привязан к
фактической позиции едущего блока на экране, а не к таймеру: так синхрон
держится при любом easing и на медленном телефоне.

1. Соседи стартовой клетки начинают поворот сразу, в момент старта хода.
2. Сосед сбоку от пути начинает поворот, когда центру едущего блока осталось
   `0,35` клетки до уровня соседа. Стрелка крутится, пока блок проезжает
   мимо.
3. Блок, в который едущий упёрся спереди, начинает поворот в момент касания.
4. Если блок касается пути несколько клеток подряд, он крутится один раз — по
   первому касанию.
5. Страховка: если кадр пропущен и блок уже доехал, все невыпущенные повороты
   стартуют немедленно.

**Как едет блок.**

- Скорость — в среднем `90 мс` на клетку.
- Остановка у блока: easing `cubic-bezier(.3, 0, .25, 1)` плюс `110 мс`
  доводки — блок мягко тормозит перед соседом.
- Уход за край: разгон `cubic-bezier(.45, 0, 1, 1)`. Блок проезжает ещё
  `1,3` клетки за край и гаснет. Поле обрезает его по своей рамке.
- Упёршийся тап (ход недопустим): покачивание `160 мс` на 5 px в сторону
  стрелки, сосед впереди коротко светлеет (`260 мс`).

**Ввод** возвращается, когда закончились движение и последний поворот.
Анимируются только `transform` и `opacity`, без перестройки раскладки.

**Приёмка анимации** (e2e-тест прототипа, как проверено на демо):

- у каждого задетого блока момент старта поворота стрелки отличается от
  целевой позиции едущего блока не больше чем на `0,2` клетки;
- во время хода квадрат задетого блока не сдвигается ни на пиксель;
- за ход нет кадра длиннее `34 мс` (два кадра при 60 fps). На демо в
  headless Chromium максимум 18 мс;
- уехавший за край блок не показывается повторно на исходной клетке ни на
  один кадр между концом анимации выезда и своим удалением из DOM — баг
  «призрака» (WAAPI-анимация без `fill: 'forwards'` откатывается к
  начальному кадру раньше, чем игра успевает убрать элемент), найден и
  исправлен 2026-09-27.

**`prefers-reduced-motion`:** блок переносится сразу, стрелки встают в новое
направление без вращения, свечение остаётся — оно не вращение, а отметка
касания.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=75%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - на уровнях 3–5 жадная стратегия не решает уровень (проверка солвером)
    - на уровне 5 минимум половина победивших делает верный setup-ход первым в попытке, которая выигрывает, не больше чем с третьей попытки
    - минимум один игрок словами объясняет setup-ход ("запущу этот, чтобы развернуть те")
  kill:
    - выполняется заранее записанный kill_criterion
    - уровни 3–5 проходятся в основном перебором первых ходов через «заново», а не планом (см. ниже)
```

Первое валидное действие — первый допустимый ход на уровне 1. По нему
считаются `first_action_without_help` и `onFirstAction()`.

В лог на каждый ход пишутся: уровень, номер попытки, номер хода, `id` блока,
был ли блок готов к выходу (`isExitReady`), ушёл ли он, сколько блоков
повернул, остался ли уровень проходимым после хода (солвер на оставшиеся
ходы), время от предыдущего хода.

- `setup_share` — доля ходов блоком, не готовым к выходу, на уровнях 3–5.
- `bait_first` — доля попыток, начатых блоком-приманкой.
- `attempts_to_win` — попыток до победы на уровне.
- `switch_after_loss` — после проигрыша следующая попытка начата другим
  первым ходом.
- `think_before_setup` — пауза перед верным setup-ходом против медианы пауз
  игрока.

**Как отделить план от перебора.** Перебор: на уровнях 3–4 первых ходов 2–4,
и игрок, меняющий первый ход после каждого проигрыша, находит верный за 2–4
попытки, не думая. Признаки плана: верный setup-ход в первой или второй
попытке на уровне 5, где состояний в 10 раз больше; пауза перед ним длиннее
обычной; объяснение словами. Если на уровне 5 игроки побеждают только после
многих попыток с разными первыми ходами, а объяснить setup-ход не могут, это
kill.

Метрики диагностические. Решение Gate 2 — по наблюдаемому поведению и
kill-критерию.

# Приложение A. Профиль реализации

**Фабрика.** `apps/arrow-flip/` (папка по slug): веб-игра под браузер
телефона, TypeScript + Vite, без фреймворка, экран на HTML/CSS. Токены и
шрифт — из `UI Design/`. Устройство как у `apps/build-pack`.

Правила хода — порт `applyMove` из `tools/arrow-flip-solver.mjs` без
изменений. Тест прототипа прогоняет решения солвера из §6 через движок игры
и сверяет, что каждое побеждает ровно за лимит, а начало с приманки на
уровнях 3–5 не побеждает. В игре — только проверка «есть ли допустимый ход»
(`no_moves`), решаемость наперёд не считается. Солвер нужен для лога
(«остался ли уровень проходимым») и не влияет на игру.
