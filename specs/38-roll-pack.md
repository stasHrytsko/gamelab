# 1. Граница прототипа

**Что проверяем.** Думает ли игрок о форме фигуры под конкретное оставшееся
место: собирает Г, Т или ступеньку, чтобы обойти препятствие и не оставить
кусок поля, который уже не закрыть оставшимися числами.

**Минимальный цикл.** Поле с препятствиями, ряд чисел 4–7, конструктор 4×4,
перетаскивание фигуры на поле, проверка «ещё можно решить». Вокруг цикла пять
экранов и три попапа (§7.1).

**Не делаем.** Кубики и любую случайность, поворот фигуры, отмену уложенной
фигуры, подсказку решения, предупреждение «уровень уже не собрать»,
звёзды, очки, таймер, звук, настройки и бесконечный режим.

**Уровней пять.** Открываются по очереди.

**Откуда эта версия.** Первая версия спеки (2026-09-25) — три случайных
кубика и горизонтальные планки с гравитацией. Автор отказался от неё после
игры: «слишком рандомно». Промежуточный вариант «кубик задаёт размер, фигура
свободная, поле 12×12» проверен солвером и отвергнут: заполнение поля
«змейкой» всегда работает, форма фигуры ничего не решает, а весь проигрыш —
от кубиков в конце. Текущая версия — решение автора 2026-09-25: числа известны
заранее (§5), сложность — препятствия и форма поля (§6).

**Почему kill-критерий такой.** Вся механика держится на том, что форму
фигуры выбирает игрок. Если форма не зависит от поля, выбор формы — пустое
действие, и это не лечится подбором уровней.

# 2. Цель и основной цикл

Цель игрока — использовать все числа уровня и заполнить поле целиком, без
пустых клеток.

Первое доступное действие — тапнуть число в ряду чисел.

```text
Выбрать число N в лотке
→ тапами собрать в конструкторе 4×4 фигуру из N клеток, касающихся сторонами
→ перетащить готовую фигуру на пустые клетки поля
→ число гаснет, конструктор очищается
→ проверка победы и поражения по §5
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Клетка поля | пустая; препятствие; занята фигурой | пустая становится занятой при укладке | препятствие задано уровнем и не меняется; занятая не освобождается |
| Число | доступно; выбрано; использовано | выбирается тапом; используется при укладке фигуры | значение 4–7; выбрано не больше одного числа; сумма чисел уровня = числу пустых клеток поля |
| Клетка конструктора | пустая; отмечена | переключается тапом; «Очистить» делает все пустыми | сетка 4×4; отмечено не больше N клеток, где N — выбранное число |
| Фигура | собирается; готова | готова, когда отмечено ровно N клеток и они связны по сторонам | форма — только та, что помещается в 4×4; поворота нет |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Пространство.** Поле — прямоугольная сетка до 6×6, клетка адресуется
`row` (сверху вниз) и `col` (слева направо). В карте уровня `.` — пустая
клетка, `#` — препятствие внутри поля (рисуется тёмной штриховкой), пробел —
клетка вне формы поля (не рисуется). Для правил оба последних — «нельзя
ставить».
Конструктор — отдельная сетка 4×4 с той же адресацией. Фигура на поле
ставится с тем же расположением клеток, что в конструкторе: без поворота и
отражения.

```ts
type Cell = 'wall' | null | number;   // number — размер фигуры, занявшей клетку

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  board: Cell[][];                    // до 6×6
  numbers: number[];                  // числа уровня, 4..7
  used: boolean[];                    // по одному на число
  selected: number | null;            // индекс выбранного числа
  built: Array<[row: number, col: number]>; // отмеченные клетки конструктора
  status: 'playing' | 'won' | 'failed';
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

# 4. Ввод и правила

```ts
type Action =
  | { type: 'select-number'; index: number }
  | { type: 'toggle-builder-cell'; row: number; col: number }
  | { type: 'clear-builder' }
  | { type: 'drag-piece'; row: number; col: number }   // клетка поля под зажатой клеткой фигуры
  | { type: 'drop-piece' }
  | { type: 'open-help' }
  | { type: 'exit-to-levels' };
```

**Счётчик клеток** — в строке подсказки, сразу после текста: «Собери фигуру
из 6 клеток `4/6`». Когда отмечено N клеток, счётчик зелёный. Решение автора
2026-09-25.

Число и клетки конструктора — тапом. Готовая фигура перетаскивается с любой
своей клетки: на телефоне пальцем, на компьютере зажатой кнопкой мыши. Во
время перетаскивания фигура рисуется над пальцем на одну клетку выше, чтобы её
было видно. Поворота, отражения, отмены уложенной фигуры и долгого нажатия
нет.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Тап по числу | доступно, ничего не выбрано | `selected = index` | число приподнято, конструктор активен, подсказка «Собери фигуру из N клеток» и счётчик `0/N` | нет |
| Тап по числу | выбрано другое число | `selected = index`; если значения разные — конструктор очищается | выбор переходит | нет |
| Тап по числу | это же число уже выбрано | `selected = null`, конструктор очищается | число опускается, конструктор гаснет | нет |
| Тап по числу | использовано | ничего | ничего | нет |
| Тап по пустой клетке конструктора | отмечено меньше N | клетка отмечается | в клетке тайл цвета числа, счётчик `k/N` растёт | нет |
| Тап по пустой клетке конструктора | отмечено уже N | ничего | ничего | нет |
| Тап по отмеченной клетке | фигура не готова | отметка снимается | клетка пустеет, счётчик уменьшается | нет |
| «Очистить» | есть отмеченные | все отметки снимаются | конструктор пуст | нет |
| Отмечено N клеток, но они не связны | всегда | ничего | подсказка «Клетки должны касаться сторонами» | нет |
| Зажать клетку готовой фигуры и вести | фигура готова | ничего | фигура едет за пальцем; клетки поля под ней зелёные, если все пустые, иначе красные | нет |
| Отпустить над полем | все клетки под фигурой пустые | клетки занимаются, число `used`, `selected = null`, конструктор очищается, дальше по §5 | фигура ложится на поле | да |
| Отпустить | хотя бы одна клетка — препятствие, занята или за краем | ничего | фигура возвращается в конструктор, подсказка «Сюда не встаёт» | нет |
| «?» | попапа нет | ввод заблокирован | попап «Как играть» | нет |
| «Понятно!» | попап открыт | `howToPlaySeen = true` | игра с того же места | нет |
| «К уровням» | всегда | попытка брошена | экран уровней | — |
| Любое действие | `status !== 'playing'` или открыт попап | ничего | ничего | нет |

Тап по отмеченной клетке готовой фигуры — начало перетаскивания, а не снятие
отметки. Чтобы переделать готовую фигуру — «Очистить».

# 5. Победа, поражение и переходы

```text
Дано: все числа уровня использованы.
Когда: завершена укладка фигуры.
Тогда: пустых клеток нет (сумма чисел = пустым клеткам); уровень добавляется
       в passed, открывается следующий, попап победы — на уровнях 1–4
       обычный, на уровне 5 финальный.
```

```text
Дано: остались неиспользованные числа.
Когда: после укладки ни одно из них нельзя поставить никуда — ни в одном
       свободном куске поля нет места под связную фигуру этого размера
       (в рамке 4×4).
Тогда: попытка заканчивается поражением с причиной no_moves; пустые клетки
       подсвечиваются красным, через 900 мс попап «Ходов нет».
```

```text
Дано: после укладки поле уже нельзя собрать целиком, но хотя бы одно число
      ещё куда-то помещается.
Когда: завершена укладка.
Тогда: игра продолжается молча. Никаких предупреждений и подсветок.
```

**Игра не предсказывает проигрыш (решение автора 2026-09-25).** Первая
сборка объявляла поражение сразу после хода, который делал уровень
нерешаемым (солвер видел это наперёд). Автор: «игра сама считает и
показывает, что я не соберу, а я думаю, что соберу, — это злит; хочу сам
увидеть, что не могу собрать». Теперь игрок доигрывает, пока есть хоть один
ход, и сам упирается в тупик. «Заново» доступно всегда.

Порядок проверок после укладки: занять клетки → число `used` → проверить
победу → проверить, есть ли хоть один ход → вернуть ввод.

Код причины поражения один и стабильный: `no_moves`.

**Случайности нет.** Поле, препятствия и числа полностью заданы уровнем и
видны с начала. Проигрыш — всегда следствие решения игрока.

**Переходы между экранами** — как в `specs/done/02-two-moves-later.md`:
главный → уровни → игровой экран; попап победы: «Следующий уровень»,
«Переиграть», «К уровням»; попап проигрыша: «Переиграть», «К уровням»;
финальный попап после уровня 5: «Переиграть», «К уровням». Закрытый уровень
на экране уровней коротко покачивается.

# 6. Контент и кривая сложности

Пример данных одного уровня:

```json
{
  "id": 1,
  "map": ["#.....", "......", "......", "......", "......", ".....#"],
  "numbers": [7, 7, 6, 5, 5, 4]
}
```

Порядок чисел — по убыванию.

**Сложность растёт двумя способами (решение автора):**

1. **Препятствия внутри поля** — клетки, куда фигуру не поставить.
2. **Форма самого поля** — не квадрат: Г, «бабочка», зигзаг.

**Уровни** (`apps/roll-pack/src/levels/levels.ts`). Подобраны солвером
2026-09-25. «Решений» — число разных раскладок поля на фигуры (до 5000).

| Уровень | Карта | Клеток | Числа | Решений | Новый навык | Главное давление |
|---:|---|---:|---|---:|---|---|
| 1 | `#.....` `......` `......` `......` `......` `.....#` | 34 | 7, 7, 6, 5, 5, 4 | 5000+ | выбрать число, собрать фигуру, уложить | почти нет |
| 2 | `......` `......` `..#...` `....#.` `.#....` `......` | 33 | 7, 7, 6, 5, 4, 4 | 5000+ | обойти препятствие формой фигуры | три препятствия рвут ряды |
| 3 | `...` `...` `...` `......` `......` `......` (Г) | 27 | 7, 7, 7, 6 | 1500 | собрать фигуру под выступ Г | форма поля, крупные фигуры |
| 4 | ` .... ` ` .... ` `......` `......` `....#.` `....#.` | 30 | 6, 6, 6, 6, 6 | 1391 | пять одинаковых чисел — пять разных форм | форма поля и препятствия |
| 5 | `....` ` .....` `  ...#` `......` `.#..` ` .....` (зигзаг) | 27 | 7, 5, 5, 5, 4 | 21 | всё вместе: пять фигур трёх размеров | 2% первых ходов не проигрышные |

Разница между соседними уровнями:

- `1→2` — появляются препятствия внутри: ряд целиком уже не ложится.
- `2→3` — поле перестаёт быть квадратом, фигуры крупнее (7, 7, 7, 6):
  выступ Г требует ступенек и уголков.
- `3→4` — все числа одинаковые: выбор числа исчезает, остаётся только выбор
  формы — прямая проверка гипотезы.
- `4→5` — зигзаг с двумя препятствиями и 21 решение: из 1445 возможных первых
  ходов не проигрывают 33.

**Правило отбора уровня** (проверяется в `npm test`):

- числа 4–7, по убыванию, сумма = числу пустых клеток;
- солвер находит решение с фигурами, помещающимися в 4×4;
- на уровнях 2–5 «змейка» не решает уровень: заполнение поля рядами слева
  направо и справа налево, кусками по порядку, при любом порядке чисел — это
  kill-критерий в форме теста;
- число решений не растёт от уровня 2 к уровню 5, на уровне 5 — от 20 до 30
  (решение автора 2026-09-25).

Уровень 5 сначала собрали с 2 решениями: из 1072 первых ходов не проигрывали
6, «аккуратный» случайный игрок выигрывал 12%. Автор попросил проще — 20–30
решений. Из подобранных солвером вариантов взят тот, где «аккуратный»
случайный игрок выигрывает 16%: вариант с 30 решениями давал 86%, это легче
уровня 4.

# 7. Обратная связь и обучение

- **Препятствие:** клетка темнее пустой, в косую штриховку, с тенью снизу —
  с первого взгляда отличается от пустой.
- **Доступное действие:** числа в лотке — крупные тайлы цвета размера (4 —
  зелёный, 5 — синий, 6 — коралловый, 7 — фиолетовый). Использованное число
  — бледный тайл без цвета.
- **Сборка:** отмеченная клетка конструктора — тайл цвета числа; счётчик
  `k/N` в подсказке. Готовая фигура обводит конструктор зелёным и слегка
  покачивается — её можно тащить.
- **Запрещённое действие:** клетки поля под фигурой красные; отпущенная там
  фигура возвращается, подсказка «Сюда не встаёт».
- **Цена хода:** уложенную фигуру не вернуть, число гаснет.
- **Победа:** последняя фигура ложится, попап победы.
- **Поражение:** только когда ходов нет — пустые клетки подсвечиваются
  красным, через `900 мс` попап «Ходов нет» — «Оставшиеся числа больше никуда
  не помещаются». Раньше игра ничего не подсказывает.
- **Payoff:** фигура точно встаёт в сложное место — клетки коротко
  подпрыгивают при укладке; при победе все клетки поля подпрыгивают волной.
- **Без текста игрок должен понять:** число = сколько клеток в фигуре;
  фигуру собираешь сам; ставить можно только на пустые клетки.

**Обучение — попап «Как играть».** Открывается сам при первом входе в
уровень 1, дальше — по кнопке. Четыре правила:

1. Выбери число сверху — столько клеток будет в фигуре.
2. Собери фигуру: тапай по сетке 4×4. Клетки должны касаться сторонами.
3. Перетащи фигуру на поле, на пустые клетки.
4. Используй все числа и заполни поле целиком. Если оставшиеся числа больше
   никуда не помещаются — попытка проиграна.

## 7.1. Экраны

![Игровой экран](../UI%20Design/prototypes/roll-pack/game-screen.png)

Снимки собранного прототипа — `UI Design/prototypes/roll-pack/`: главный,
уровни, игровой экран (390×664 и 360×560), «Как играть», проигрыш, победа.
Пересобираются из `apps/roll-pack` (`tools/make-screens.ts`). Мокапы v2 и v3
там же — история.

**Игровой экран обязан помещаться целиком без прокрутки** на экранах от
360×560 (Android, встроенные браузеры, окно Claude) до 430×932. Проверено на
прототипе e2e-тестом: 360×560, 375×560, 390×664, 430×932 — прокрутки нет.

Сверху вниз:

1. **Шапка, 44 px:** слева иконка «к уровням», по центру «Уровень N»,
   справа иконки «?» и «заново». Текстовых кнопок нет.
2. **Поле — главный объект, занимает всё оставшееся место.** Размер клетки
   считается от свободного места: 28–60 px.
3. **Лоток внизу, в зоне большого пальца:** строка подсказки (одна короткая
   фраза и счётчик `k/N`); слева конструктор 4×4 (клетка 32–40 px в зависимости от высоты
   экрана), справа числа сеткой 3×2 и кнопка «Очистить».

Почему так: поле — цель, поэтому сверху и крупно; сборка и выбор чисел —
руками, поэтому внизу; фигуру тянут вверх, и палец не закрывает место, куда
она ложится. Готовая фигура обводит конструктор зелёным.

Главный — арт первого экрана от автора (`UI Design/prototypes/roll-pack/assets/home-screen.png`):
название Build & Pack, поле и летящие фигуры. В игре — `home-art.webp` (55 КБ):
арт обрезан над нарисованной кнопкой и подписью генератора, края растворяются
в размытой копии арта на фоне. Под артом — настоящая кнопка «Играть» в стиле
арта: синяя пилюля 72 px, текст 26 px. Кнопка зовёт нажать: дышит (масштаб
1 → 1,045, 2,4 с), в такт мягко светится и раз в 3,2 с по ней пробегает блик.
При `prefers-reduced-motion` анимации нет. Арт и кнопка — одной группой по
центру экрана; помещаются без прокрутки от 360×560 (решение автора 2026-09-26).
Уровни: пять карточек с числом клеток и фигур. Попапы — как у
`apps/taxi-slide`. Стиль PuzzleKit, новых цветов, радиусов и теней нет.

За секунду читаются: какие числа остались, какие клетки поля пустые, а какие
— препятствия. Payoff — на поле, в момент укладки.

**Второй канал к цвету.** Размер фигуры читается по числу на тайле и по числу
клеток, цвет — только подсказка.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=75%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - на уровнях 2–5 «змейка» не решает уровень (проверка солвером)
    - на уровнях 3–5 игроки собирают фигуры минимум трёх разных форм для одного и того же числа
    - минимум один игрок словами объясняет, почему собрал именно такую форму
  kill:
    - выполняется заранее записанный kill_criterion
```

Первое валидное действие — первая уложенная фигура. По нему считается
`first_action_without_help`.

В лог уровня на каждой укладке пишутся: число, форма фигуры (клетки
относительно левого верхнего угла), позиция на поле, сколько раз игрок
очищал конструктор перед этой фигурой, время от выбора числа до укладки.

- `shape_variety` — сколько разных форм игрок собрал для одного размера за
  уровень.
- `rebuilds` — среднее число «Очистить» на фигуру: признак, что игрок
  примеряет форму.

Метрики диагностические. Решение Gate 2 — по наблюдаемому поведению и
kill-критерию.
