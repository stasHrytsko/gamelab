# 1. Граница прототипа

**Что проверяем.** Останавливается ли игрок перед выбором кубика и выбирает ли
длину ради того, какую поверхность она оставит под следующие броски, а не
только ради того, куда она ложится сейчас.

**Минимальный цикл.** Поле шириной 6 столбцов, прямоугольный силуэт высотой
2–6, три кубика на ход, выбор одного, перетаскивание планки по горизонтали,
падение на ровный участок. Вокруг цикла пять экранов и три попапа (§7.1).

**Не делаем.** Перебросы, пропуски хода, отмену хода, фигурные силуэты,
вертикальные планки, бустеры, очки, звёзды, таймер, звук, настройки и
бесконечный режим.

**Уровней пять:** силуэты 6×2, 6×3, 6×4, 6×5 и 6×6. Открываются по очереди.

**Почему силуэты только прямоугольные.** Солвер проверил фигурные силуэты
(ступенька, пирамида, «бутылка»): выбор кубика решает исход только в 1–12%
ходов, а идеальный игрок выигрывает 9–31%. У прямоугольников — 37–56% и
57–76%. Фигура душит выбор, поэтому в прототипе её нет.

**Почему три кубика, а не два с перебросами.** A/B-тест солвером
(`ideas/approved/38-roll-pack.md`): у двух кубиков с тремя перебросами выбор
кубика решает исход в 3% ходов, у трёх кубиков — в 37%.

**Почему kill-критерий такой.** Он ловит ровно то, ради чего существует
механика: выбор из трёх длин. Если игрок берёт кубик автоматически, дело не в
балансе силуэтов — выбор просто не читается как решение о будущей поверхности.

# 2. Цель и основной цикл

Цель игрока — заполнить силуэт целиком: каждый столбец до своей высоты.

Первое доступное действие — тапнуть один из трёх кубиков.

```text
Увидеть три выпавших числа и поверхность поля
→ тапнуть кубик: над полем появляется планка этой длины
→ перетащить планку по горизонтали на ровный участок
→ отпустить: планка падает и ложится
→ выпадают три новых числа
→ проверка победы и поражения по §5
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Столбец | высота `0..cap` | высота растёт на 1, когда на него ложится планка | высота никогда не превышает `cap`; не уменьшается |
| Кубик | не выбран; выбран | выбирается тапом; после укладки все три заменяются следующим броском | значение `1..6`; выбран не больше одного кубика за раз |
| Планка | в руке; уложена | появляется в руке при выборе кубика; ложится при отпускании на валидной позиции | длина = значение выбранного кубика; горизонтальная; целиком внутри поля |
| Бросок | текущий; сыгран | после каждой укладки заменяется новым случайным броском | ровно три числа, каждое независимо и равновероятно `1..6` |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Пространство** — 6 столбцов, `col = 0..5` слева направо. Клетка адресуется
парой `col` и `row`, `row = 0` — нижний ряд. Силуэт задан высотой `cap[col]`;
в прототипе все `cap` уровня равны. Позиция планки — `x`, индекс её левого
столбца: планка длины `L` занимает столбцы `x..x+L-1`.

**Валидная позиция.** Планка длины `L` в позиции `x` валидна, если:

1. `0 <= x` и `x + L - 1 <= 5`;
2. все столбцы `x..x+L-1` одной высоты `h`;
3. `h < cap` у каждого из них.

Уложенная планка поднимает эти столбцы до `h + 1`. Пустот под планками не
бывает: невалидную позицию нельзя выбрать.

```ts
type Die = { value: 1 | 2 | 3 | 4 | 5 | 6 };

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  cap: number;               // высота силуэта, общая для всех столбцов уровня
  heights: number[];         // длина 6, 0..cap
  rollsMade: number;         // сколько бросков сделано в попытке
  dice: [Die, Die, Die];
  selectedDie: 0 | 1 | 2 | null;
  planksPlaced: number;
  status: 'playing' | 'won' | 'failed';
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

# 4. Ввод и правила

```ts
type Action =
  | { type: 'select-die'; index: 0 | 1 | 2 }
  | { type: 'drag-plank'; x: number }     // промежуточная позиция, снап к столбцу
  | { type: 'release-plank'; x: number }
  | { type: 'open-help' }
  | { type: 'exit-to-levels' };
```

Кубик выбирается тапом. Планка перемещается перетаскиванием по горизонтали:
на телефоне пальцем, на компьютере зажатой кнопкой мыши. Позиция снапится к
ближайшему столбцу по центру планки. Вертикального перемещения, поворота
планки, долгого нажатия, переброса, пропуска хода, отмены и перезапуска на
игровом экране нет.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Тап по кубику | ничего не выбрано | `selectedDie = index` | кубик приподнят; над полем появляется планка его длины у левого края; все валидные позиции этой длины подсвечены | нет |
| Тап по кубику | выбран другой кубик | `selectedDie = index` | прежний кубик опускается; планка в руке меняет длину; подсветка позиций обновляется | нет |
| Тап по кубику | этот же кубик уже выбран | `selectedDie = null` | кубик опускается, планка исчезает | нет |
| Тап по кубику | у его длины нет ни одной валидной позиции | состояние не меняется | кубик затемнён и коротко покачивается | нет |
| Перетаскивание планки | кубик выбран | состояние не меняется | планка едет за пальцем; над валидной позицией — сплошная, над невалидной — полупрозрачная с красным контуром | нет |
| Отпускание планки | позиция валидна | столбцы `x..x+L-1` растут на 1, `planksPlaced += 1`, дальше по §5 | планка падает `180 мс` и ложится | да |
| Отпускание планки | позиция невалидна | состояние не меняется, `selectedDie` сохраняется | планка возвращается к последней валидной позиции или к левому краю, коротко покачивается | нет |
| Перетаскивание не с планки | всегда | состояние не меняется | ничего | нет |
| Тап по полю | всегда | состояние не меняется | ничего | нет |
| «?» | попапа нет | ввод на поле заблокирован | попап «Как играть» | нет |
| «Понятно!» в «Как играть» | попап открыт | попап закрывается, `howToPlaySeen = true` | игра продолжается с того же места | нет |
| «К уровням» | всегда | попытка брошена, прогресс не меняется | экран уровней | — |
| Любое действие на поле | `status !== 'playing'` или открыт попап | состояние не меняется | ничего | нет |

Одинаковые значения на кубиках допустимы и ничем не отличаются от разных:
игрок всё равно выбирает один кубик.

# 5. Победа, поражение и переходы

```text
Дано: высота каждого столбца равна cap.
Когда: завершена укладка планки.
Тогда: уровень добавляется в passed, открывается следующий, показывается
       попап победы — на уровнях 1–4 обычный, на уровне 5 финальный.
```

```text
Дано: поле не заполнено.
Когда: выпал новый бросок, и ни у одной из трёх длин нет валидной позиции.
Тогда: попытка заканчивается поражением с причиной no_fit, показывается
       попап проигрыша.
```

Поражение возможно всегда, кроме победного хода: любая поверхность, кроме
полной, может не принять ни одну из трёх длин.

Порядок автоматической обработки после валидной укладки:

1. Завершить падение планки, обновить `heights`.
2. Проверить победу. Если победа — дальше не идём.
3. Бросить три новых случайных кубика, `rollsMade += 1`: кубики выкатываются
   `250 мс`.
4. `selectedDie = null`.
5. Проверить поражение `no_fit`.
6. Вернуть ввод игроку.

Код причины поражения один и стабильный: `no_fit`.

**Кубики всегда случайны.** Каждый бросок — три независимых равновероятных
числа `1..6`, в том числе первый бросок попытки. Броски не зависят от
уровня, номера попытки, прошлых попыток и игрока: сколько бы раз игрок ни
заходил в уровень, каждая попытка — новая случайная партия. Зёрен,
заготовленных последовательностей и подкрутки бросков нет. Будущие броски
игроку не показываются.

Попытку может быть невозможно выиграть из-за бросков — даже идеальный игрок
проигрывает на уровнях 1–5 от 24% до 43% партий (§6). Это нормально: игрок
переигрывает и выигрывает в следующий раз.

Это осознанное отступление от правила шаблона «никакой случайности, влияющей
на исход, в момент игры». Решение автора 2026-09-25: неизвестность следующего
броска — само давление идеи. Для оценки гипотезы случайность отделяется от
решений игрока через лог (§8), а не через фиксацию бросков.

**Переходы между экранами:**

| Откуда | Действие | Куда |
|---|---|---|
| Главный | «Играть» | Уровни |
| Уровни | «Назад» | Главный |
| Уровни | тап по открытому уровню | Игровой экран, уровень с начала, новый случайный бросок |
| Уровни | тап по закрытому уровню | ничего, уровень коротко покачивается |
| Игровой экран, уровень 1 | вход, `howToPlaySeen = false` | попап «Как играть» открывается сам |
| Попап победы 1–4 | «Следующий уровень» | Игровой экран, следующий уровень с начала |
| Попап победы 1–4, проигрыша, финальный | «Переиграть» | Игровой экран, тот же уровень с начала, новый случайный бросок |
| Попап победы 1–4, проигрыша, финальный | «К уровням» | Уровни |

# 6. Контент и кривая сложности

Пример данных одного уровня:

```json
{
  "id": 3,
  "width": 6,
  "cap": 4
}
```

Бросков в данных уровня нет: они случайны во время игры (§5).

**Правило построения.** Уровень `N` (1..5): `width = 6`, `cap = N + 1`.

**Kill-тест для уровней.** На уровнях 3–5 каждая из эвристик выигрывает не
больше 60% от побед идеального игрока на том же уровне (оба играют случайные
броски, от 10 000 партий):

- «держи ровно» — позиция и длина, после которых на поверхности меньше всего
  перепадов высоты; при равенстве — длиннее;
- «бери длинное» — самая длинная длина, у которой есть валидная позиция,
  в самую левую из них.

Идеальный игрок не знает будущих бросков и на каждом ходу выбирает кубик и
позицию с максимальной вероятностью победы (точный подсчёт по всем будущим
броскам). Если эвристика подбирается к нему ближе 60% — автоматический выбор
кубика работает, и это ранний сигнал kill-критерия ещё до игроков.

Замер солвером, 1000 случайных бросков на уровень (`ideas/approved/38-roll-pack.md`):

| Уровень | Силуэт | Клеток | Ходов в среднем | Идеальный игрок | «Держи ровно» | Случайный | Выбор решает исход | Вынужденных ходов | Новый навык | Главное давление |
|---:|---|---:|---:|---:|---:|---:|---:|---:|---|---|
| 1 | 6×2 | 12 | 3,7 | 76% | 56% | 19% | 56% | 22% | выбрать кубик, перетащить, уложить | почти нет |
| 2 | 6×3 | 18 | 5,5 | 69% | 42% | 6% | 48% | 21% | ровный участок нужен и под следующий бросок | поверхность после двух планок |
| 3 | 6×4 | 24 | 7,2 | 63% | 34% | 2% | 45% | 21% | намеренно взять меньшее число, чтобы сохранить широкий участок | выбор решает почти каждый второй ход |
| 4 | 6×5 | 30 | 8,8 | 58% | 29% | 1% | 40% | 22% | держать два ровных участка под разные длины | длинная партия, ошибка всплывает через 2–3 хода |
| 5 | 6×6 | 36 | ~10 | 57% | 22% | 0% | 37% | 22% | всё вместе на полной высоте | эвристика выигрывает только каждую пятую партию |

«Выбор решает исход» — доля ходов, где лучшая и вторая по силе длина
расходятся по вероятности победы на 10 п.п. и больше. «Вынужденный ход» —
валидная позиция есть только у одной длины.

Разница между соседними уровнями:

- `1→2` — третий ряд: впервые важно, что останется после планки, а не только
  куда она ложится; эвристика падает с 56% до 42%.
- `2→3` — четвёртый ряд: ходов становится больше семи, и появляется ход
  «взять меньшее, чтобы сберечь ровный участок»; случайный игрок почти не
  выигрывает.
- `3→4` — пятый ряд: ошибка всплывает не сразу, а через 2–3 хода; нужно
  держать участки под разные длины одновременно.
- `4→5` — полная высота 6×6: самая длинная партия, эвристика выигрывает только
  22% — проверка гипотезы.

Замер «держи ровно» против идеального: уровень 3 — 54%, уровень 4 — 50%,
уровень 5 — 39%. «Бери длинное» замеряется при сборке.

**СЛЕДУЕТ.** Если эвристика не проходит kill-тест, это сигнал против идеи, а
не повод менять силуэт: силуэт остаётся прямоугольным (§1).

# 7. Обратная связь и обучение

- **Доступное действие:** три кубика внизу экрана крупные и нажимаемые. У
  кубика, чья длина никуда не ложится, пониженная яркость.
- **Валидные позиции:** после выбора кубика все ровные участки, куда
  помещается эта длина, подсвечены тонкой рамкой на уровне своей высоты.
- **Запрещённое действие:** планка над невалидной позицией полупрозрачная с
  красным контуром; отпущенная там — возвращается и покачивается.
- **Цена хода:** один бросок сыгран — два других числа уходят навсегда. Два
  невыбранных кубика при укладке уезжают за край экрана.
- **Победа:** последняя планка ложится, силуэт вспыхивает одним цветом,
  попап победы.
- **Поражение:** три кубика коротко покачиваются вместе, самый высокий
  ровный участок подсвечивается с подписью его ширины, попап проигрыша.
- **Payoff:** планка точно закрывает последний ровный участок ряда — ряд
  вспыхивает `300 мс`. Ввод разблокируется после вспышки.
- **Без текста игрок должен понять:** число на кубике — длина планки;
  планка ложится только на ровное место; остальные числа сгорают.

**Обучение — только попап «Как играть».** Пошагового онбординга нет. Попап
сам открывается при первом входе в уровень 1, дальше — по «?». Содержание:
картинка «кубик 3 → планка из трёх клеток → ровный участок» и четыре правила:

1. Выбери один из трёх кубиков — число равно длине планки.
2. Перетащи планку и отпусти над ровным участком.
3. Планка ложится только туда, где под ней нет ступенек.
4. Заполни фигуру целиком. Если ни одно число никуда не ложится — попытка
   проиграна.

Кнопка одна — «Понятно!».

   Кнопки: «Переиграть», «К уровням».
7. **Финальный попап после уровня 5.** Кубок, «Все уровни пройдены!».
   Кнопки: «Переиграть», «К уровням».

За секунду на игровом экране читаются: три числа, ровные участки и их
ширина, сколько рядов осталось. Payoff — на поле: ряд, закрытый точной
длиной, вспыхивает.

**Второй канал к цвету.** Механика на цвете не построена: длина читается по
числу точек на кубике и по числу клеток планки.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=75%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - на уровнях 3–5 эвристики «держи ровно» и «бери длинное» выигрывают не больше 60% от побед идеального игрока (§6)
    - минимум один игрок словами объясняет, почему взял не самое удобное сейчас число
  kill:
    - выполняется заранее записанный kill_criterion
```

Первое валидное действие — первая завершённая укладка планки. Выбор кубика
без укладки, открытие «?» и брошенное перетаскивание первым действием не
считаются. По нему считается `first_action_without_help`.

Для гипотезы в лог уровня пишутся на каждом ходу: три числа, выбранный
кубик, позиция, высоты столбцов до хода, число смен выбранного кубика до
укладки и время от появления броска до укладки.

- `optimal_choice_rate` — доля ходов, где выбранная длина совпала с лучшей по
  солверу, среди ходов, где выбор решает исход (разница ≥ 10 п.п.).
- `die_switches` — среднее число смен кубика до укладки: признак того, что
  игрок сравнивает варианты.
- `decision_ms` — медиана времени на ход; если она не растёт от уровня 1 к
  уровню 5, выбор скорее автоматический.
- `lost_by_dice` — доля проигрышей, где перед последним ходом у идеального
  игрока на той же поверхности шанс победы был меньше 10%: такой проигрыш
  решили кубики, а не игрок. Остальные проигрыши — `lost_by_choice`; по ним и
  судится гипотеза.

Метрики диагностические. Решение Gate 2 принимается по наблюдаемому
поведению и kill-критерию, а не по одному числу. Время хода только
записывается и на исход игры не влияет.

# Приложение A. Профиль реализации

**Фабрика.** `apps/roll-pack/`: веб-игра под браузер телефона, TypeScript +
Vite, без фреймворка, экран на HTML/CSS. Токены и шрифт подключаются из
`UI Design/` напрямую. Как запускать и публиковать — `apps/roll-pack/README.md`.

Броски — `Math.random()` или `crypto.getRandomValues()`, без зерна.

Солвер (точная вероятность победы по всем будущим броскам) считается при
сборке, а не во время игры. Для метрик §8 МОЖНО поставлять таблицу
вероятностей по поверхностям вместе с игрой: у поля 6×6 не больше `7⁶`
поверхностей.
