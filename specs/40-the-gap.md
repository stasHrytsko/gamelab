# 1. Граница прототипа

**Что проверяем.** Делает ли игрок на уровнях 3–5 возвраты из колб как часть
плана: вынимает верхний чужой квадрат, чтобы добраться до нужного, и освобождает
клетку выхода заранее, а не разбирает колбу по одной случайной ошибке.

**Минимальный цикл.** Поле со стенами и четырьмя выходами, четыре колбы разной
вместимости с перемешанным стартовым содержимым, свайп по квадрату (скольжение
до упора), тап по колбе (возврат), счётчик ходов с лимитом и звёзды. Вокруг цикла
главный экран, экран уровней и три попапа (§5, §7.1).

**Не делаем.** Отмену хода, подсказку решения, предупреждение «дальше не пройти»
(тупиков нет, §5), таймер, очки, бустеры, звук, настройки, магазин,
особые квадраты и особые клетки, два выхода на одной клетке, поля крупнее 4×3,
цвет в двух колбах на финише и бесконечный режим.

**Уровней пять.** Сгенерированы по `cfg + seed` и проверены солвером (§6). Два
обучающих, три с нарастающим числом обязательных возвратов. Открываются по
очереди.

**Почему kill-критерий такой.** Отличие от обычной пары «скольжение + сортировка»
только одно: возврат из колбы, который меняет решение на поле.
Если цвет можно раз и навсегда назначить колбе и вести квадраты по прямой, поле
и колбы решаются независимо, и подбором уровней это не лечится.
A/B-эксперимент (`ideas/backlog/40-the-gap.md`, «Результат A/B») показал: на
пустых колбах критерий срабатывает в 87,5% уровней, на колбах, заполненных
наполовину, только в 17,5%. Поэтому солвер отсекает такие уровни при генерации
(§6): без возвратов уровень нерешаем. Структурно критерий не выполнен, а
проверять надо игроков — используют ли они возвраты как план (§8).

# 2. Цель и основной цикл

Цель игрока — убрать все квадраты с поля так, чтобы каждый цвет лежал ровно в
одной колбе и каждая непустая колба была одноцветной, уложившись в лимит ходов.

Первое доступное действие — свайп по любому квадрату на поле.

```text
Выбрать колбу для цвета и посмотреть, что лежит сверху
→ достать верхний чужой квадрат тапом по колбе
→ увести его свайпом в свободное место или в другой выход
→ отправить нужный квадрат свайпом в свой выход
→ повторять, пока все цвета не соберутся по одному в колбах
→ результат: победа со звёздами или поражение по лимиту ходов
```

Условие завершения попытки — §5.

# 3. Объекты и состояние

| Объект | Идентификатор | Состояния | Изменения | Ограничения |
|---|---|---|---|---|
| Клетка поля | `(x, y)`, `x` — столбец слева направо, `y` — строка сверху вниз, от `(0,0)` | пустая, стена, занята квадратом | стена не меняется никогда; пустая ↔ занята | клетка-стена не бывает клеткой выхода |
| Квадрат | цвет `1..3` | на поле в клетке, в колбе на месте `i` | скользит, входит в колбу, выходит из неё | не более одного квадрата на клетку |
| Выход | номер `1..4` | не меняется | — | стоит в периметре поля, смотрит наружу; клетка выхода — периметровая клетка рядом со щелью; на одной клетке не более одного выхода; клетка выхода не стена |
| Колба | номер `1..4`, совпадает с номером выхода | пуста, содержит стопку квадратов | верхний квадрат добавляется или достаётся | вместимость `2..4`, задаётся уровнем; не больше вместимости |

Направление выхода — одно из `↑ ↓ ← →`: наружу от рамки поля. Выход у левой
стороны смотрит `←`, у верхней `↑` и т. д.

```ts
type Color = 1 | 2 | 3;
type Cell = 0 | -1 | Color;          // 0 пусто, -1 стена
type Exit = { x: number; y: number; dx: -1 | 0 | 1; dy: -1 | 0 | 1 };

type GameState = {
  field: Cell[];                     // w × h, индекс = y * w + x
  flasks: Color[][];                 // 4 стопки, снизу вверх
  moves: number;
  status: 'playing' | 'won' | 'failed';
  failReason: 'moves_exhausted' | 'no_moves' | null;
  stars: 0 | 1 | 2 | 3;              // считается при победе
};
```

Пространство игры — прямоугольная сетка `w × h`. Клетка адресуется парой
`(x, y)`. Внутри сетки скольжение идёт по строке или столбцу; поле не
замкнуто, выходы — единственные щели в рамке.

# 4. Ввод и правила

```ts
type Action =
  | { type: 'swipe'; x: number; y: number; dir: 'up' | 'down' | 'left' | 'right' }
  | { type: 'tap-flask'; n: 1 | 2 | 3 | 4 }
  | { type: 'restart' }
  | { type: 'open-help' }
  | { type: 'close-help' }
  | { type: 'exit-to-levels' };
```

Ввод — свайп по квадрату на поле и тап по колбе. Свайп определяется по
доминирующей оси смещения не меньше `24 px`; направление — сторона большего
смещения. Ход совершается при отпускании пальца (решение по ходу доработки
2026-09-29): пока палец ведёт квадрат, на поле виден призрак назначения (§7);
если палец вернули к квадрату ближе `24 px`, ход отменяется. Долгого нажатия,
отмены хода и тапа по квадрату на поле нет.

**Правила свайпа** — дословно как в `tools/the-gap-solver.mjs` (`moves`):

1. Квадрат движется по свайпу клетка за клеткой, пока следующая клетка внутри
   поля, свободна и не стена.
2. Достигнув последней клетки на пути, квадрат смотрит, есть ли на ней выход в
   направлении свайпа.
3. Если выход есть и в его колбе есть место, квадрат исчезает с поля и ложится
   верхним в колбу выхода.
4. Если выход есть, а колба полна, или выхода нет, квадрат остаётся на последней
   клетке пути.
5. Ход допустим, если квадрат сдвинулся хотя бы на одну клетку или ушёл в колбу.
   Квадрат, стоящий на клетке выхода, уходит в колбу свайпом к щели без
   единого шага, и это допустимый ход.
6. Выход срабатывает только когда квадрат упёрся в него скольжением. Квадрат,
   проехавший мимо чужого выхода вдоль рамки, в колбу не попадает.

**Правила тапа по колбе:**

7. Верхний квадрат колбы `n` выходит на клетку выхода `n`, если она свободна.
8. Если клетка выхода занята или колба пуста, ход не совершается.
9. Из колбы достаётся только верхний квадрат.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Свайп по квадрату | скользит хотя бы на клетку, выхода на конце нет | квадрат на новой клетке, `moves + 1` | квадрат скользит и упирается | да |
| Свайп по квадрату | доехал до выхода, в колбе есть место | квадрат в колбе сверху, `moves + 1` | квадрат въезжает в щель и ложится в колбу | да |
| Свайп по квадрату | доехал до выхода, колба полна | квадрат на клетке выхода, `moves + 1` | квадрат встаёт у щели, колба коротко мигает | да, если сдвинулся |
| Свайп по квадрату | упирается сразу, выхода нет | ничего | квадрат покачивается на месте `160 мс` | нет |
| Свайп по квадрату, стоящему на клетке выхода, к щели | в колбе есть место | квадрат в колбе, `moves + 1` | квадрат въезжает в колбу | да |
| Свайп мимо квадрата (по пустой клетке или по стене) | всегда | ничего | ничего | нет |
| Тап по колбе | не пуста, клетка выхода свободна | верхний квадрат на клетке выхода, `moves + 1` | квадрат выезжает из щели на клетку выхода | да |
| Тап по колбе | не пуста, клетка выхода занята | ничего | клетка выхода мигает красным `300 мс`, колба покачивается `160 мс` | нет |
| Тап по колбе | пуста | ничего | ничего | нет |
| Свайп или тап во время анимации хода | ввод заблокирован | ничего | ничего | нет |
| «Заново» | всегда | уровень в стартовое состояние, `moves = 0`, `status = playing` | поле как в начале | — |
| «?» | попапа нет | ввод заблокирован | попап «Как играть» | нет |
| «Понятно!» | попап открыт | `howToPlaySeen = true` | игра с того же места | нет |
| «К уровням» | всегда | попытка брошена | экран уровней | — |
| Любое действие на поле | `status !== 'playing'` или открыт попап | ничего | ничего | нет |

Недопустимое действие никогда не тратит ход.

# 5. Победа, поражение и переходы

**Победа.**

```text
Дано: на поле не осталось квадратов, в каждой непустой колбе лежит один цвет
и каждый цвет лежит ровно в одной колбе.
Когда: завершена обработка допустимого хода.
Тогда: status = won, считается stars, показывается попап победы.
```

**Поражение по ходам.**

```text
Дано: победа не наступила.
Когда: moves ≥ limit после допустимого хода.
Тогда: status = failed, failReason = moves_exhausted, показывается попап поражения.
```

**Поражение «нет ходов».**

```text
Дано: победа не наступила, moves < limit.
Когда: после хода нет ни одного допустимого свайпа и ни одного допустимого тапа по колбе.
Тогда: status = failed, failReason = no_moves.
```

Тупиков в игре нет: по эксперименту из идеи в позициях, достижимых из старта,
победа достижима всегда (доля проигранных позиций 0%). Поэтому предупреждения
«дальше не пройти» нет; проиграть можно только по ходам. На сгенерированных
уровнях `no_moves` не встречается (проверяется солвером, §6). Условие оставлено
на случай позиции из ручной правки.

**Звёзды** (`opt` — оптимум солвера в ходах, §6):

| Звёзды | Условие |
|---:|---|
| 3 | `moves ≤ opt + 2` |
| 2 | `moves ≤ ceil(1.5 × opt)` |
| 1 | победа в пределах `limit` |

`limit = ceil(2 × opt)`.

**Порядок проверок после допустимого хода:** завершить перемещение →
проверить, что не осталось квадратов на поле и колбы собраны → при победе
посчитать звёзды → проверить `moves ≥ limit` → проверить `no_moves` →
разблокировать ввод.

Коды причин поражения: `moves_exhausted`, `no_moves`.

Никакой случайности, влияющей на исход, в момент игры нет: уровень целиком
задаётся `cfg + seed` (§6).

# 6. Контент и кривая сложности

Схема уровня (данные лежат в `tools/the-gap-levels.json`):

```json
{
  "id": "TG-03", "seed": 6,
  "w": 4, "h": 3,
  "exits": [{ "x": 2, "y": 0, "dx": 0, "dy": -1 }],
  "caps": [3, 3, 4, 4],
  "field": [-1, 0, 0, 0, 0, -1, 0, 1, 0, 2, 0, 2],
  "flasks": [[], [1], [], [2, 1]],
  "opt": 10, "limit": 20, "stars3": 11, "stars2": 15
}
```

Уровень задаётся **правилом генерации** `cfg + seed`, а не координатами: тест
проверяет формулу. Генератор — `genLevel` в `tools/the-gap-solver.mjs`;
`seed` — наименьшее число от 1, при котором уровень проходит фильтры. Фильтры
(все обязательны):

1. Без возвратов уровень нерешаем.
2. В оптимальном решении не меньше `minRet` возвратов.
3. Оптимум в пределах `minOpt..maxOpt`.
4. Достижимое пространство состояний ≤ 250 000 (иначе солвер не считает).
5. В достижимом пространстве нет проигранных позиций.

| TG-02 | 4×3, 2 цвета × 3, 1 стена, вместимость 3 | 1 | 9 | 18 | 11 | 14 | 1 | 221 960 |
| TG-03 | 4×3, 2 цвета × 3, 2 стены, вместимость 3–4 | 6 | 10 | 20 | 12 | 15 | 2 | 150 460 |
| TG-04 | 3×3, 3 цвета × 2, 1 стена, вместимость 2–3 | 15 | 9 | 18 | 11 | 14 | 2 | 244 080 |

### Уровень 1 — TG-01, обучающий

Поле 3×3 без стен, два цвета по два квадрата, вместимость колб 2. Два квадрата
`2` на поле, два `1` в разных колбах: цвет уже разбит на две колбы, и их надо
собрать в одной. Функция: игрок сам
понимает, что квадрат скользит и падает в щель. Ожидаемый сложный момент —
достать квадрат из колбы, чтобы собрать цвет в одной.

### Уровень 2 — TG-02

Поле 4×3, одна стена, два цвета по три квадрата, вместимость колб 3.
Функция: закрепляет скольжение и возврат без нового исключения; возвратов
нужно минимум один.

### Уровень 3 — TG-03, первый настоящий выбор

Две стены, вместимость колб 3–4 (разная). В колбе 4 лежат два цвета друг на
друге (`[2, 1]` снизу вверх). Функция: впервые нужно два возврата; разумных планов, по замыслу, несколько
(число планов солвер пока не считает). Ожидаемый сложный момент — вынуть `1` сверху колбы 4,
не заблокировав клетку выхода, которая понадобится для `2`.

### Уровень 4 — TG-04

Поле сжато до 3×3 с одной стеной, но цветов три (по два квадрата), вместимость
колб 2–3. Колбы стартуют так: `[1]`, `[1, 2]`, две пустые. Функция: комбинирует
правила под давлением — три цвета на четыре колбы оставляют одну свободную
колбу-буфер, и её надо использовать. Ожидаемый сложный момент — решить, какой
цвет уходит в пустую колбу, чтобы не запереть клетку выхода другой колбы.

### Уровень 5 — TG-05, проверка гипотезы

Поле 4×3, три стены, три цвета, вместимость колб 2–3. Колба 1 стартует с
тремя цветами сразу: `[2, 3, 1]` снизу вверх, в колбе 4 лежит `[3]`, на поле
два квадрата. Оптимум 16 ходов, лимит 32. Функция: проверяет гипотезу —
чтобы добраться до `2` на дне колбы 1, надо вынуть два чужих квадрата подряд и
куда-то их деть, не заблокировав клетку выхода 1. Возвратов минимум два, при
этом оптимум 16 почти вдвое длиннее, чем на уровнях 3–4, а значит, плану есть
где разойтись; проверяется игроками (§8).

### Сводка разниц между уровнями

- **1→2:** поле больше, появляется стена, оптимум 7 → 9.
- **2→3:** две стены вместо одной, колбы разной вместимости, содержимое одной
  колбы перемешано, возвратов минимум два.
- **3→4:** появляется третий цвет и свободная колба-буфер; поле меньше
  (3×3), вместимость 2–3 вместо 3–4, оптимум 10 → 9.
- **4→5:** поле снова 4×3, три стены вместо одной, одна колба сразу с тремя
  цветами, оптимум 9 → 16.

Решаемость проверяется солвером на этапе генерации (фильтр 1–5 выше).

# 7. Обратная связь и обучение

**Как читается доступное действие.** Любой квадрат можно свайпнуть. Колба, из
которой можно достать квадрат, слегка приподнята; если клетка выхода занята,
колба серая.

**Как показывается запрещённое действие.** Тап по колбе с занятой клеткой
выхода: клетка выхода мигает красным `300 мс` (`--ui-danger`), колба
покачивается `160 мс`. Свайп в упор: квадрат покачивается `160 мс`.

**Цена хода** (решение по итогам проверки по формуле «интересных решений»,
2026-09-29). Пилюля «Ходы `k / лимит`» над полем. Рядом три звезды и порог
трёх звёзд (`≤ opt + 2`); звезда гаснет, когда `moves` достиг её порога и
победа за меньшее число ходов уже невозможна. Под пилюлями полоска запаса
ходов: заливка растёт с `moves / limit`, зелёная до порога трёх звёзд, жёлтая
до порога двух, коралловая дальше; на полоске две метки порогов. Каждый лишний
ход виден как расход запаса.

**Цели.** Под полоской счётчики цветов: значок цвета и `k/N`, где `k` — сколько
квадратов цвета лежит в одной одноцветной колбе, `N` — сколько их всего. Когда
`k = N`, счётчик получает зелёную обводку и галочку. Победа = все счётчики
закрыты и поле пусто.

**Призрак назначения.** Пока квадрат ведут, пунктирный контур показывает, где он
остановится; если он упадёт в колбу, контур сплошной, а колба выделена синей
обводкой. Так последствие свайпа видно до хода.

**Итог уровня.** Экран победы: звёзды, «`moves` ходов, образец — `opt`, лишних:
`k`», «Новый рекорд!», если результат лучше прежнего, и «С образцом разошлись на
ходу `n`» — номер первого хода, где путь игрока впервые отличается от
сохранённого образца (это не приговор: у уровня бывает несколько оптимальных
решений). Экран проигрыша показывает то же расхождение. Кнопка **«Разбор»**
(на экране победы, если счёт хуже образца; на экране проигрыша всегда) ведёт на
`#/level/N/demo`: образец проигрывается сам с паузой `850 мс`, ввод закрыт,
вверху плашка «Образец: ход `k` из `opt`», в конце попап «Играть» / «К уровням».
Разбор не тратит попытки и не меняет прогресс. Он показывает решение только
после того, как игрок сам закончил или проиграл уровень; заранее игра решение не
показывает и проигрыш не предсказывает.

**Лучший результат.** У пройденного уровня на карточке экрана уровней вместо
«N квадратов · M ходов» показаны лучшие звёзды и ходы. Рекорд — больше звёзд или
столько же за меньшее число ходов.

**Победа и поражение.** Победа: последняя колба закрывается, звёзды
проявляются по одной с задержкой `200 мс`, через `600 мс` попап. Поражение:
попап с кнопкой «Заново».

**Payoff.** В момент закрытия колбы (все квадраты одного цвета, вместимость
заполнена или цвет собран целиком) колба мягко светится `400 мс`. Три звезды
загораются на пилюле.

**Чему игрок учится без текста:** квадрат скользит до упора; в щель попадает
тот, кто в неё упёрся; колбу можно разобрать обратно.

**Подсказка «?»** — три строки: скольжение до упора, тап по колбе достаёт
верхний квадрат, звёзды за ходы. Не пошаговое обучение.

**Онбординг** (как собрано, решение по ходу сборки 2026-09-29): 1) попап «Как
играть?» открывается сам при первом входе на уровень 1; 2) на уровнях 1–2
внизу карточка-подсказка про свайп и тап по колбе; 3) на уровнях 3–5
подсказок нет, кроме «?». Выделения «единственного подходящего свайпа» на
уровне 1 нет.

**Анимации.** Скольжение — `80 мс` на клетку, не больше `320 мс` на ход.
Въезд в колбу и выезд из неё — по `220 мс`. Ввод заблокирован до конца
анимации хода.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=70%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - на уровнях 3–5 без возвратов уровень нерешаем (проверка солвером, §6)
    - на уровнях 3–5 минимум половина победивших делает два и более возвратов
    - минимум один игрок словами объясняет план с возвратом ("достану верхний, чтобы освободить...")
  kill:
    - выполняется заранее записанный kill_criterion
    - на уровнях 3–5 меньше 10% ходов победивших — возвраты (возврат нужен как исправление, а не как план)
```

Первое валидное действие — первый допустимый ход на уровне 1. По нему
считаются `first_action_without_help` и `onFirstAction()`.

В лог на каждый ход пишутся: уровень, номер попытки, номер хода, тип хода
(`swipe`, `return`), совпал ли ход с сохранённым оптимальным решением
(`onSolution`: все ходы попытки до этого тоже совпали), сколько возвратов уже
сделано, время от предыдущего хода. Солвера в игре нет, поэтому «оптимальность»
хода считается по одному сохранённому решению уровня, а не по всем
оптимальным.

- `return_share` — доля возвратов среди ходов на уровнях 3–5.
- `on_solution_return_share` — доля возвратов, которые совпали с сохранённым решением.
- `stars_by_level` — распределение звёзд.
- `attempts_to_win` — попыток до победы на уровне.
- `think_before_return` — пауза перед возвратом против медианы пауз игрока.

**Как отделить план от случайной ошибки.** Возврат-план: игрок тапает колбу
после паузы длиннее обычной, и ход совпал с сохранённым решением уровня. Возврат-исправление:
его делают сразу после отправки в колбу, тем же квадратом, без паузы. Если на
уровнях 3–5 большинство возвратов — исправления, это kill.

Метрики диагностические. Решение Gate 2 — по наблюдаемому поведению и
kill-критерию.

# Приложение A. Профиль реализации

**Фабрика.** `apps/the-gap/` (папка по slug): веб-игра под браузер телефона,
TypeScript + Vite, без фреймворка, экран на HTML/CSS. Токены и шрифт — из
`UI Design/`. Устройство как у `apps/build-pack`.

Правила хода — порт `moves` из `tools/the-gap-solver.mjs` (`src/engine/gapEngine.ts`).
Тесты прототипа:

- `tests/parity.test.ts` — на случайных партиях из старта каждого уровня допустимые
  ходы и их результаты совпадают с `moves` солвера клетка в клетку;
- `tests/levels.test.ts` — сохранённое решение каждого уровня проходит через
  движок и побеждает ровно за `opt` ходов с тремя звёздами; лимит и пороги звёзд
  считаются по формулам §5; **kill-критерий в форме теста**: без возвратов
  уровень нерешаем (полный обход состояний без возвратов не содержит победы);
  копия уровней в `apps/the-gap/src/levels/levels.json` совпадает с
  `tools/the-gap-levels.json`.

Уровни лежат в `tools/the-gap-levels.json` и собираются командой
`node tools/the-gap-solver.mjs build TG-01=1 TG-02=1 TG-03=6 TG-04=15 TG-05=2`
(`cfg + seed` → уровень, фильтры §6, оптимальное решение). Решаемость наперёд
в игре не считается, солвера в игре нет; в лог ходит только «совпал ли ход с
сохранённым решением».
