# 1. Граница прототипа

1. **Что проверяем.** Тратит ли игрок монеты осмысленно: часть ходов кладёт
   фигуру как есть и копит, часть платит за удобство, и ни одна покупка не
   съедает почти всех трат.
2. **Минимальный цикл.** Поле 8×8, три фигуры на руках с выбором любой,
   линии по строкам и столбцам с доходом `n²`, три покупки (поворот, зеркало,
   замена), кошелёк с потолком, пять уровней с целью по линиям.
3. **Не делаем:** пересдачу и платный сброс (в «Идеях на будущее» идеи), мету,
   магазин за реальные деньги, рекламу, бесконечный режим, перенос монет между
   уровнями, отмену хода, звук, показ следующих фигур.
4. **Уровней пять.** Хватает, чтобы увидеть, как меняется трата монет при
   росте цели, числа камней и неудобства.

**Почему kill-критерий такой.** Пустой кошелёк в последней трети говорит, что
монет не хватает на решения именно там, где они нужны, и остаток уровня
играется без выбора. Одно действие на 70% трат говорит, что остальное меню
мёртвое, и «рынок» превратился в одну кнопку. Оба признака про экономику идеи,
а не про то, что уровни плохо подобраны: их можно проверить на любом уровне.

# 2. Цель и основной цикл

- **Цель игрока:** за 20 фигур собрать на уровне заданное число линий.
- **Первое доступное действие:** перетащить любую из трёх фигур на поле.
- **Цикл:**

```text
Выбрать одну из трёх фигур на руках
→ при желании заплатить за поворот, зеркало или замену
→ поставить фигуру на поле
→ полные строки и столбцы исчезают и платят монеты
→ на место фигуры встаёт новая
→ проверить конец уровня
```

- **Конец попытки:** раздел 5.

# 3. Объекты и состояние

| Поле | Смысл |
|---|---|
| Клетка поля | `0` пусто, `1–5` цвет фигуры, `9` камень |
| Фигура | тип из каталога, ориентация, цвет по типу |
| Рука | до трёх фигур; порядок мест не меняется |
| Кошелёк | целое от `0` до `10` |
| Уровень | цель, число камней, неудобство, зерно |

Изменения: клетка меняется постановкой фигуры и очисткой линий; фигура на
руке меняется поворотом, зеркалом, заменой, постановкой; кошелёк — доходом,
покупкой. Ограничения: камень не исчезает иначе как в очищенной линии;
фигура ставится только на пустые клетки внутри поля.

Каталог: 23 фигуры — моно, домино, две трёхклеточных, семь тетромино, двенадцать
пентомино. Цвет — по номеру типа, второй канал цвета — сама форма. Цена замены
— базовая цена типа плюс `2`, всего `5–8`.

```ts
type GameState = {
  level: number;            // 1..5
  goal: number;
  board: number[];          // 64 клетки, ряд за рядом
  hand: Piece[];            // до трёх фигур
  used: number;             // сыграно или сгорело, 0..20
  dealIdx: number;          // сдано фигур, 0..20
  lines: number;
  coins: number;            // 0..10
  status: 'playing' | 'won' | 'lost';
};
```

**Пространство:** сетка 8×8, клетка адресуется парой (столбец, ряд) от левого
верхнего угла; фигура — координатами левого верхнего угла её описывающего
прямоугольника.

# 4. Ввод и правила

```ts
type Action =
  | { type: 'select'; slot: number }                    // тап по фигуре
  | { type: 'place'; slot: number; x: number; y: number } // перетащить и отпустить
  | { type: 'rotate'; slot: number }                    // кнопка «Поворот 90°»
  | { type: 'mirror'; slot: number }                    // кнопка «Зеркало»
  | { type: 'swap'; slot: number; piece: PieceType };   // «Замена» → фигура → «Взять»
```

Долгого нажатия нет, отмены нет, двойного тапа нет. Перетаскивание начинается
от фигуры на руке; тап без сдвига только выбирает фигуру (на неё действуют
покупки). Шторку «Замена» можно закрыть без покупки.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Поставить | все клетки фигуры пусты и внутри поля | клетки заняты, полные строки и столбцы очищены одновременно, `coins += min(n², место в кошельке)`, `lines += n`, `used += 1`, на место фигуры встаёт новая (пока сдано меньше 20, иначе место исчезает) | фигура встаёт, линии исчезают волной, всплывает «+N» | да |
| Поставить | клетка занята или фигура за краем | без изменений | фигура возвращается на руку, поле качается | нет |
| Отпустить мимо поля | всегда | без изменений | фигура возвращается | нет |
| Повернуть | `coins ≥ 2`, форма после поворота отличается | фигура на 90° по часовой, `coins -= 2` | фигура поворачивается | нет |
| Повернуть | `coins < 2` или форма не меняется (квадрат, крест) | без изменений | кнопка качается, подсказка называет причину | нет |
| Зеркало | `coins ≥ 2`, форма отличается | отражение слева направо, `coins -= 2` | фигура отражается | нет |
| Зеркало | `coins < 2` или форма не меняется | без изменений | как выше | нет |
| Замена | `coins ≥ цена выбранной`, выбранная не совпадает с текущей в исходной ориентации | на месте фигуры выбранная в исходной ориентации, `coins -= цена` | новая фигура появляется на месте | нет |
| Замена | не хватает монет | без изменений | фигура в шторке приглушена, тап качает её | нет |
| Выбрать фигуру | место занято фигурой | меняется выбранное место | фигура подсвечена | нет |

**Ход** — это постановка. Покупки ход не тратят, но тратят монеты. Повтор
того же действия допустим, пока хватает монет. Две фигуры в одной клетке
невозможны: постановка на занятую клетку отклоняется.

# 5. Победа, поражение и переходы

```text
Дано: сыграно или сгорело 20 фигур, линий собрано не меньше цели.
Когда: завершена обработка последнего действия.
Тогда: статус won, уровень отмечается пройденным, открывается следующий.
```

```text
Дано: сыграно или сгорело 20 фигур, линий меньше цели.
Когда: завершена обработка последнего действия.
Тогда: статус lost с причиной goal_missed.
```

```text
Дано: ни одной фигуре на руке некуда встать и никакая покупка за имеющиеся
монеты не поможет (ни поворот, ни зеркало, ни замена с последующим поворотом).
Когда: завершена обработка любого действия, после которого это верно.
Тогда: левая фигура на руке сгорает бесплатно, used растёт на 1, на её место
встаёт новая; проверка повторяется.
```

**Порядок проверок после действия:** применить действие → очистить линии и
начислить доход (только для постановки) → сдать новую фигуру на место →
сжечь фигуры, которым некуда встать → проверить конец уровня (после 20-й).

**Коды причин поражения:** `goal_missed`. Других поражений нет: тупик
разрешается сгоранием фигуры.

**Случайность.** Руку и камни определяет зерно уровня и порядок действий
игрока; две попытки, в которых игрок делает одно и то же, дают одно и то же.
Внешней случайности нет. Косметическая случайность (дрожание, вариации
анимации) не влияет на исход.

# 6. Контент и кривая сложности

```ts
type LevelDef = { id: number; goal: number; stones: number; hostileK: number; mix: number; seed: number };
```

**Способ А:** пять уровней перечислены; зерно фиксировано.

| Уровень | Линий за 20 фигур | Камней | Из скольких выбирается неудобная | Набор фигур (`mix`) | Зерно |
|---:|---:|---:|---:|---:|---:|
| 1 | 4 | 3 | 2 | 1 | 101 |
| 2 | 5 | 5 | 3 | 3 | 202 |
| 3 | 6 | 7 | 3 | 5 | 303 |
| 4 | 7 | 9 | 4 | 8 | 404 |
| 5 | 8 | 11 | 5 | 11 | 505 |

**Сдача.** Каждым вторым ходом (счёт с нуля) из `hostileK` случайных кандидатов
берётся та фигура, которая как есть ложится на поле в меньшее число мест;
остальные фигуры случайные. Типы выбираются по весу: мелочь 0.8, тетромино 3,
лёгкие пентомино `0.6 + 0.2·mix`, сложные `0.4 + 0.5·mix`. Двух одинаковых
типов на руке нет. Валидность уровня: камни никогда не образуют готовую
линию.

| Уровень | Новое решение | Давление | Ожидаемо сложное |
|---:|---|---|---|
| 1 | сам понять, что фигуру тянут на поле и что монеты за линии | мало камней, цель 4 | первая покупка: зачем платить, если место есть |
| 2 | закрепить правило; монет уже нужно беречь | цель 5, кандидатов 3 | палка и П-образная фигура рядом с камнями |
| 3 | впервые настоящий выбор: заплатить сейчас или копить | цель 6, камней 7 | рука без удобной фигуры |
| 4 | сочетать поворот с заменой под давлением | цель 7, камней 9 | нужна двойная очистка, чтобы окупить траты |
| 5 | проверка гипотезы: без осмысленных трат цели не достичь | цель 8, камней 11, сложных фигур больше всего | ни одной подходящей фигуры и мало монет |

Разница между уровнями:

- **1→2:** цель на линию выше, камней на два больше, кандидатов для неудобной
  фигуры три вместо двух; закрепляет правило без нового исключения.
- **2→3:** камней ещё на два больше и набор фигур смещён к сложным (`mix` 3→5):
  теперь на руке чаще нет удобной фигуры, и покупка становится вопросом
  «сейчас или потом».
- **3→4:** цель 7 при 9 камнях и четыре кандидата: без двойной очистки монет
  не хватает на повороты и замены.
- **4→5:** `mix` 8→11 и пять кандидатов: рука почти всегда плохая; центральная
  гипотеза проверяется напрямую.

**Решаемость.** Солвера нет (`solver: none`), решаемость уровней не доказана.
Цели подобраны прикидкой, их надо проверить на живых людях; правило для
выхода из тупика (сгорание) не даёт уровню зависнуть.

# 7. Обратная связь и обучение

- **Доступное действие:** три фигуры на руках, выбранная подсвечена синим;
  при перетаскивании на поле показывается тень, куда фигура ляжет, и рамкой
  линии, которые закроются; в подсказке внизу «Закроет N линии и вернёт M монет».
- **Запрещённое действие:** фигура возвращается на руку, поле качается 320 мс,
  вибрация 20–30 мс; кнопка покупки без денег или без эффекта качается, в
  подсказке причина.
- **Цена хода:** на кнопках цены с монетой; в шторке цены на каждой фигуре;
  что не по карману — приглушено.
- **Верх экрана:** три плашки. Фигуры: сколько показано из 20 и сколько
  осталось показать. Линии: сколько собрано из цели и сколько ещё нужно (цель
  набрана — зелёная рамка). Монеты: сколько из 10 (кошелёк полон — жёлтая
  рамка).
- **Победа и поражение:** попап через 520 мс после последнего хода при победе,
  через 900 мс при поражении; при победе кнопки «Следующий уровень»,
  «Переиграть», «К уровням»; после пятого уровня финальный попап с кубком.
- **Payoff:** линии исчезают волной от поставленной фигуры за 300 мс с задержкой
  `28 мс × расстояние в клетках`, всплывает «+N» с монетой; при двойной очистке
  вибрация двойная.
- **Чему учится без текста:** тянуть фигуру на поле, что монеты приходят из
  линий, что кнопки стоят монет.
- **Подсказка «?»:** только правила из онбординга, без советов.
- **Онбординг (открывается сам на первом входе в уровень 1):**
  1. Выбери любую из трёх фигур и перетащи на поле; полная строка или столбец
     исчезает и платит 1, 4, 9 монет за 1, 2, 3 линии сразу.
  2. За монеты можно повернуть, отзеркалить или заменить выбранную фигуру; в
     кошельке до 10.
  3. На уровне 20 фигур; сверху видно, сколько показано и сколько линий ещё
     нужно.
  4. Если ни одной из трёх некуда встать и никакая покупка не поможет, одна
     фигура сгорает.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=70%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - у игроков есть ходы и с покупкой, и без неё
    - не меньше трёх видов трат, ни одно действие не выше 70% трат у половины игроков
  kill:
    - выполняется заранее записанный kill_criterion
```

**Первое валидное действие:** первая принятая постановка фигуры на поле.

**Метрики из лога** (`localStorage['block-market:log']`, события `place`,
`buy`, `buy_refused`, `level_win`, `level_fail`):

- доля ходов с кошельком меньше 2 в последней трети уровня (`turn` ≥ 14);
- доля потраченных монет по видам покупок для каждого игрока;
- доля ходов с покупкой и без;
- на каком уровне игрок остановился и почему (победа, `goal_missed`).

Общее правило проверки на игроках — `results/gate2.md`.

# Приложение A. Профиль реализации

**Фабрика.** `apps/block-market/`, по `apps/CLAUDE.md`: веб-игра под браузер
телефона, TypeScript + Vite, без фреймворка, экран на HTML/CSS. Токены и
шрифт — из `UI Design/`. Плитки — элементы DOM с градиентом от `--c`.

**Движок** — `src/engine/engine.ts`: чистые функции `startLevel`, `place`,
`rotatePiece`, `mirrorPiece`, `swapPiece`, `rescuable`; каждая возвращает
`{ state, event }` или `null` для недопустимого действия. Числа — в
`src/engine/config.ts` и `src/levels/levels.ts`.

**Связь с симулятором.** `tools/block-market-sim.mjs` считал экономику по
предыдущей версии правил (очередь, потолок 10, 12 уровней, пересдача). Тест
`tests/engine.test.ts` сверяет с ним общие константы и сдачу фигур на одном
зерне; правила рук и покупок в симуляторе не отражены, его цифры к текущей
версии не относятся.

**Тесты.** `tests/engine.test.ts` покрывает правила из разделов 4–6:
постановку, очистку, доход, потолок, покупки, сгорание, конец уровня, сдачу и
инварианты на случайных партиях. `e2e/play.spec.ts` проходит путь игрока:
главный → уровни → уровень 1 → победа → уровень 2, поражение и «Переиграть»,
финал после пятого уровня, отсутствие прокрутки на 360×560, 375×560, 390×664,
430×932.

**Параметры адреса для проверки:** `unlock=all`, `seed=N`, `goal=N`.
