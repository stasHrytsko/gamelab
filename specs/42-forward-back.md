# 1. Граница прототипа

**Что проверяем.** Думает ли игрок о позиции героя после взятия: берёт ли он
сознательно меньшую линию, чтобы следующий шаг снова что-то убрал.

**Минимальный цикл.** Поле 5×5, один герой, неподвижные враги, лимит ходов.
Тап по врагу или клетке — шаг и взятие. Предпросмотр по удержанию, отмена
хода. Вокруг цикла главный экран, уровни, игровой экран и попапы (§7.1).

**Не делаем.** Цепочки взятий за один ход (как в настоящей Фанороне),
диагонали, нейтральные ящики, стены и дыры на поле, звёзды, очки, таймер,
звук, подсказку решения, предупреждение «уровень уже не пройти»,
бесконечный режим.

**Уровней пять.** Все открыты сразу — для тестов на игроках (решение автора
2026-10-02). `?lock=1` в адресе включает открытие по очереди.

**Откуда эта версия.** Источник — правило захвата Фанороны: приближение и
отступление бьют по разным линиям. Первая сборка (2026-10-01) называла режимы
«вперёд/назад» и выбирала вариант кнопками внизу. По замечаниям автора
2026-10-02: один тап на ход, подсветка тех, кого уберёт ход, затем — «шёл
вверх, а удалились снизу — нелогично». Отсюда метафора толчка и рывка с цепью,
предпросмотр по удержанию, отмена хода и обучение по одному правилу (решения
автора 2026-10-02).

# 2. Цель и основной цикл

Цель игрока — убрать с поля всех врагов, не превысив лимит ходов.

Первое доступное действие — тапнуть врага (или соседнюю с героем клетку).

```text
Тап по врагу (или прижать палец и отпустить)
→ герой шагает на соседнюю клетку
→ убирается цепочка врагов: толчок — перед новой клеткой, рывок — позади старой
→ счётчик ходов +1
→ проверка победы и поражения по §5
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Клетка поля | пустая; герой; враг | герой уходит и приходит; враг исчезает при взятии | поле 5×5, стен и дыр нет |
| Герой | на клетке | шаг на соседнюю клетку по горизонтали или вертикали | ровно один; ходит только на пустую клетку внутри поля |
| Враг | на поле; убран | убирается толчком или рывком | неподвижен; не появляется заново (кроме отмены хода) |
| Уровень | открыт; пройден | пройден победой | по умолчанию все открыты |

**Пространство.** Клетка адресуется `row` (сверху вниз, 0–4) и `col`
(слева направо, 0–4). Шаг — в одном из четырёх направлений `^ > v <`.

**Линия.** Подряд стоящие враги в одном направлении, начиная с заданной
клетки; линия обрывается на пустой клетке или краю поля.

- **Толчок** (`forward`): линия от клетки сразу за новой клеткой героя, по
  направлению шага.
- **Рывок** (`back`): линия от клетки сразу за старой клеткой героя, против
  направления шага.

```ts
type Dir = '^' | '>' | 'v' | '<';
type Mode = 'forward' | 'back' | 'none';
type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  hero: { row: number; col: number };
  enemies: { id: string; row: number; col: number }[];
  moves: number;
  moveLimit: number;
  status: 'playing' | 'won' | 'failed';
  failReason: 'moves_exhausted' | 'no_moves' | null;
};
// История для отмены — стек предыдущих GameState в пределах попытки.
// Хранится на устройстве между запусками:
type Progress = { passed: number[]; howToPlaySeen: boolean };
```

# 4. Ввод и правила

**Правило хода.** Шаг на соседнюю пустую клетку. Если с этого шага доступна
хотя бы одна линия, нужно взять одну из них (`forward` или `back`); просто
шагнуть нельзя. Если обе пусты — обычный шаг (`none`). Любой шаг стоит один ход.

**Однозначность тапа по врагу.** Каждого врага убирает не больше одного хода:
линия толчка начинается через клетку от героя, линия рывка — вплотную, и по
каждому направлению линия одна. Поэтому тап по врагу однозначно задаёт шаг и
вид взятия. Проверено тестом на случайных расстановках.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Прижать палец к врагу | его убирает какой-то ход | ничего | призрак героя на клетке шага; враги этой линии дрожат в кольце (зелёное — толчок, жёлтое — рывок); при рывке цепь от героя к первому врагу | нет |
| Отпустить палец над тем же врагом | — | ход по правилу, дальше §5 | анимация хода (§7) | да |
| Увести палец на клетку без хода и отпустить | — | ничего | предпросмотр гаснет | нет |
| Прижать и отпустить соседнюю пустую клетку | доступен ровно один вариант | ход этим вариантом | анимация хода | да |
| То же | доступны и толчок, и рывок | ничего | подсказка «Отсюда можно и толкнуть, и утянуть. Тапни врага, которого хочешь убрать.» | нет |
| Тап по врагу, которого не убрать | — | ничего | враг покачивается 160 мс, вибрация | нет |
| Тап по пустой клетке не рядом с героем | — | ничего | герой покачивается | нет |
| «Отменить» | есть история, нет анимации | `state` = предыдущий из стека | враги возвращаются с коротким появлением, герой на прежней клетке | ход возвращается |
| «Заново» | всегда | уровень с начала, история пуста | — | — |
| «?» | нет анимации и попапа | ввод заблокирован | попап «Как играть» | нет |
| Любое действие на поле | идёт анимация, открыт попап или `status !== 'playing'` | ничего | ничего | нет |

# 5. Победа, поражение и переходы

Порядок проверок после хода: убрать линию → `moves + 1` → врагов нет? победа
→ `moves >= moveLimit`? поражение `moves_exhausted` → у героя нет пустой
соседней клетки? поражение `no_moves` → вернуть ввод.

```text
Дано: на поле один враг, он в линии толчка; остался один ход.
Когда: игрок делает этот толчок.
Тогда: status = won (победа на последнем ходу — победа, а не поражение).
```

```text
Дано: ходов не осталось, враги на поле.
Когда: сделан последний ход без победы.
Тогда: status = failed, failReason = moves_exhausted; враги мигают, через
       900 мс попап «Ходы закончились».
```

```text
Дано: герой зажат врагами и краем.
Когда: ход закончился.
Тогда: status = failed, failReason = no_moves; попап «Ходов нет».
```

```text
Дано: доступны и толчок, и рывок.
Когда: попытка сделать шаг без взятия.
Тогда: ход недопустим, состояние не меняется.
```

**Игра не предсказывает проигрыш.** Решаемость наперёд не считается: игрок
доигрывает, пока есть ходы (правило студии, `apps/CLAUDE.md` §3).

**Отмена хода без ограничений**, в том числе из попапа поражения: «Отменить
ход» возвращает последний ход и снова `status = playing` (решение автора
2026-10-02). Отмена не прячет поражение: попап всё равно показывается.

**Переходы.** Главный → уровни → игровой экран. Попап победы: «Следующий
уровень», «Переиграть», «К уровням». Попап поражения: «Отменить ход»,
«Переиграть», «К уровням». После уровня 5 — финальный попап: «Переиграть»,
«К уровням». Коды причин стабильны: `moves_exhausted`, `no_moves`.

**Случайности нет.** Всё задано уровнем.

# 6. Контент и кривая сложности

Обозначения: `H` — герой, цифры — id врагов, `.` — пусто. Уровни 1–3
обучающие, по одному правилу за раз: лимит = оптимум + 2, жадная стратегия
решает. Уровни 4–5 — ловушки, подобраны солвером (`tools/gen-levels.ts`):
лимит = оптимум, жадная стратегия «всегда бери самую длинную линию» не решает.
Всё это проверяет `tests/levels.test.ts`.

**Уровень 1 — FB-T1, только толчок.** Лимит 4, оптимум 2. Рука-подсказка на
враге 0.

```text
. . 2 . .
. . . . .
. H . 0 1
. . . . .
. . . . .
```
Решение: вправо, толчок ×2 → вверх, толчок ×1.

**Уровень 2 — FB-T2, только рывок.** Лимит 4, оптимум 2.

```text
. . . . .
3 2 . . .
. . H . .
. . 0 . .
. . 1 . .
```
Решение: вверх, рывок ×2 → вправо, рывок ×2.

**Уровень 3 — FB-T3, впервые оба на одном шаге.** Лимит 4, оптимум 2.

```text
. . . . .
. . . . .
0 1 H . 2
. . . . .
. . . . .
```
Шаг вправо даёт выбор: толкнуть 2 или утянуть 0–1.

**Уровень 4 — FB-01, ловушка.** Лимит 5 = оптимум, 4 оптимальных решения.

```text
0 H . 4 .
1 . . 5 .
. 2 . . .
. 3 . . .
. . . . .
```
Одно из решений: вправо, толчок ×1 → влево, толчок ×1 → вниз, толчок ×2 →
вправо, толчок ×1 → влево, толчок ×1.

**Уровень 5 — FB-03, ловушка, проверяет гипотезу напрямую.** Лимит 6 =
оптимум, решение единственное.

```text
. . . 1 .
. 0 H . 2
. . . . 3
. . 4 5 6
. . . . .
```
Решение: вправо, толчок ×1 → вниз, рывок ×1 → влево, рывок ×1 → влево, шаг →
вниз, рывок ×1 → влево, рывок ×3.

Разница между соседними уровнями: 1 → 2 новое правило; 2 → 3 выбор на одном
шаге; 3 → 4 лимит без запаса; 4 → 5 единственное решение с рывками и пустым
шагом.

# 7. Обратная связь и обучение

**Метафора.** Толчок — герой бьёт, линия отлетает вперёд (на 0,4 клетки) и
лопается. Рывок — от героя к первому врагу сзади выстреливает жёлтая цепь
(140 мс), герой шагает (170 мс), и вся линия едет за ним на цепи, затем
лопается. Враги исчезают от героя наружу, 230 мс каждый, шаг 70 мс.

**Метки на клетках шага:** шеврон по направлению шага и число — толчок
(зелёный); крюк и число — рывок (жёлтый); точка — обычный шаг. Цвет — второй
канал, значок — первый.

**Предпросмотр по удержанию** — §4. Постоянной подсветки врагов нет: она не
связывала клетку с врагами и делала поле пёстрым (решение автора 2026-10-02).

**Обучение.** Уровень 1: рука «прижми палец» над врагом до первого касания.
Подсказка внизу у каждого обучающего уровня своя (`tip` в данных уровня).
«Как играть» открывается сам при первом входе в уровень 1: картинка и 4
правила.

**Недопустимое действие** — покачивание 160 мс и короткая вибрация, ход не
тратится. **Победа** — волна по полю, попап через 700 мс. **Поражение** —
враги мигают, попап через 900 мс. `prefers-reduced-motion` — анимации почти
нулевые, состояние то же.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 8-12
  success:
    first_action_without_help: ">=80%"
    pull_understood_after_level_2: ">=75%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - на уровнях 4–5 жадная стратегия не решает уровень (проверка солвером)
    - на уровнях 4–5 игроки хотя бы раз берут меньшую линию при доступной большей
    - минимум один игрок словами объясняет выбор позицией героя
  kill:
    - выполняется заранее записанный kill_criterion
```

Лог хода (`localStorage['forward-back:log']`): направление, вид взятия,
сколько убрано, был ли настоящий выбор (`choice`), взята ли меньшая линия
(`tookLess`), время с прошлого хода. Также `undo`, `preview_cancel`,
`help_open`, `level_win`, `level_fail` с кодом причины.

- `tookLess` на уровнях 4–5 — прямой ответ на гипотезу.
- `undo` и `preview_cancel` — признак, что игрок примеряет ход, а не тапает
  наугад.

Метрики диагностические. Решение Gate 2 — по наблюдаемому поведению и
kill-критерию.

# Приложение A. Профиль реализации

**Фабрика.** `apps/forward-back/`: веб-игра под браузер телефона,
TypeScript + Vite, без фреймворка, экран на HTML/CSS. Токены и шрифт — из
`UI Design/`. Как запускать — `apps/forward-back/README.md`.

Движок — `src/engine/forwardEngine.ts` (чистые функции). Солвер —
`src/engine/solver.ts`: BFS и «жадный» режим, используется в подборе уровней
(`tools/gen-levels.ts`) и тестах; в бандл игры не входит. Тест прогоняет
решения солвера через движок игры.
