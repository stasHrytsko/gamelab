# 1. Граница прототипа

**Что проверяем.** Переставляет ли игрок плитки «не того» цвета, чтобы подвести
пустую клетку к более срочному маршруту, когда несколько целей ждут
одновременно и их счётчики тикают с каждым сдвигом.

**Минимальный цикл.** Поле `5×5`, 17–21 плитка в одну клетку трёх цветов, 4–8
пустых клеток, цели снаружи у краёв, счётчики по ходам, свайп на одну клетку,
немедленный выезд совпавшей плитки. Плиток больше, чем целей: лишние остаются
на поле помехами, и их приходится переставлять. Вокруг цикла пять экранов и
три попапа (§7.1).

**Не делаем.** Отмену хода, перезапуск во время игры (только из попапов),
генерацию уровней во время игры, другие размеры поля, препятствия, специальные
плитки, повороты, бустеры, кнопку «пропустить ход», звук и настройки.

**Тематики нет (решение автора 2026-09-26).** Игра абстрактная: плитки,
кружки-цели, квадраты, сдвиги. Первая версия была про такси и пассажиров —
тема убрана из игры, кода и документов, механика не менялась.

**Уровней пять:** 3, 4, 5, 7 и 8 целей. Открываются по очереди.

**Почему победа — «все цели закрыты», а не «поле пустое».** При 3 целях и 17
плитках очистить поле невозможно. Лишние плитки и есть то, ради чего
существует механика: kill-критерий спрашивает, приходится ли двигать чужой
цвет.

**Почему kill-критерий такой.** Он проверяет центральную перестановку «не
моего» цвета. Если уровни проходятся прямым движением плиток нужного цвета,
дело не в балансе отдельной раскладки: заявленного решения через перестановку
пустот просто нет.

# 2. Цель и основной цикл

Цель игрока — закрыть все цели уровня. Плитки без своей цели остаются на поле.

Первое доступное действие — свайпнуть плитку в сторону соседней пустой клетки.

```text
Увидеть цвет, клетку выхода и счётчик ждущих целей
→ свайпнуть плитку на одну соседнюю пустую клетку
→ при совпадении цвета с целью у этой клетки плитка выезжает, клетка пустеет
→ счётчики остальных ждущих целей уменьшаются на 1
→ появляются цели, чья очередь наступила
→ проверка победы и поражения по §5
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Клетка | занята плиткой; пустая | освобождается при сдвиге или выезде плитки; занимается при сдвиге | не больше одной плитки в клетке |
| Плитка | на поле; выехала | сдвигается в соседнюю пустую клетку; выезжает, встав на клетку выхода своей цели | занимает одну клетку; закрывает одну цель; цвет не меняется |
| Цель | в очереди; ждёт; закрыта; сгорела | появляется, когда закрыто `unlockAfterServed` целей; счётчик уменьшается после каждого валидного сдвига | стоит снаружи поля напротив одной краевой клетки; две цели уровня не делят одну клетку |
| Клетка выхода | — | — | краевая клетка напротив цели; для плиток это обычная клетка, цель движение не блокирует |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Пространство** — ортогональная сетка `5×5`. Клетка адресуется парой
`row = 0..4` (сверху вниз) и `col = 0..4` (слева направо). Соседние клетки —
на манхэттенском расстоянии `1`, диагональ соседством не считается. Клетка
выхода — сторона поля (`top`, `right`, `bottom`, `left`) и индекс клетки вдоль
неё `0..4`, слева направо или сверху вниз.

**Состав уровня.**

- Плиток 17–21, пустых клеток 4–8, вместе 25.
- Цвета плиток делятся почти поровну: разница между цветами не больше одного.
- Плиток каждого цвета не меньше, чем целей этого цвета.

```ts
type Color = 'red' | 'blue' | 'yellow';
type Index = 0 | 1 | 2 | 3 | 4;

type BlockState = { id: string; color: Color; row: Index; col: Index };

type GoalState = {
  id: string;
  color: Color;
  target: { side: 'top' | 'right' | 'bottom' | 'left'; index: Index };
  initialCountdown: number;  // задаётся уровнем, 5–10 на уровнях из §6
  unlockAfterServed: number; // сколько целей должно быть закрыто до появления
  countdown: number;
  status: 'queued' | 'waiting' | 'served' | 'left';
};

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  blocks: BlockState[];      // только плитки на поле
  goals: GoalState[];
  moves: number;
  served: number;
  status: 'playing' | 'won' | 'failed';
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

# 4. Ввод и правила

```ts
type Action =
  | { type: 'swipe'; blockId: string; direction: 'up' | 'right' | 'down' | 'left' }
  | { type: 'open-help' }
  | { type: 'exit-to-levels' };
```

Свайп начинается на плитке: на телефоне пальцем, на компьютере зажатой
кнопкой мыши. Тапа для перемещения, свободного перетаскивания, долгого
нажатия, кнопки «пропустить ход», отмены хода и перезапуска на игровом экране
нет. Жест короче `18 px` считается тапом и игнорируется. У диагонального жеста
берётся ось с большим смещением; при равенстве — горизонтальная.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Свайп по плитке | соседняя клетка в направлении свайпа пустая | плитка переходит в неё, прежняя клетка пустеет, `moves += 1`, дальше по §5 | плитка встаёт в новую клетку | да |
| Свайп по плитке | соседняя клетка занята | состояние не меняется | плитка коротко покачивается | нет |
| Свайп по плитке | соседняя клетка за краем поля | состояние не меняется | плитка коротко покачивается | нет |
| Жест по плитке короче `18 px` | всегда | состояние не меняется | ничего | нет |
| Свайп не с плитки | всегда | состояние не меняется | ничего | нет |
| «?» | попапа нет | ввод на поле заблокирован, состояние уровня не меняется | попап «Как играть» | нет |
| «Понятно!» в «Как играть» | попап открыт | попап закрывается, `howToPlaySeen = true` | игра продолжается с того же места | нет |
| «К уровням» | всегда | попытка брошена, прогресс уровней не меняется | экран уровней | — |
| Любое действие на поле | `status !== 'playing'` или открыт попап | состояние не меняется | ничего | нет |

Плитка едет только в пустую клетку. Перепрыгивания, обмена двух плиток,
диагонального хода и сдвига сразу на несколько клеток нет.

Если плитка встала на клетку выхода ждущей цели своего цвета, совпадение
происходит сразу: плитка и цель исчезают раньше, чем уменьшаются счётчики
остальных. Выезд дополнительного хода не стоит.

Плитка чужого цвета на клетке выхода ничего не делает: цель ждёт, плитку можно
сдвинуть дальше.

# 5. Победа, поражение и переходы

```text
Дано: все цели уровня закрыты; плитки на поле могут оставаться.
Когда: завершена автоматическая обработка последнего валидного сдвига.
Тогда: уровень добавляется в passed, открывается следующий, показывается
       попап победы — на уровнях 1–4 обычный, на уровне 5 финальный.
```

```text
Дано: хотя бы одна цель ждёт.
Когда: после валидного сдвига её счётчик уменьшился до 0, и этим же сдвигом
       её не закрыли.
Тогда: попытка заканчивается поражением с причиной goal_timeout,
       показывается попап проигрыша.
```

Поражение возможно всегда: у каждой ждущей цели счётчик конечен.

Порядок автоматической обработки после валидного сдвига:

1. Завершить перемещение плитки.
2. Если её цвет совпал с ждущей целью у этой клетки — цель закрыта,
   `served += 1`, плитка убирается с поля.
3. Уменьшить счётчики всех остальных ждущих целей на `1`.
4. Если у какой-то цели счётчик `0` — поражение `goal_timeout`, дальше не идём.
5. Перевести в «ждёт» все цели, у которых `unlockAfterServed <= served`,
   с `countdown = initialCountdown`.
6. Если появившаяся цель стоит напротив плитки своего цвета — закрыть её
   сразу, без хода. Авторские уровни ОБЯЗАНЫ таких бесплатных совпадений
   избегать; правило нужно, чтобы движок не завис.
7. Повторять 5–6, пока новых совпадений нет.
8. Проверить победу.
9. Вернуть ввод игроку.

Код причины поражения один и стабильный: `goal_timeout`.

**Переходы между экранами:**

| Откуда | Действие | Куда |
|---|---|---|
| Главный | «Играть» | Уровни |
| Уровни | «Назад» | Главный |
| Уровни | тап по открытому уровню | Игровой экран, уровень с начала |
| Уровни | тап по закрытому уровню | ничего, уровень коротко покачивается |
| Игровой экран, уровень 1 | вход, `howToPlaySeen = false` | попап «Как играть» открывается сам |
| Попап победы 1–4 | «Следующий уровень» | Игровой экран, следующий уровень с начала |
| Попап победы 1–4, проигрыша, финальный | «Переиграть» | Игровой экран, тот же уровень с начала |
| Попап победы 1–4, проигрыша, финальный | «К уровням» | Уровни |

Случайности во время игры нет. Раскладка, цвета, клетки выхода, счётчики и
очерёдность целей полностью заданы уровнем. Косметика (частицы) может
различаться.

# 6. Контент и кривая сложности

Пример данных одного уровня:

```json
{
  "id": 1,
  "gridSize": 5,
  "blocks": [{ "id": "block-1", "color": "red", "row": 4, "col": 1 }],
  "goals": [
    {
      "color": "blue",
      "target": { "side": "bottom", "index": 1 },
      "initialCountdown": 9,
      "unlockAfterServed": 0
    }
  ]
}
```

**Правило построения.** Раскладка генерируется по фиксированному зерну.
Солвер ищет маршрут. Счётчик каждой цели — её ожидание на найденном маршруте
плюс запас уровня. Уровень берётся, только если выполнено всё:

- солвер проходит его, и маршрут проигрывается в тесте через настоящий движок;
- на уровнях 2–5 полный перебор, двигающий только плитки цветов ждущих целей,
  решения не находит — это kill-критерий в форме теста;
- бот, который думает на два хода вперёд за самую срочную цель и в 15% ходов
  свайпает наугад, выигрывает в полосе своего уровня (столбец «Бот»). Это мера
  сложности, а не прогноз для людей.

«Появляются» — порядок групп: `1 → 2` значит, что сначала приходит одна цель,
а следующая группа из двух — после того, как её закрыли. Больше, чем размер
группы, одновременно не ждёт никто. «Чужие» — сколько свайпов на маршруте
солвера делают плитки не того цвета, что у самой срочной цели.

Все числа замерены на собранном пакете (`apps/slide-out`, зёрна 1528, 2367,
2382, 4082, 30030). Уровни 1 и 4 совпадают с play; 2, 3 и 5 сгенерированы
заново под этот порядок целей.

| Уровень | Старт | Цели | Появляются | Макс. ждут | Счётчик | Новый навык | Главное давление | Маршрут / чужие | Бот |
|---:|---|---|---|---:|---|---|---|---:|---:|
| 1 | 17 плиток, 8 пустот | 3; запас +5 | 1 → 1 → 1 | 1 | 7–9 | свайп, цена хода, немедленный выезд | почти нет | 8 / 1 | 93% |
| 2 | 21 плитка, 4 пустоты | 4; запас +4 | 1 → 1 → 2 | 2 | 7–9 | подвинуть чужую плитку ради пустоты; в конце впервые ждут две цели | теснота | 12 / 4 | 60% |
| 3 | 20 плиток, 5 пустот | 5; запас +3 | 1 → 2 → 2 | 2 | 6–8 | пары подряд: какую цель закрывать первой, решать дважды | общий расход ходов | 12 / 5 | 38% |
| 4 | 21 плитка, 4 пустоты | 7; запас +3 | 1 → 2 → 2 → 2 | 2 | 5–10 | готовить пустоту под следующую пару, пока закрываешь текущую | теснота и пары | 19 / 8 | 13% |
| 5 | 21 плитка, 4 пустоты | 8; запас +2 | 1 → 2 → 2 → 3 | 3 | 4–9 | в финале три цели разом | три дедлайна на одно поле, права на ошибку почти нет | 24 / 12 | 0% |

`unlockAfterServed` по уровням: 1 — `0, 1, 2`; 2 — `0, 1, 2, 2`; 3 — `0, 1,
1, 3, 3`; 4 — `0, 1, 1, 3, 3, 5, 5`; 5 — `0, 1, 1, 3, 3, 5, 5, 5`.

Разница между соседними уровнями:

- `1→2` — пустот вдвое меньше: впервые приходится двигать чужой цвет, иначе
  нужная плитка не пройдёт; в конце впервые ждут две цели сразу.
- `2→3` — пары идут с первой же закрытой цели, запас +3: выбирать, какую цель
  спасать первой, приходится дважды подряд.
- `3→4` — пустот на одну меньше и третья пара: пустоту надо готовить под
  следующую пару, пока закрываешь текущую.
- `4→5` — восемь целей, финальная группа из трёх и запас всего +2: одна
  пустота должна работать на два маршрута, чужих ходов на маршруте — 12, а
  лишний ход почти не прощается. Уровень рассчитан на то, что с первого раза
  его не пройти.

**СЛЕДУЕТ.** Если генератор за разумное время не находит уровень с этими
параметрами, сначала поднимать запас на 1, потом добавлять одну пустоту.
Число целей и порядок их появления не трогать — это решение автора.

Уровень 5 сначала собрали с запасом +3 (бот выигрывал 5%), но автор прошёл его
с первого раза и 2026-09-24 попросил сложнее. Теперь запас +2, от бота
требуется 0–3% побед и не меньше 10 чужих ходов на маршруте солвера. Kill-тест
перебором по-прежнему обязателен.

# 7. Обратная связь и обучение

- **Доступное действие:** в начале свайпа плитка чуть приподнимается, а
  соседняя пустота в выбранном направлении пульсирует точкой.
- **Запрещённое действие:** плитка коротко покачивается, счётчики не меняются.
- **Цена хода:** после сдвига число на каждой ждущей цели уменьшается на один;
  на `1` цель пульсирует красным кольцом.
- **Победа:** последняя цель закрыта, оставшиеся плитки подпрыгивают волной,
  затем попап победы.
- **Поражение:** кружок цели гаснет и уходит за край, её клетка выхода
  подсвечивается красным, затем попап проигрыша.
- **Payoff:** цель соединяется с плиткой своего цвета, плитка за `220 мс`
  выезжает за край, её клетка вспыхивает как новая пустота. Ввод
  разблокируется после выезда.
- **Без текста игрок должен понять:** двигаются только плитки рядом с
  пустотой; плитка и цель одного цвета и знака связаны; выехавшая плитка
  оставляет место.

**Обучение — только попап «Как играть».** Пошагового онбординга нет. Попап
сам открывается при первом входе в уровень 1, дальше — по «?». Содержание:
картинка «плитка → пустая клетка → цель» и четыре правила:

1. Сдвигай плитку пальцем в соседнюю пустую клетку.
2. Подведи плитку того же цвета и знака к кружку-цели, пока его число не
   стало нулём.
3. Каждый сдвиг отнимает у всех ждущих целей по одному.
4. Плитка у своей цели сразу выезжает с поля и оставляет пустую клетку.

Кнопка одна — «Понятно!».

   серый тайл с замком, бледный текст.
3. **Игровой экран.** Сверху слева «к уровням», по центру «Уровень N».
   Под ними **строка целей**: по кружку на каждую цель уровня в порядке
   появления, справа число оставшихся. Закрытая — пустой кружок с галочкой,
   ждущая — в своём цвете со знаком, ещё не появившаяся — серая, её цвет
   заранее не раскрывается. Остальное место — поле `5×5`. Цели-кружки стоят
   снаружи напротив своих краевых клеток: цвет, счётчик крупно внутри, знак в
   белом кружке сбоку. Клетка выхода обведена цветом цели, числа на клетке
   нет. Внизу справа круглая кнопка «?».
4. **Попап «Как играть»** — поверх затемнённого поля (§7).
5. **Попап победы, уровни 1–4.** Зелёная галочка, «Уровень пройден!», «Все
   цели закрыты». Кнопки: «Следующий уровень» (зелёная), «Переиграть»,
   «К уровням».
6. **Попап проигрыша.** Красный крест, «Неудача», «Счётчик цели дошёл до
   нуля». Кнопки: «Переиграть» (синяя), «К уровням».
7. **Финальный попап после уровня 5.** Кубок, «Все уровни пройдены!».
   Кнопки: «Переиграть», «К уровням». Оценки в прототипе нет (решение автора
   2026-09-24).

За секунду на игровом экране читаются: пустые клетки, самый маленький
счётчик, цвет и знак каждой цели, её клетка выхода. Payoff происходит на краю
поля: плитка соединяется с кружком и выезжает наружу, её клетка становится
новой пустотой.

**Плитки — тайлы PuzzleKit.** Детальные картинки вместо тайлов пробовали
2026-09-24: на поле 5×5 это слишком мелко, глазам тяжело, автор вернул тайлы.

**Второй канал к цвету.** Цвет дублируется знаком внутри объекта: коралловый —
круг, синий — квадрат, жёлтый — треугольник. Знак стоит на плитке, на цели и
на её кружке в строке целей.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=75%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - уровни 2–5 не проходятся, если двигать только плитки цветов ждущих целей (проверка перебором)
    - минимум один игрок словами объясняет, зачем подвёл пустую клетку чужой плиткой
    - уровни 2–5 создают разные решения, а не только более короткие счётчики
  kill:
    - выполняется заранее записанный kill_criterion
```

Первое валидное действие — первый завершённый сдвиг плитки в соседнюю пустую
клетку. Открытие «Как играть» и начатый, но брошенный жест первым действием не
считаются. По нему считается `first_action_without_help`.

Для гипотезы в лог уровня пишутся цвет каждой сдвинутой плитки, ждущие цели на
момент сдвига и каждое открытие «?».

- `support_move_rate` — доля валидных сдвигов плиток цвета, которого нет у
  самой срочной цели.

Метрика диагностическая. Решение Gate 2 принимается по наблюдаемому
поведению и kill-критерию, а не по одному числу.

# Приложение A. Профиль реализации

**Фабрика.** `apps/slide-out/`: веб-игра под браузер телефона, TypeScript +
Vite, без фреймворка, экран на HTML/CSS. Токены и шрифт подключаются из
`UI Design/` напрямую. Как запускать и публиковать — `apps/slide-out/README.md`.

**Движок.** `src/engine/` — чистые функции §4–5, перенесены из play вместе с
солвером, ботом и генератором уровней (`tools/`).

**Ввод.** Pointer Events: плитка идёт за пальцем до соседней клетки, в занятую
пружинит на 7 px и покачивается; жест короче 18 px — тап. Поле с
`touch-action: none`, страница не прокручивается и не масштабируется.

**Ссылки.** Маршруты в `#`: `/` — главный, `#/levels`, `#/level/N` (только
открытый уровень), `?unlock=all` открывает все уровни на вкладку для проверки.
Превью ссылки — `public/og.png`, иконка и запуск с экрана «Домой» —
`manifest.webmanifest`. Service worker нет: на прототипе он только мешает
увидеть свежую версию.

**Хранение.** `localStorage`: пройденные уровни и «Как играть» уже показан.
Лог §8 — там же, `slide-out:log`.

**Публикация.** Vercel, Root Directory `apps/slide-out`, настройки в
`vercel.json`.

**Проверки.** `npm test` — движок и пакет уровней, в том числе kill-критерий
перебором и порядок появления целей; `npm run e2e` — пять уровней свайпами на
экране iPhone 13, настоящий тач, проигрыш и переигровка.
