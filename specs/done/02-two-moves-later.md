# 1. Граница прототипа

**Что проверяем.** Переставляет ли игрок такси «не того» цвета, чтобы подвести
пустую клетку к более срочному маршруту, когда несколько пассажиров ждут
одновременно и терпение тратится с каждым сдвигом.

**Минимальный цикл.** Поле `5×5`, 17–21 такси в одну клетку трёх цветов, 4–8
пустых клеток, пассажиры снаружи у краёв, терпение по ходам, свайп на одну
клетку, немедленный выезд совпавшего такси. Такси больше, чем пассажиров:
лишние остаются на поле помехами, и их приходится переставлять. Вокруг цикла
пять экранов и три попапа (§7.1).

**Не делаем.** Отмену хода, перезапуск во время игры (только из попапов),
генерацию уровней во время игры, другие размеры поля, препятствия, специальные
такси, повороты, бустеры, кнопку «пропустить ход», звук и настройки.

**Уровней пять:** 3, 4, 5, 7 и 8 пассажиров. Открываются по очереди.

**Почему победа — «все пассажиры развезены», а не «поле пустое».** При 3
пассажирах и 17 такси очистить поле невозможно. Лишние такси и есть то, ради
чего существует механика: kill-критерий спрашивает, приходится ли двигать чужой
цвет.

**Почему kill-критерий такой.** Он проверяет центральную перестановку «не
моего» цвета. Если уровни проходятся прямым движением целевых такси, дело не
в балансе отдельной раскладки: заявленного пятнашечного решения просто нет.

# 2. Цель и основной цикл

Цель игрока — развезти всех пассажиров уровня. Такси без пассажира остаются
на поле.

Первое доступное действие — свайпнуть такси в сторону соседней пустой клетки.

```text
Увидеть цвет, место посадки и терпение ожидающих пассажиров
→ свайпнуть такси на одну соседнюю пустую клетку
→ при совпадении цвета с пассажиром у этой клетки такси уезжает, клетка пустеет
→ терпение остальных ожидающих уменьшается на 1
→ появляются пассажиры, чья очередь наступила
→ проверка победы и поражения по §5
```

# 3. Объекты и состояние

| Объект | Состояния | Изменения | Ограничения |
|---|---|---|---|
| Клетка | занята такси; пустая | освобождается при сдвиге или выезде такси; занимается при сдвиге | не больше одного такси в клетке |
| Такси | на поле; уехало | сдвигается в соседнюю пустую клетку; уезжает при посадке | занимает одну клетку; везёт одного пассажира; цвет не меняется |
| Пассажир | в очереди; ждёт; обслужен; ушёл | появляется, когда обслужено `unlockAfterServed` пассажиров; теряет терпение после каждого валидного сдвига | стоит снаружи поля напротив одной краевой клетки; два пассажира уровня не делят одну клетку |
| Место посадки | — | — | краевая клетка напротив пассажира; для такси это обычная клетка, пассажир движение не блокирует |
| Уровень | закрыт; открыт; пройден | открывается победой на предыдущем; первый открыт всегда | проходится повторно сколько угодно |

**Пространство** — ортогональная сетка `5×5`. Клетка адресуется парой
`row = 0..4` (сверху вниз) и `col = 0..4` (слева направо). Соседние клетки —
на манхэттенском расстоянии `1`, диагональ соседством не считается. Место
посадки — сторона поля (`top`, `right`, `bottom`, `left`) и индекс клетки
вдоль неё `0..4`, слева направо или сверху вниз.

**Состав уровня.**

- Такси 17–21, пустых клеток 4–8, вместе 25.
- Цвета такси делятся почти поровну: разница между цветами не больше одного.
- Такси каждого цвета не меньше, чем пассажиров этого цвета.

```ts
type Color = 'red' | 'blue' | 'yellow';
type Index = 0 | 1 | 2 | 3 | 4;

type TaxiState = { id: string; color: Color; row: Index; col: Index };

type PassengerState = {
  id: string;
  color: Color;
  target: { side: 'top' | 'right' | 'bottom' | 'left'; index: Index };
  initialPatience: number;   // задаётся уровнем, 5–10 на уровнях из §6
  unlockAfterServed: number; // сколько пассажиров должно быть обслужено до появления
  patience: number;
  status: 'queued' | 'waiting' | 'served' | 'left';
};

type GameState = {
  level: 1 | 2 | 3 | 4 | 5;
  taxis: TaxiState[];        // только такси на поле
  passengers: PassengerState[];
  moves: number;
  served: number;
  status: 'playing' | 'won' | 'failed';
};

// Хранится на устройстве между запусками.
type Progress = {
  passed: Array<1 | 2 | 3 | 4 | 5>;
  howToPlaySeen: boolean;
};
```

# 4. Ввод и правила

```ts
type Action =
  | { type: 'swipe'; taxiId: string; direction: 'up' | 'right' | 'down' | 'left' }
  | { type: 'open-help' }
  | { type: 'exit-to-levels' };
```

Свайп начинается на такси: на телефоне пальцем, на компьютере зажатой кнопкой
мыши. Тапа для перемещения, свободного перетаскивания, долгого нажатия,
кнопки «пропустить ход», отмены хода и перезапуска на игровом экране нет. Жест
короче `18 px` считается тапом и игнорируется. У диагонального жеста берётся
ось с большим смещением; при равенстве — горизонтальная.

| Действие | Условие | Изменение состояния | Видимый результат | Ход потрачен |
|---|---|---|---|---|
| Свайп по такси | соседняя клетка в направлении свайпа пустая | такси переходит в неё, прежняя клетка пустеет, `moves += 1`, дальше по §5 | такси встаёт в новую клетку | да |
| Свайп по такси | соседняя клетка занята | состояние не меняется | такси коротко покачивается | нет |
| Свайп по такси | соседняя клетка за краем поля | состояние не меняется | такси коротко покачивается | нет |
| Жест по такси короче `18 px` | всегда | состояние не меняется | ничего | нет |
| Свайп не с такси | всегда | состояние не меняется | ничего | нет |
| «?» | попапа нет | ввод на поле заблокирован, состояние уровня не меняется | попап «Как играть» | нет |
| «Понятно!» в «Как играть» | попап открыт | попап закрывается, `howToPlaySeen = true` | игра продолжается с того же места | нет |
| «К уровням» | всегда | попытка брошена, прогресс уровней не меняется | экран уровней | — |
| Любое действие на поле | `status !== 'playing'` или открыт попап | состояние не меняется | ничего | нет |

Такси едет только в пустую клетку. Перепрыгивания, обмена двух такси,
диагонального хода и сдвига сразу на несколько клеток нет.

Если такси встало на место посадки ожидающего пассажира своего цвета, посадка
происходит сразу: такси и пассажир исчезают раньше, чем уменьшается терпение
остальных. Выезд дополнительного хода не стоит.

Такси чужого цвета на месте посадки пассажира ничего не делает: пассажир
ждёт, такси можно сдвинуть дальше.

# 5. Победа, поражение и переходы

```text
Дано: все пассажиры уровня обслужены; такси на поле могут оставаться.
Когда: завершена автоматическая обработка последнего валидного сдвига.
Тогда: уровень добавляется в passed, открывается следующий, показывается
       попап победы — на уровнях 1–4 обычный, на уровне 5 финальный.
```

```text
Дано: хотя бы один пассажир ждёт.
Когда: после валидного сдвига его терпение уменьшилось до 0, и этим же
       сдвигом его не обслужили.
Тогда: попытка заканчивается поражением с причиной passenger_timeout,
       показывается попап проигрыша.
```

Поражение возможно всегда: у каждого ожидающего пассажира терпение конечно.

Порядок автоматической обработки после валидного сдвига:

1. Завершить перемещение такси.
2. Если его цвет совпал с ожидающим пассажиром у этой клетки — пассажир
   обслужен, `served += 1`, такси убирается с поля.
3. Уменьшить терпение всех остальных ожидающих на `1`.
4. Если у кого-то терпение `0` — поражение `passenger_timeout`, дальше не идём.
5. Перевести в «ждёт» всех пассажиров, у которых `unlockAfterServed <= served`,
   с `patience = initialPatience`.
6. Если появившийся пассажир стоит напротив такси своего цвета — обслужить его
   сразу, без хода. Авторские уровни ОБЯЗАНЫ таких бесплатных совпадений
   избегать; правило нужно, чтобы движок не завис.
7. Повторять 5–6, пока новых совпадений нет.
8. Проверить победу.
9. Вернуть ввод игроку.

Код причины поражения один и стабильный: `passenger_timeout`.

**Переходы между экранами:**

| Откуда | Действие | Куда |
|---|---|---|
| Главный | «Играть» | Уровни |
| Уровни | «Назад» | Главный |
| Уровни | тап по открытому уровню | Игровой экран, уровень с начала |
| Уровни | тап по закрытому уровню | ничего, уровень коротко покачивается |
| Игровой экран, уровень 1 | вход, `howToPlaySeen = false` | попап «Как играть» открывается сам |
| Попап победы 1–4 | «Следующий уровень» | Игровой экран, следующий уровень с начала |
| Попап победы 1–4, проигрыша, финальный | «Переиграть» | Игровой экран, тот же уровень с начала |
| Попап победы 1–4, проигрыша, финальный | «К уровням» | Уровни |

Случайности во время игры нет. Раскладка, цвета, места посадки, терпение и
очерёдность пассажиров полностью заданы уровнем. Косметика (частицы) может
различаться.

# 6. Контент и кривая сложности

Пример данных одного уровня:

```json
{
  "id": 1,
  "gridSize": 5,
  "taxis": [{ "id": "taxi-1", "color": "red", "row": 4, "col": 1 }],
  "passengers": [
    {
      "color": "blue",
      "target": { "side": "bottom", "index": 1 },
      "initialPatience": 9,
      "unlockAfterServed": 0
    }
  ]
}
```

**Правило построения.** Раскладка генерируется по фиксированному зерну.
Солвер ищет маршрут. Терпение каждого пассажира — его ожидание на найденном
маршруте плюс запас уровня. Уровень берётся, только если выполнено всё:

- солвер проходит его, и маршрут проигрывается в тесте через настоящий движок;
- на уровнях 2–5 полный перебор, двигающий только такси цветов ожидающих
  пассажиров, решения не находит — это kill-критерий в форме теста;
- бот, который думает на два хода вперёд за самого срочного пассажира и в
  15% ходов свайпает наугад, выигрывает в полосе своего уровня (столбец
  «Бот»). Это мера сложности, а не прогноз для людей.

«Появляются» — порядок групп: `1 → 2` значит, что сначала приходит один
пассажир, а следующая группа из двух — после того, как его развезли.
Больше, чем размер группы, одновременно не ждёт никто. «Чужие» — сколько
свайпов на маршруте солвера делают такси не того цвета, что у самого срочного
пассажира.

Все числа замерены на собранном пакете (`apps/taxi-slide`, зёрна 1528, 2367,
2382, 4082, 30030). Уровни 1 и 4 совпадают с play; 2, 3 и 5 сгенерированы
заново под этот порядок пассажиров.

| Уровень | Старт | Пассажиры | Появляются | Макс. ждут | Терпение | Новый навык | Главное давление | Маршрут / чужие | Бот |
|---:|---|---|---|---:|---|---|---|---:|---:|
| 1 | 17 такси, 8 пустот | 3; запас +5 | 1 → 1 → 1 | 1 | 7–9 | свайп, цена хода, немедленный выезд | почти нет | 8 / 1 | 93% |
| 2 | 21 такси, 4 пустоты | 4; запас +4 | 1 → 1 → 2 | 2 | 7–9 | подвинуть чужое такси ради пустоты; в конце впервые ждут двое | теснота | 12 / 4 | 60% |
| 3 | 20 такси, 5 пустот | 5; запас +3 | 1 → 2 → 2 | 2 | 6–8 | пары подряд: кого спасать первым, решать дважды | общий расход ходов | 12 / 5 | 38% |
| 4 | 21 такси, 4 пустоты | 7; запас +3 | 1 → 2 → 2 → 2 | 2 | 5–10 | готовить пустоту под следующую пару, пока развозишь текущую | теснота и пары | 19 / 8 | 13% |
| 5 | 21 такси, 4 пустоты | 8; запас +2 | 1 → 2 → 2 → 3 | 3 | 4–9 | в финале трое разом | три дедлайна на одно поле, права на ошибку почти нет | 24 / 12 | 0% |

`unlockAfterServed` по уровням: 1 — `0, 1, 2`; 2 — `0, 1, 2, 2`; 3 — `0, 1,
1, 3, 3`; 4 — `0, 1, 1, 3, 3, 5, 5`; 5 — `0, 1, 1, 3, 3, 5, 5, 5`.

Разница между соседними уровнями:

- `1→2` — пустот вдвое меньше: впервые приходится двигать чужой цвет, иначе
  нужное такси не пройдёт; в конце впервые ждут двое сразу.
- `2→3` — пары идут с первого же развезённого, запас +3: выбирать, кого
  спасать первым, приходится дважды подряд.
- `3→4` — пустот на одну меньше и третья пара: пустоту надо готовить под
  следующую пару, пока развозишь текущую.
- `4→5` — восемь пассажиров, финальная группа из трёх и запас всего +2: одна
  пустота должна работать на два маршрута, чужих ходов на маршруте — 12, а
  лишний ход почти не прощается. Уровень рассчитан на то, что с первого раза
  его не пройти.

**СЛЕДУЕТ.** Если генератор за разумное время не находит уровень с этими
параметрами, сначала поднимать запас на 1, потом добавлять одну пустоту.
Число пассажиров и порядок их появления не трогать — это решение автора.

Уровень 5 сначала собрали с запасом +3 (бот выигрывал 5%), но автор прошёл его
с первого раза и 2026-09-24 попросил сложнее. Теперь запас +2, от бота
требуется 0–3% побед и не меньше 10 чужих ходов на маршруте солвера. Kill-тест
перебором по-прежнему обязателен.

# 7. Обратная связь и обучение

- **Доступное действие:** в начале свайпа такси чуть приподнимается, а
  соседняя пустота в выбранном направлении пульсирует точкой.
- **Запрещённое действие:** такси коротко покачивается, терпение не меняется.
- **Цена хода:** после сдвига число на каждом ожидающем пассажире
  уменьшается на один; на `1` пассажир пульсирует красным кольцом.
- **Победа:** последний пассажир уезжает, оставшиеся такси подпрыгивают
  волной, затем попап победы.
- **Поражение:** круг пассажира гаснет и уходит за край, его место посадки
  подсвечивается красным, затем попап проигрыша.
- **Payoff:** пассажир соединяется с такси своего цвета, такси за `220 мс`
  уезжает за край, его клетка вспыхивает как новая пустота. Ввод
  разблокируется после выезда.
- **Без текста игрок должен понять:** двигаются только такси рядом с
  пустотой; такси и пассажир одного цвета и знака связаны; уехавшее такси
  оставляет место.

**Обучение — только попап «Как играть».** Пошагового онбординга нет. Попап
сам открывается при первом входе в уровень 1, дальше — по «?». Содержание:
картинка «такси → пустая клетка → пассажир» и четыре правила:

1. Сдвигай такси в соседнюю пустую клетку.
2. Подай такси того же цвета и знака к пассажиру, пока его число не стало
   нулём.
3. Каждый сдвиг отнимает у всех ждущих по одному.
4. Такси с пассажиром сразу уезжает и оставляет пустую клетку.

Кнопка одна — «Понятно!».

   цвет заранее не раскрывается. Остальное место — поле `5×5`.
   Пассажиры-круги стоят снаружи напротив своих краевых клеток: цвет, число
   терпения крупно внутри, знак в белом кружке сбоку. Место посадки обведено
   цветом пассажира, числа на клетке нет. Внизу справа круглая кнопка «?».
4. **Попап «Как играть»** — поверх затемнённого поля (§7).
5. **Попап победы, уровни 1–4.** Зелёная галочка, «Уровень пройден!», «Все
   пассажиры развезены». Кнопки: «Следующий уровень» (зелёная), «Переиграть»,
   «К уровням».
6. **Попап проигрыша.** Красный крест, «Неудача», «Пассажир не дождался».
   Кнопки: «Переиграть» (синяя), «К уровням».
7. **Финальный попап после уровня 5.** Кубок, «Все уровни пройдены!».
   Кнопки: «Переиграть», «К уровням». Оценки в прототипе нет (решение автора
   2026-09-24).

За секунду на игровом экране читаются: пустые клетки, самое маленькое
терпение, цвет и знак каждого пассажира, его место посадки. Payoff происходит
на краю поля: такси соединяется с кругом и выезжает наружу, его клетка
становится новой пустотой.

**Такси — тайлы PuzzleKit.** Машинки сверху пробовали 2026-09-24: на поле
5×5 они слишком детальные, глазам тяжело, автор вернул тайлы.

**Второй канал к цвету.** Цвет дублируется знаком внутри объекта: коралловый —
круг, синий — квадрат, жёлтый — треугольник. Знак стоит на такси, на
пассажире и на его кружке в строке пассажиров.

# 8. Проверка прототипа

```yaml
playtest:
  sample: 10-15
  success:
    first_action_without_help: ">=80%"
    goal_understood: ">=75%"
    voluntary_continue: ">=60%"
    retry_after_fail: ">=50%"
  mandatory:
    - уровни 2–5 не проходятся, если двигать только такси цветов ожидающих пассажиров (проверка перебором)
    - минимум один игрок словами объясняет, зачем подвёл пустую клетку чужим такси
    - уровни 2–5 создают разные решения, а не только более короткое терпение
  kill:
    - выполняется заранее записанный kill_criterion
```

Первое валидное действие — первый завершённый сдвиг такси в соседнюю пустую
клетку. Открытие «Как играть» и начатый, но брошенный жест первым действием не
считаются. По нему считается `first_action_without_help`.

Для гипотезы в лог уровня пишутся цвет каждого сдвинутого такси, ожидающие
пассажиры на момент сдвига и каждое открытие «?».

- `support_move_rate` — доля валидных сдвигов такси цвета, которого нет у
  самого срочного пассажира.

Метрика диагностическая. Решение Gate 2 принимается по наблюдаемому
поведению и kill-критерию, а не по одному числу.

# Приложение A. Профиль реализации

**Фабрика.** `apps/taxi-slide/`: веб-игра под браузер телефона, TypeScript +
Vite, без фреймворка, экран на HTML/CSS. Токены и шрифт подключаются из
`UI Design/` напрямую. Как запускать и публиковать — `apps/taxi-slide/README.md`.

**Движок.** `src/engine/` — чистые функции §4–5, перенесены из play вместе с
солвером, ботом и генератором уровней (`tools/`).

**Ввод.** Pointer Events: такси идёт за пальцем до соседней клетки, в занятую
пружинит на 7 px и покачивается; жест короче 18 px — тап. Поле с
`touch-action: none`, страница не прокручивается и не масштабируется.

**Ссылки.** Маршруты в `#`: `/` — главный, `#/levels`, `#/level/N` (только
открытый уровень), `?unlock=all` открывает все уровни на вкладку для проверки.
Превью ссылки — `public/og.png`, иконка и запуск с экрана «Домой» —
`manifest.webmanifest`. Service worker нет: на прототипе он только мешает
увидеть свежую версию.

**Хранение.** `localStorage`: пройденные уровни и «Как играть» уже показан.
Лог §8 — там же, `taxi-slide:log`.

**Публикация.** Vercel, Root Directory `apps/taxi-slide`, настройки в
`vercel.json`.

**Проверки.** `npm test` — движок и пакет уровней, в том числе kill-критерий
перебором и порядок появления пассажиров; `npm run e2e` — пять уровней
свайпами на экране iPhone 13, настоящий тач, проигрыш и переигровка.
